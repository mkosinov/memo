# Единый контракт удаления

- Введено: 2026-09-19, дизайн #243 (решение пользователя 2026-09-19), фаза 1.
- Заменяет критерий подключения к отложенному контракту «наличие серверных
  зависимостей (FK_MATRIX)» из #285 rev8 и расширяет решение от 17.09
  («архивируемым отложенное удаление не положено») — теперь только для действия
  «в архив»; действию «удалить» отложенный контракт положен всем.

## Правило

Действие «удалить» у ЛЮБОЙ сущности выполняется только через единый отложенный
контракт:

1. Строка убирается с экрана сразу (оптимистично).
2. Показывается тост с окном отмены (5 секунд, кольцо обратного отсчёта).
3. Нажата «Отменить» — строка возвращается на исходную позицию из снимка;
   запрос на сервер не уходит.
4. Окно истекло — на сервер уходит запрос на удаление.
5. Контракт ошибок коммита (D4, #285 rev8):
   - 404 «уже не существует» — тихий успех, возврата нет;
   - сервер ответил иной ошибкой — строка возвращается из снимка + тост
     «Не удалось удалить. Изменение отменено»;
   - ответа сервера не было (сеть/таймаут) — строка возвращается из снимка +
     тост «Не удалось подтвердить удаление» (исход неизвестен; после реализации
     #330 — опираться на состояние соединения).

Восстановление всегда локальное, из снимка, без обращения к серверу; снимок
запоминает позицию строки.

Действие «в архив» (и «восстановить из архива») — не удаление: остаётся как
есть (обратимо, окно отмены не требуется).

## Таблица применения

| Сущность | Класс | Фаза перевода |
|---|---|---|
| Record (запись) | отложенный контракт | готово (#285) |
| Activity (занятие) | отложенный контракт | готово (#286) |
| Visit (визит), Payment (платёж) | отложенный контракт, лист (`{expected:{}}`) | готово (#324): кольца — фаза 1 (#243/#285), контракт рута — этап 2 трекера #346 |
| Tag (тег) | зависимая (8 join-таблиц) | готово (#318) |
| Photo (фото), Visitor (посетитель), Position (должность) | зависимые: photo_tags / visits+visitor_tags / staff_positions | готово (#324, этап 3 трекера #346); Position — зависимая, не листовая |
| Staff, Location, Service, Material, Client | архивируемые: «удалить» после диалога зависимостей — отложенный контракт; «в архив»/«восстановить» без изменений | фаза 3 (follow-up) |
| UserSettings | пользовательское DELETE = сброс к дефолтам (строка пересоздаётся чтением, get-or-create); смерть пользователя — каскад: удаление карточки сотрудника сносит учётку и её настройки | готово (#319 + #324: лист, `{expected:{}}`, own-only роут) |
| User, Tariff | неявный soft-delete, вне скоупа (как раньше) | не применимо |

Примечания: Position включён в матрицу `_overview.md` как зависимая сущность
(staff_positions), не листовая. Форма контракта шести субъектов #324 —
один-в-один с тегами (#318): `?dry_run=true` (зависимости → 409-дерево с items,
чисто → 204), голый DELETE → 422 `expected_state_required`, коммит
`{resolutions?, expected}` с subset-сверкой, кольцо 5 с; страж «схема ↔ матрица»
(`test_delete_matrix_guard.py`) закрепляет декларации.
