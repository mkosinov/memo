# Employee Profile — Domain Rules (#262)

## Description
Личные данные сотрудника, которые он правит сам в «Мои данных». Публичная половина живёт на карточке сотрудника (`Staff`: имя, фамилия, аватар) и на master-секции (`Master`: специализация), приватная — в отдельной таблице `user_profiles` (1:1 с `users`, строка создаётся лениво при первом сохранении).

## Public / private boundary (решение юзера 2026-09-09)
- **Публично** (без сессии): имя, фамилия, аватар карточки сотрудника (`Staff`) и специализация master-секции (`GET /api/v1/masters` публичен по #247; полный `GET /api/v1/staff` — под сессией).
- **Приватно** (только владелец, `GET/PUT /api/v1/my`, нужна сессия): отчество, дата рождения, адрес фактического проживания, место рождения, серия и номер паспорта, когда выдан, кем выдан, адрес регистрации.
- Роль видна владельцу в форме, но публично не отдаётся.
- `user_profiles` никогда не присоединяется к публичным сериализаторам — это структурное правило, а не дисциплина сериализатора (публичный masters GET по #247 — см. auth.md).

## Fields (`user_profiles`)
Все колонки опциональные, `user_id` — уникальный FK на users. Очистка поля = явный `null` в `PUT /my`; пропущенный ключ = «не трогать».

## Паспорт: фото — заглушка (решение юзера 2026-09-10)
Форма показывает неактивную строку «Фото первой страницы паспорта — появится позже». Загрузки, приватного файлового хранения и раздачи в v1 нет; колонка под файл не создаётся до отдельного решения.

## Avatar files (единственная файловая инфраструктура v1)
- Хранение: `FILES_DIR/avatars` (настройка в `core/config.py`).
- Загрузка `POST /api/v1/my/portrait`: лимит 5 МБ (`Content-Length` проверяется ДО чтения + кап при стриминге), тип по магическим байтам (JPEG/PNG/WebP), stdlib без новых зависимостей; имя файла — UUIDv4 + расширение из белого списка, пользовательский ввод в путь не попадает.
- Раздача: Starlette StaticFiles на `/api/v1/files/avatar`, публичная и запертая в каталоге аватаров конструктивно; приватных файлов на диске в v1 нет.
- Успешная загрузка перезаписывает `Staff.avatar_url` карточки сотрудника и удаляет предыдущий собственный файл (внешние URL не трогаем).
