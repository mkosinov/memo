# E2E Infra Roots (#108 DB Lock + #126 Warmup) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Eliminate two E2E-infra root causes — SQLite lock flakiness (#108) and missing standalone route warmup (#126) — so E2E runs are reliable without skips/workarounds.

**Architecture:** Backend: one process-global `event.listens_for(Engine, "connect")` PRAGMA hook (busy_timeout + WAL) covering all 3 engines. E2E: extract a shared sqlite retry helper, apply consistent retry+explicit-fail across `db-query.ts` / `globalSetup.ts` / `cleanTestData()`, and add standalone-only route warmup in `globalSetup`.

**Tech Stack:** SQLAlchemy 2.0 async (aiosqlite), FastAPI, pytest; Playwright + TypeScript E2E fixtures, vitest for fixture unit tests.

**Spec:** `docs/specs/2026-07-17-e2e-infra-roots-108-126-design.md`

---

## Behavioral Delta

How this behaves, mapped to spec acceptance criteria:

- **US-1 (#126)** → Running `pnpm exec playwright test` standalone on a cold cache no longer hangs on "Загрузка"; routes are pre-compiled before tests start.
- **US-2 (#108)** → Concurrent CLI-vs-backend DB writes during E2E no longer abort a run with "database is locked" (writes wait via busy_timeout).
- **US-3 (#108)** → If test-data cleanup can't get the DB after retries, the test fails LOUDLY instead of silently continuing with stale data.
- **US-4 (#108)** → The backend enables WAL journal mode on connect (`PRAGMA journal_mode` = `wal`).
- **US-5 (#108)** → All existing backend behavior is unchanged; full pytest suite stays green with WAL + busy_timeout.
- **US-6 (#108)** → A locked DB during global setup retries rather than killing the whole Playwright run.

## Task 1: Backend PRAGMA-on-connect hook (busy_timeout + WAL)

### Classification: standard
### Required Docs
- `docs/specs/2026-07-17-e2e-infra-roots-108-126-design.md` — §3-A (hook mechanism, why global Engine-level)
- `.opencode/skills/pytest-patterns/SKILL.md` — backend test conventions (async, markers)
- `docs/decisions/001-use-sqlite-for-storage.md` — deployment model (why WAL is safe)

### Task Description
Add a process-global SQLAlchemy `connect` event listener in `backend/src/db/database.py` that, on every new DBAPI connection, executes `PRAGMA busy_timeout=5000` then `PRAGMA journal_mode=WAL`. Use the class-level `Engine` target (NOT `engine.sync_engine`) so it covers the app async engine AND the Alembic/sqladmin sync engines. Register it at module scope so it's active before any engine connects.

### Steps
- [ ] Read `backend/src/db/database.py` (32 lines) and `backend/tests/test_database.py`.
- [ ] **RED:** In `test_database.py`, add a test using a FILE-based DB (WAL is not supported on `:memory:`), e.g.:
  ```python
  async def test_engine_sets_wal_and_busy_timeout(tmp_path) -> None:
      from src.db.database import DBManager
      db_file = tmp_path / "pragma_test.db"
      manager = DBManager(f"sqlite+aiosqlite:///{db_file}")
      async with manager.engine.connect() as conn:
          jm = (await conn.exec_driver_sql("PRAGMA journal_mode")).scalar()
          bt = (await conn.exec_driver_sql("PRAGMA busy_timeout")).scalar()
      assert str(jm).lower() == "wal"
      assert int(bt) == 5000
      await manager.engine.dispose()
  ```
  Match the file's existing async style + `pytestmark = pytest.mark.misc`.
- [ ] Run it, confirm it FAILS (journal_mode == `delete`, busy_timeout default):
  `cd backend && uv run pytest tests/test_database.py -k wal_and_busy_timeout -q`
- [ ] **GREEN:** In `database.py`, add at module scope (after imports, before/around `DBManager`):
  ```python
  from sqlalchemy import event
  from sqlalchemy.engine import Engine

  @event.listens_for(Engine, "connect")
  def _set_sqlite_pragmas(dbapi_connection, connection_record):
      cursor = dbapi_connection.cursor()
      cursor.execute("PRAGMA busy_timeout=5000")
      cursor.execute("PRAGMA journal_mode=WAL")
      cursor.close()
  ```
  (Confirm import path `from sqlalchemy.engine import Engine` resolves; if lint prefers `from sqlalchemy import Engine`, use whatever the codebase/SQLAlchemy 2.0 exposes — verify import works.)
- [ ] Run the new test, confirm GREEN.
- [ ] **US-5 regression:** run full backend suite: `cd backend && uv run pytest -q` — all green (no app breakage). If any `:memory:`-based test now errors on WAL, note it — WAL PRAGMA on `:memory:` is a no-op/returns `memory`, should not error, but verify.
- [ ] Commit: `git commit -am "fix(#108): set busy_timeout + WAL on sqlite connect (global hook)"`

### DoD
- New test asserts `journal_mode=wal` + `busy_timeout=5000` on a file DB (US-4).
- Full backend pytest green (US-5).
