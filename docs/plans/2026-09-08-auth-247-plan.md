# Full API & Admin App Authentication (#247) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Staff log into the admin app by phone + password; the API becomes default-deny with a public allowlist; roles `admin`/`master` carry code-defined permissions checked by FastAPI dependencies; sqladmin gets a login screen; the public site's behavior (dictionaries + anonymous booking) is untouched.

**Architecture:** New `backend/src/auth/` package — pwdlib/Argon2 password hashing (params pinned), server-side `sessions` table with a sliding idle window (7d) and absolute cap (30d) behind an opaque `HttpOnly` cookie, `ROLE_PERMISSIONS` matrix enforced through `require_permission` dependencies, `PUBLIC_ROUTES` allowlist enforced by a contract test, `Sec-Fetch-Site` check on authenticated mutations. Frontend: `/login` page + `AuthContext` + client-side guard + 401 interceptor in the shared `api()` client; permission-aware navigation and affordances; Playwright storageState via globalSetup login.

**Tech Stack:** FastAPI (current `uv.lock` version), SQLAlchemy async + alembic, pwdlib[argon2] (new), sqladmin `AuthenticationBackend` (0.20 API: `secret_key` only, `form_overrides` + `on_model_change`), Next.js 14 App Router, TanStack Query, Playwright.

**Spec (binding):** `docs/specs/2026-09-08-auth-design.md` — §2 decisions 1–15, §3 backend contract (§3.2 hashing, §3.3 session model, §3.4 service, §3.5 permissions, §3.6 auth router, §3.7 access matrix, §3.8 user-settings breaking change, §3.9 sqladmin [G2-corrected], §3.10 CLI, §3.11 seed, §3.12 config), §4 frontend contract, §5 error table, §6 User Scenarios 1–7, §7 testing, §8 NOT-built.

## Behavioral Delta

How this behaves for the user, mapped to spec User Scenarios:

- **Администратор входит по телефону и паролю (С1)** — открывает админку, видит страницу входа; после правильного телефона и пароля попадает в приложение и видит все разделы как раньше.
- **Мастер входит (С2)** — та же страница входа; интерфейс тот же, что у админа (настройка отображения по ролям — отдельная задача в будущем); запрещённое действие (например, создать платёж) отклоняется API с понятной ошибкой. Внизу слева — имя мастера и роль, там же выход.
- **Кто вошёл — видно (С1)** — существующий блок пользователя внизу слева показывает реального человека (имя мастера или телефон, роль «Админ»/«Мастер»), рядом — выход.
- **Неверный пароль (С3)** — понятная ошибка на месте и тостом, на странице входа остаёшься, кука не ставится; **3 неудачи подряд — блок на 15 минут, ещё 3 — на час, ещё 3 — наглухо до сброса администратором**; во время блокировки не принимает и верный пароль.
- **Выход (С4)** — кнопка выхода удаляет сессию: защищённые страницы отправляют на вход, API отвечает 401.
- **Границы анонима (С5)** — без сессии API отдаёт 401 на защищённых данных; публичный сайт как работал (справочники + бронирование без логина), так и работает.
- **Мастеру нельзя менять чужое (С6)** — попытка мастера создать платёж получает 403; админу — разрешено.
- **sqladmin закрыт (С7)** — панель управления базой открывается только после входа, и только для роли администратора.
- **Сессия живёт, пока работаешь** — активность продлевает сессию; после 7 дней молчания или 30 дней жизни — новый вход.
