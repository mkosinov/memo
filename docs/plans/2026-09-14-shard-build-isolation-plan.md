# Shard build isolation + bounded cleanup Implementation Plan (#264+#122)

> **For agents:** REQUIRED SUB-SKILL: Use subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Убрать кросс-печение шардовых сборок e2e (каждый шард собирается в свою `.next-shard-N`) и сделать уборщик `test-all.sh` конечным — любой выход (включая Ctrl-C) завершает шардовые стеки за ограниченное время без зависаний и без убийства посторонних процессов.

**Architecture:** Чисто скриптовый трек, продуктовый код не трогается. Изоляция = env-механизм из двух неделимых правок: `e2e-shard-start.sh` экспортирует `NEXT_DIST_DIR`, `next.config.mjs` читает его в `distDir`. Вайпы имеют единственного продюсера — `test-all.sh` (собственный вайп дефолтного `.next` в шардовом скрипте упраздняется). Уборщик = лестница TERM → бюджетное ожидание (10 с, поллинг 0.5 с) → `kill -9` → свип «порт + маска команды» → удаление шардовых БД. Тестируемые куски (сироты/вайп/уборщик) выносятся в сорсируемую библиотеку `scripts/lib/shard-helpers.sh` — dryrun-тесты гоняют её напрямую с фейк-процессами, без реального Next; порты для тестов подставляются через **существующие** глобалы `SHARD_FRONTEND_PORTS`/`SHARD_BACKEND_PORTS` (новой сигнатуры нет).

**Tech Stack:** bash (set -euo pipefail — существующий стиль скриптов; macOS-совместимо: pgrep/ps/lsof системные, python3 системный на darwin), Next.js 14.2.35 (webpack, `distDir` из env — подтверждено экспериментом панели), шелл-тесты `scripts/e2e-shard-start.dryrun.test.sh` (заглушки через PATH).

**Спека:** `docs/specs/2026-09-14-shard-build-isolation-design.md` (rev2; решения §3.1–§3.5 обязательны, §4 — границы скоупа).

**Ревизия 2** — правки по plan-reviewer (NEEDS_CHANGES → все блокеры/мажоры внесены: семантика вайпа на пустом наборе — успех; fail-fast-кейс через PATH-заглушку `rm` вместо chmod; конструкция TERM-стойкого держателя задана однозначно; каскадная семантика TERM и роль свипа зафиксированы комментарием; `mkdir scripts/lib`; grep-бейзлайн с `*.json`; ссылки между задачами исправлены; параметризация портов — через существующие глобалы, не новую сигнатуру).

## Behavioral Delta

Как поведёт себя инфраструктура для разработчика/CI (маппинг на сценарии спеки §5):

- **S1** → `bash scripts/test-all.sh` на чистой машине: оба шарда собираются каждый в своей `.next-shard-N` (env `NEXT_DIST_DIR` доходит до `next dev`), полный прогон зелёный.
- **S2** → Повторный запуск подряд: шардовые папки стираются на старте безусловно (независимо от состояния портов; на чистой машине стирать нечего — это успех), с fail-fast при реальной неудаче удаления; чанки прошлого прогона не наследуются.
- **S3** → Ctrl-C или любой другой выход: уборщик завершает оба стека максимум за ~15 с (10 с бюджетное ожидание + эскалация `kill -9` + свип, секунды), `wait` не виснет, шардовые БД удалены.
- **S4** → Внук `next-server`, переживший TERM, добивается контрольным свипом «порт + маска команды».
- **S5** → Живой dev-стек на 3000/8000 во время прогона: шарды не выполняют ни одного `rm` дефолтного `.next` (их собственный вайп упразднён); порто-гард дефолтного вайпа `test-all.sh` сохранён.
- **S6** → CI-матрица идёт через тот же `e2e-shard-start.sh` — код-путь единый, `test.yml` не меняется, прогон зелёный.
- Неизменное → dev-стек (3000/3001/8000), одиночный e2e-прогон без `SHARD_ID` (дефолтный `.next`), readiness-механика (60×curl + `sleep 30`), порты шардов.

## Task 3: библиотека shard-helpers.sh — сироты, вайп, уборщик

### Classification: standard

### Required Docs

Спека §3.2 (безусловный вайп + fail-fast), §3.3 (лестница уборщика, отказ от PGID с обоснованием), §2 (факты: сироты `:61-83`, cleanup `:183-193`).

### Steps

- [ ] 3.1 `mkdir -p scripts/lib` (каталог новый, инфраструктурный); создать `scripts/lib/shard-helpers.sh` — без shebang-исполнимости и без `chmod +x`, сорсируется: `source "$ROOT/scripts/lib/shard-helpers.sh"`. Внутри `set -euo pipefail` **не** выставлять (контекст вызывающего). Функции читают порты из глобалов `SHARD_FRONTEND_PORTS`/`SHARD_BACKEND_PORTS`, объявленных в `test-all.sh:153-154`, — тесты подставляют свои значения до сорсирования (новой сигнатуры/параметров нет).
- [ ] 3.2 Перенести из `test-all.sh` (`:61-83`) `kill_port_orphans`: `kill -9` слушателей шардовых портов через `lsof -ti` + порто-гардированный pkill `next dev -p 300[2-3]` (с существующими комментариями-запретами глобального pkill `next-server`).
- [ ] 3.3 Новая `wipe_shard_dirs`. **Семантика пустого набора:** `shopt -s nullglob`, цикл по `frontend/admin/.next-shard-*`; ноль совпадений (чистая машина, первый запуск) — **успех**, стирать нечего; fail-fast — только на реальную неудачу `rm` существующей папки: сообщение с путём и `exit 1` (на `set -e` и на код возврата голого `rm` с литеральным глобом не полагаться).
- [ ] 3.4 Новая `cleanup_shards` (лестница спеки §3.3, вызов в trap `:193` совместим):
  1. TERM всем PID из `SHARD_BACKEND_PIDS` (это PID обёрток); комментарий в теле функции обязателен: TERM обёртке каскадно TERM-ит её трекаемых детей (бэкенд, родителя `next dev`), но **не** внука `next-server` — единственный путь добить внука, это свип; trap в `e2e-shard-start.sh` не «чинить» (расширение трекинга = скрытый PGID, запрещён спекой §3.3);
  2. бюджетное ожидание: поллинг `kill -0` каждые 0.5 с, общий бюджет 10 с (константа `CLEANUP_BUDGET_S=10`);
  3. пережившие → `kill -9`;
  4. контрольный свип «порт + маска команды», двухступенчатый pgrep (`pgrep -f` не умеет AND — фильтр по аргументам вторым шагом): фронты — кандидаты `pgrep -f 'next dev -p 300[2-3]'`, для каждого PID проверить `ps -p "$pid" -o args=` и держание порта из `SHARD_FRONTEND_PORTS` (`lsof -ti :$port` содержит PID) → `kill -9`; бэкенды — кандидаты `pgrep -f 'uvicorn'`, для каждого PID в `ps -o args=` искать `test_memo_shard` и держание порта из `SHARD_BACKEND_PORTS` → `kill -9`. Голый `lsof`-килл по порту без маски в уборщике запрещён (гонка с невиновным займётом порта); глобальный pkill `next-server` запрещён (`test-all.sh:78-79`);
  5. `rm -f backend/test_memo_shard*.db`.
- [ ] 3.5 В `test-all.sh`: сорсировать библиотеку рядом с определением портов (`:153-154`); удалить перенесённые inline-версии (`:61-83`, `:183-193`); trap `EXIT cleanup_shards` (`:193`) остаётся без изменений.

### DoD

`test-all.sh` не содержит inline-копий перенесённого; библиотека сорсируется и функции вызываются. Поведенческая проверка — кейсы (b), (c) Task 6. E2E-сценарии: S2, S3, S4.

## Task 6: dryrun-харнесс — кейсы библиотеки (вайп + уборщик)

### Classification: standard

### Required Docs

Спека §5 (S2, S3, S4), §6 DoD (b), (c). Библиотека из Task 3 сорсируется тестом напрямую — `test-all.sh` целиком не запускается. Перед сорсированием тест объявляет глобалы, которые функции читают: `SHARD_FRONTEND_PORTS`/`SHARD_BACKEND_PORTS` — **тестовые** порты из изоляционного диапазона (не боевые 3002/3003/8001/8002 — на машине разработчика может жить чужой worktree-шард), `SHARD_BACKEND_PIDS`, `ROOT` — на tempdir кейса.

### Steps

- [ ] 6.1 Кейс (b) S2, безусловность: fixture — создать две папки `.next-shard-1`/`.next-shard-2` (под `ROOT` tempdir) с файлами внутри; вызвать `wipe_shard_dirs` → папки исчезли, код 0; второй вызов на пустом месте → код 0 (ноль совпадений — успех, семантика 3.3).
- [ ] 6.2 Кейс (b) S2, fail-fast: PATH-заглушка `rm`, возвращающая не-ноль для путей `.next-shard-*` (единственный детерминированный способ уронить удаление; chmod-трюки на darwin недетерминированы — удаление требует прав на родителя, не на саму папку); вызвать `wipe_shard_dirs` с существующей fixture-папкой → не-нулевой код + сообщение с путём.
- [ ] 6.3 Кейс (c) S3, конечность: фейковая обёртка — фоновый `sleep 60` (PID в `SHARD_BACKEND_PIDS`); замер `date +%s` вокруг вызова `cleanup_shards`: вернулась ≤ 15 с; процесс мёртв.
- [ ] 6.4 Кейс (c) S4, TERM-стойкий держатель. Конструкция (один процесс, bash+системный python3, без nc/perl):
  ```bash
  ( exec -a uvicorn python3 -c '
  import signal, socket, sys, time
  signal.signal(signal.SIGTERM, signal.SIG_IGN)
  s = socket.socket(); s.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
  s.bind(("127.0.0.1", int(sys.argv[1]))); s.listen(1); time.sleep(60)
  ' "$TEST_PORT" test_memo_shardX ) &
  ```
  argv процесса: `uvicorn -c <код> <порт> test_memo_shardX` — проходит обе ступени маски (`pgrep -f uvicorn` + `test_memo_shard` в args) и держит тестовый порт. Вызвать `cleanup_shards` → держатель мёртв (kill -9 пробивает SIG_IGN), порт свободен. Контрольный кейс: тот же держатель **без** `test_memo_shard` в argv (и не `uvicorn`) → выжил (маска не дала убить невиновного); добить вручную в cleanup-блоке теста.
- [ ] 6.5 Гигиена: все процессы теста — на тестовых портах; по завершению кейса тест сам добивает свои фоновые PID (`kill -9` + `wait`), ни один держатель не переживает тест.

### DoD

Кейсы (b), (c) зелёные; тест не трогает боевые порты и не оставляет процессов. E2E-сценарии: S2, S3, S4.
