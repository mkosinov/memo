# План #417: окно отмены в e2e — управляемые часы вместо реальных ожиданий по 5,5 с

**Goal:** заменить 22 литеральных ожидания `waitForTimeout(5_500)` (окно отложенного удаления) на хелпер-обёртку с управляемыми часами «пауза → тело окна → перемотка → сток → отпускание»; замаскированный буфер `WINDOW_MS + 500` в unload-guard остаётся реальным (осознанное исключение, спека). Попутно устраняется класс тайминговых флейков окна (#291) и переносятся его защиты в US-3. Полная механика и роспись всех мест — в спеке `docs/specs/2026-10-07-undo-window-page-clock-417-design.md` (rev2, на main); план не повторяет её, задачи реализуют сценарии S1–S6.

**Architecture:** единственная новая точка — хелпер `withUndoWindow(page, fn, opts)` в `frontend/admin/e2e/fixtures/helpers.ts` (общий дом e2e-хелперов; сегодня хелпера часов нет). Механика: `page.clock.pauseAt(<сейчас>)` → колбэк (только работа с окном) → `page.clock.fastForward(5_500)` → короткий реальный сток на стороне Node (`drainMs`, по умолчанию ~500 мс — события запросов асинхронны) → `page.clock.resume()`. Для позитивных проверок «DELETE дошёл» после обёртки используется существующий `commitDeleteWait` (там же в helpers, часам неподвластен). Порядок «пауза до создающего окно действия» гарантирован вызовом: обёртка открывается до клика «×». Код приложения, конфиг Playwright, 4 существующих использования часов и спецификации реального времени (офлайн-детектор, серверные события) не трогаются.

**Tech Stack:** Playwright 1.x (`page.clock`: `pauseAt`/`fastForward`/`resume`), TypeScript, локальные прогоны по `docs/tests_workflow.md` (shard-rest 3003/8002, shard-schedule 3002/8001; воркер один — параллельных тестов в моменте нет, каждому тесту свежая страница).

## Task 1: хелпер withUndoWindow

### Classification: standard

`frontend/admin/e2e/fixtures/helpers.ts`: экспорт `withUndoWindow(page, fn, opts?)` — `opts.advanceMs` (по умолчанию `5_500`), `opts.drainMs` (по умолчанию `500`). Контракт в docstring: вызывать ДО действия, создающего окно (таймеры, запланированные до паузы, реальны и перемоткой не управляются); внутри `fn` — только работа с окном (клик «×», проверки тоста/скрытия строки, при undo — клик «Отменить»); ничего, зависящего от реального времени (дебаунс-ввод, ожидание SSE-событий). После перемотки — реальный сток `drainMs` (Node-сторона, часам неподвластен) и `resume()`. Возврат — результат `fn`. Повторный вызов в одном тесте легален (пара окон сценария 19).

### Required Docs

- спека §Техническое решение (шаги 1–5), §Концепт

### DoD

- Хелпер импортируется существующими спеками без циклических зависимостей; типы `Page`/`opts` выводятся из контракта.
- Ручная проверка на любом живом окне: пауза держит окно (тост не исчезает сам), перемотка срабатывает мгновенно, `resume()` возвращает ход времени (тост без отмены исчезает в реальном темпе).
