# План: бэкенд lint/mypy — рахет-гейт в CI и волновая чистка до нуля (#306)

- **Дата:** 2026-10-08.
- **Спека:** `docs/specs/2026-10-08-backend-lint-mypy-ratchet-306-design.md` (main `1c077ffb`, Gate B OK 2026-10-08).
- Поведенческая дельта (что изменится для пользователя) живёт в спеке — здесь не повторяется.

## Goal

Остановить рост долга статических проверок бэкенда (ruff 269 / mypy 531 на 2026-10-08) немедленным CI-рахет-гейтом и обнулить его волнами, дойдя до постоянного полного гейта (`ruff`/`mypy` напрямую по exit-коду).

## Architecture

- `backend/scripts/lint_budget.py` — единственный исполнитель обоих инструментов и владелец их exit-кодов: запускает `ruff check src tests scripts --output-format json` (пороги per-rule) и `mypy src --no-incremental` (тотал из итоговой строки), правила «факт > порога / факт < порога / рост порога против базы — красные, равенство — зелёное», fail-closed на поломке инструмента.
- Джоба `backend-lint` в `.github/workflows/test.yml` — параллельно тестам (без `needs`), `uv sync --extra dev`, триггеры как у workflow (`pull_request` + `push` в main).
- Волны правок (сохраняют поведение, полный тест-сьют обязателен): 0 — конфиг B008 + безопасные автоправки; 1..k — mypy по семьям от большей к меньшей; r — ruff-хвост; финал — удаление скрипта сравнения, прямой вызов инструментов.

## Tech Stack

Python (uv, зависимости в dev-экстре), ruff, mypy (`strict = true`, без ослабления), GitHub Actions; проверки волн — pytest-сьют + e2e-шарды Playwright.

**Волна 0 = один PR:** задачи 1–3 приземляются одним PR «волна 0» (спека: механика и конфиг — один PR).

## Task 1 — скрипт бюджета `backend/scripts/lint_budget.py`

**Классификация:** small. **Required Docs:** спека §Механика гейта (пп. 2–6).

- Пороги константами в скрипте: ruff — per-rule словарь `{"I001": 44, …}` (снять точные значения на `origin/main` в момент старта), mypy — тотал.
- Запуск `ruff check src tests scripts --output-format json` и `mypy src --no-incremental`; парсинг ruff — по JSON, mypy — итоговая строка `Found N errors`.
- Fail-closed: exit-код инструмента ≠ «нарушения найдены» (ruff ≥ 2, mypy = 2), пустой/непарсимый вывод → exit 1 с сообщением «инструмент сломан».
- Правила сравнения на инструмент: факт > порога → «PR добавил ошибок: было N, стало F»; факт < порога → «опусти порог до F»; равенство → зелёный. Отчёты обоих инструментов печатаются, короткого замыкания нет.
- Запрет роста: в CI скрипт читает пороги из базы (`git show <merge-base>:backend/scripts/lint_budget.py`; для пуша в main — `HEAD~1`) и краснеет на рост любого порога; файла в базе нет → создание (волна 0) разрешено.
- Локальная точка входа: `uv run python scripts/lint_budget.py` (из `backend/`).
- Маппинг: US-1, US-2, US-4 спеки.

## Task 4 — волна mypy: services (~170)

**Классификация:** standard. **Required Docs:** спека §Волны (волны 1..k), §Политики, §Координация.

- Разбивка ошибок по кодам (`--show-error-codes`), честные аннотации; нерешаемый паттерн — точечный `[[tool.mypy.overrides]]` с обоснованием в PR.
- Крупная семья делится на под-PR по файлам; каждый опускает порог до своего факта; параллельные под-PR сериализуются ребейзом (равенство порога факту принуждает).
- Граница координации: файл **определения** `@transactional`-декоратора (`src/services/decorators.py`, трекер #394) не трогать; он сейчас даёт 0 mypy-ошибок сам по себе. Аннотации **мест использования** декоратора — обычная работа своих семей (действует для задач 4–7).
- Маппинг: US-2.
