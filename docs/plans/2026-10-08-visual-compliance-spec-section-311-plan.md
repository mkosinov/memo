# План: #311 — обязательная секция визуальных проверок в дизайн-спеках

- Спека: `docs/specs/2026-10-08-visual-compliance-spec-section-311-design.md` (rev4: расширение объёма — подсказка URL на пункт, решение пользователя 2026-10-09, гейт G4.5 вариант B; rev3 — гейт B пройден 2026-10-08)
- Дата: 2026-10-08 (rev4 плана — 2026-10-09)

## Goal

Ввести и исполнить контракт «каждая спека несёт секцию визуальных проверок»: чек-лист
проверяемых пунктов с машинной подсказкой или маркер N/A; пустая/прозаическая секция —
красный код возврата 3 с возвратом карточки в In Design; синхронизировать канон
харнесса (memo + superagents). Поведенческая дельта — в спеке, здесь не повторяется.

## Architecture

Хост (zcode): скрипт сверки `scripts/visual-compliance-check.sh` + парсер
`scripts/visual-compliance-parser.js` + их тесты; канон спеки —
`.zcode/skills/design-phase/SKILL.md`, указатель — `.zcode/skills/auto-design/SKILL.md`.
Контейнер (opencode): маршруты гейта G4.5 — `.opencode/agents/architect.md`,
`.opencode/agents/manager.md`, `.opencode/skills/subagent-driven-development/SKILL.md`.
Канон superagents: зеркальная правка трёх файлов в `~/dev/superagents`. Изменений
продуктового кода нет — только харнесс и одна спека-образец.

## Tech Stack

Bash (`set -euo pipefail`, таблица кодов возврата в шапке), Node.js (парсер —
CommonJS, без зависимостей), существующий тест-раннер парсера
`scripts/test-visual-compliance-parser.js` (node-тесты без фреймворка),
`scripts/test-all.sh` как точка подключения тестов.

## Task 1. Парсер: применимость, грамматика N/A, устойчивость разбора

Классификация: small. Required Docs: спека, разделы «Решение» п.1, «Технические
детали» (Грамматика N/A, Форма checks.json).

- `scripts/visual-compliance-parser.js`: выход меняется с голого массива на
  `{ "applicable": bool, "checks": [...] }`; `applicable=false` только для
  секции-маркера N/A — грамматика спеки дословно: единственная содержательная
  строка секции, после обрезки пробелов равная `N/A` или `- N/A` (ASCII-дефис —
  префикс пункта чек-листа; обе формы принимаются), регистр неважен; длинное и
  среднее тире и прочие начертания НЕ принимаются; правило маркера применяется
  только когда обычный разбор дал ноль машинных подсказок и действует для всех трёх
  имён секции; прозаические абзацы и горизонтальные линии маркер не отменяют.
- Расширить `scripts/test-visual-compliance-parser.js`: US-1 (секция с
  `data-testid`/`aria-*`/кавычками → automatable-проверки, applicable=true),
  US-2 (N/A → applicable=false, пустой список; обе формы — `N/A` и `- N/A`),
  отрицательные случаи (среднее/длинное тире вместо дефиса — `– N/A`, `— N/A` →
  обычный разбор, ноль подсказок; код-блок внутри секции не даёт машинных подсказок;
  заголовок только `##`, не `###`).
- Проверка: node-тесты зелёные (US-1, US-2).

## Task 2. Скрипт сверки: порядок стадий, код 3, ранний выход, гигиена

Классификация: small. Required Docs: спека, «Технические детали» (Порядок стадий,
Сбой парсера, Форма checks.json, Коды возврата, Попутно).

- `scripts/visual-compliance-check.sh`: порядок — аргументы → существование спеки →
  парсинг → ветвление: нет секции / пустая / ноль машинных подсказок и не N/A →
  `exit 3` с сообщением, адресующим возврат карточки в дизайн; N/A → печать
  «not applicable» и немедленный `exit 0` до проверок зависимостей, сервера,
  Playwright и генерации отчёта; применимая секция → прежний конвейер.
- Убрать `|| true` с вызова парсера: ненулевой выход парсера → `exit 2`;
  `checks.json` перезаписывается в начале прогона.
- Правка двух внутренних потребителей формы JSON: подсчёт `CHECKS_COUNT`
  (`.checks.length`) и чтение массива в генерируемом Playwright-раннере.
- Шапка: таблица кодов 0/1/2/3 (единственный канон кодов); попутно — пути в
  вызовах `node -e` передавать аргументами процесса, не интерполяцией.
- Smoke-тесты (bash, без dev-сервера): US-2 — спека с N/A → exit 0, «not
  applicable» в выводе; US-3 — три варианта красного (нет секции / пустая /
  прозаическая) → exit 3.

## Task 5. Канон хоста: design-phase + указатель auto-design

Классификация: small. Required Docs: спека, «Технические детали» (правки
харнесс-доков, п.1 решения).

- `.zcode/skills/design-phase/SKILL.md` — канон секции: обязательность для каждой
  новой спеки; канонический шаблон пункта
  `- [ ] <элемент интерфейса> — <проверяемое утверждение>` + машинная подсказка
  (`data-testid="…"`, `aria-label="…"`, «текст в кавычках») хотя бы в одном пункте;

  в fast-track несёт N/A.
- `.zcode/skills/auto-design/SKILL.md` — краткий указатель на канон (одно
  предложение, без пересказа — правило единого источника).

## Порядок и зависимости

пина URL) + ревью харнесс-доков одним списком.
