# План: локальное vitest-окружение admin (#389)

- **Спека:** `docs/specs/2026-10-10-vitest-local-env-design.md` — единственный источник поведения; план не пересказывает её, задачи ссылаются на секции.
- **Goal:** полный прогон vitest в `frontend/admin` зелёный в контейнере и в CI без ручных действий: тестовое время всегда UTC, Web Storage — родной jsdom (Node-заглушка выключена флагом), версия Node задана декларативно (`.nvmrc` для CI, `node:26-bookworm` в Dockerfile контейнера — правка Dockerfile и пересборка уже выполнены вне плана: Dockerfile внесён 11.10, пересборку делает пользователь сам).
- **Architecture:** одна точка правок в приложении — `frontend/admin/vitest.config.ts` (две строки: TZ-пин через присваивание в конфиге, флаг через `test.execArgv`); одна точка в CI — новый `.nvmrc` + чтение его четырьмя джобами `test.yml`. Прод-код, ассерты, setup-файл тестов и e2e-инфраструктура не меняются.
- **Tech Stack:** vitest 4.1 (конфиг: `test.execArgv`, env-наследование), GitHub Actions (`node-version-file`), Node (`--no-experimental-webstorage`).

## Task 1 — vitest.config: UTC и выключение Node-заглушки

- **Классификация:** trivial
- **Файлы:** `frontend/admin/vitest.config.ts`.
- **Работа:** две правки по спеке §Решение п.2–3: (а) после блока импортов, до `defineConfig`, — `process.env.TZ = 'UTC'` (механизм — наследование env дочерними процессами, не порядок относительно ESM-импортов); (б) в секцию `test` — `execArgv: ['--no-experimental-webstorage']`. Рядом — по одному краткому комментарию-обоснованию (ограничение, невидимое из кода: флаг выключает встроенную заглушку `localStorage` новых Node, конфликтующую с jsdom-окружением; TZ — паритет с CI-раннерами). Ничего больше в файле не менять (пул, таймауты, алиасы — как были).
- **Проверка:** полный `npx vitest run` в контейнере — до правки в нём красные только TZ-тесты (контейнер в Europe/Moscow, Node 24 без заглушки: localStorage-группа уже зелёная), после правки — весь прогон зелёный. На хосте (Node 25.9, обе группы красные) — тот же зелёный результат: флаг закрывает группу localStorage, UTC — тайм-зону.
- **Required Docs:** спека §Решение п.2–3, §Риски (запасной приём — только если флаг исчезнет из Node).
- **Соответствие сценариям:** US-1, US-3, US-4.

## Task 2 — Пин версии: .nvmrc и четыре джобы CI

- **Классификация:** trivial
- **Файлы:** `.nvmrc` (новый), `.github/workflows/test.yml` (все четыре места `node-version: 22` — джобы `frontend-tests`, `frontend-checks`, `shard-script-checks`, `e2e-tests` — меняются на `node-version-file: .nvmrc`).
- **Работа:** `.nvmrc` содержит одну строку `26`. В воркфлоу заменяется только строка версии, шаги и структура джобов не трогаются. Воркфлоу `web-checks.yml`, `visual-check.yml`, `update-snapshots.yml` остаются на 22 — вне рамок (спека §Границы).
- **Проверка:** CI у PR реализации — все четыре работы зелёные на Node 26 (в отчёте джобов видна версия из `.nvmrc`). При красноте e2e на 26 — по спеке §Риски: починка совместимости либо осознанный временный возврат одного джоба на 22 с комментарием.
- **Required Docs:** спека §Решение п.1 (включая границу пина), §Границы.
- **Соответствие сценариям:** US-2, US-4.

## Task 3 — Полная верификация прогонов и закрытие дублей

- **Классификация:** small
- **Работа:** без правок кода. Итоговая сверка по DoD спеки: полный `npx vitest run` в `frontend/admin` в контейнере зелёный (все 18 файлов группы localStorage и все TZ-чувствительные тесты; в контейнере до пересборки — Node 24); зелёный CI у PR (четыре работы на 26). После пересборки контейнера пользователем — повторный полный прогон в контейнере на Node 26 и беглый e2e smoke (спека §Риски); эти два шага — пост-условие в комментарии issue, не блокер мержа PR. После фактического мержа PR — закрыть issues #403 и #460 с комментарием-обоснованием поглощения их TZ-темы этим дизайном (спека §Поглощение дублей: #403 сам называет пин в конфиге закрывающим решением; #460 исполняется своей второй опцией «зафиксировать в конфиге тестов»). При вскрытии иных окруженческих падений за пределами двух групп — отдельный issue, не расширение данного (спека §Границы).
- **Required Docs:** спека §Техническая сводка (DoD), §Риски, §Поглощение дублей.
- **Соответствие сценариям:** охрана всех четырёх (US-1–US-4).
