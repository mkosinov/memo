# План #422 — фиксированная функциональная неделя сида

- **Спека:** `docs/specs/2026-10-20-e2e-seed-fixed-week-422-design.md` (rev3, main 260198e0)
- **Issue:** #422

## Goal

Убрать зависимость e2e-прогонов от текущей даты: функциональная половина сида садится в фиксированные недели (опорная — 2026-06-01), страж готовности `globalSetup` сверяется с опорной неделей, все «сегодня»-вычисления в спеках и фикстурах переводятся на константу опорной недели. Behavioral Delta — в спеке, здесь не пересказывается.

## Architecture

Три слоя, правятся согласованно: генерация сида (`backend/src/seed/seed.py` — источник дат), проверка готовности (`frontend/admin/e2e/globalSetup.ts` — страж опорной недели), навигация и данные спек (`frontend/admin/e2e/fixtures/` — константа `SEED_WEEK_MONDAY`, хелперы, фабрики + ~30 файлов спек). Визуальная половина (неделя 2026-06-15, 61 эталон), канон #310, флейк-гейт #415 и механика copy-last-week не меняются.

## Tech Stack

Python (seed, pytest), TypeScript (playwright-фикстуры, спеки), playwright.config. Коммит — через PR с зелёным CI (флейк-гейт — арбитр стабильности миграции).

## Task 1 — сид: фиксированные недели и инвариант-докстринг

Классификация: **standard**. US: С1. Required Docs: спека §1.

- `backend/src/seed/seed.py`: ввести `FUNC_WEEK_START = datetime(2026, 6, 1)` (понедельник) — единственный источник; `WEEK3_START = FUNC_WEEK_START`, `WEEK2_START = FUNC_WEEK_START - timedelta(days=7)`, `WEEK_START = FUNC_WEEK_START - timedelta(days=14)`.
- Удалить `_today`, `_THIS_WEEK_MONDAY`, `_LAST_WEEK_MONDAY`, `_WEEK_BEFORE_MONDAY` и `_get_week_monday` (перед удалением грепнуть использование `_get_week_monday` внутри seed.py — функция существует только там).
- Обновить комментарий-мотивацию у недель («current week — so e2e tests find activities» больше не причина) и добавить в докстринг модуля инвариант из спеки §1: write-пути принимают даты в прошлом; появление серверной валидации `date ≥ now` ломает фиксированный мир (dev/playground/e2e) — пересчитать недели.
- DoD: `uv run python -m seed.seed` на чистой тестовой БД проходит; `grep -n 'datetime.now()' backend/src/seed/seed.py` — ноль вхождений (страж отсутствия календарной генерации); `pytest backend/tests/test_seed.py` без новых падений (относительные ассерты, если есть, закрываются Task 2 в том же PR).
