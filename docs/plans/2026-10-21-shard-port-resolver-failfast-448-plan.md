# План #448 — /proc-резолвер портов + fail-fast прогона

- **Спека:** `docs/specs/2026-10-20-shard-port-resolver-failfast-448-design.md` (rev4, main 62a0d18b)
- **Issue:** #448

## Goal

Устранить класс «невидимый держатель порта» в контуре прогонов (lsof слеп к переписанному `process.title` next-server): все пять проверок портов переводятся на собственный резолвер «порт → PID» по /proc/net/tcp{,6} + /proc/*/fd, а смерть дочернего сервера стека даёт немедленный красный вердикт всего прогона (жёсткая форма: обе Playwright-стадии останавливаются). Behavioral Delta — в спеке, здесь не пересказывается.

## Architecture

Два независимых слоя, каждый закрываем своим задачами: резолвер (примитив `listen_pairs` в `scripts/lib/shard-helpers.sh` + замена пяти lsof-точек) и fail-fast (слой стека в `scripts/e2e-shard-start.sh` + слой оркестратора в `scripts/test-all.sh` с watchdog-примитивом в `shard-helpers.sh`). Тестовый контур: существующие два dryrun-набора (`shard-helpers.dryrun.test.sh` — миграция lsof-стабов на /proc-фикстуры, `e2e-shard-start.dryrun.test.sh` — кейсы слоя стека); в CI входит только второй (статус-кво). Механика тегов/лизов #317, kill-лестница и pgrep-гейты не меняются.

## Tech Stack

Bash 3.2-совместимые скрипты + awk (резолвер, watchdog), bash dryrun-наборы как тестовый каркас. Коммит — через PR с зелёным CI.

## Task 1 — примитив `listen_pairs` + нормализатор констант

Классификация: **standard**. US: US-1, US-3 (кейсы конъюнкции). Required Docs: спека §3.1, §3.2 (константы), §7.

- `scripts/lib/shard-helpers.sh`: новый примитив `listen_pairs` — один сэмпл на вызов, stdout строки «pid port»: `/proc/net/tcp` + `/proc/net/tcp6` (отсутствие tcp6 — не ошибка), строки состояния `0A` (LISTEN), порт = hex локального адреса после последнего двоеточия → dec, inode → владелец одиночным проходом `/proc/[0-9]*/fd/*` по симлинку `socket:[inode]`.
- Fail-closed: LISTEN-строка без атрибутируемого PID не выбрасывается — порт маркируется занятым: в выводе строка с ПУСТЫМ pid (формат сегодняшнего сэмпла пар сохранён; для `_masked_pids` пустой pid не матчится ни с одним pgrep-кандидатом — убийства нет, занятость есть).
- Не-Linux фолбэк: `/proc/net/tcp` нечитаем → однократное предупреждение в stderr → возврат не-нулевого rc/специального маркера, при котором Точки (Task 2) используют прежний lsof-вызов. Пути к таблицам — литеральные дефолты; переопределение переменными honoured только при непустом флаге dryrun-режима (переменная набора тестов).
- Нормализатор `_watch_interval_s`: env `SHARD_STACK_WATCH_S`/`SHARD_RUN_WATCH_S` → дефолт 5 при не-числе/0/отрицательном/больше 600.
- `scripts/lib/shard-helpers.dryrun.test.sh`: кейсы `listen_pairs` на /proc-фикстуре (создание фейк-каталога `/proc`-формы: tcp/tcp6, LISTEN/не-LISTEN, hex→dec, inode без владельца → «занят», отсутствие tcp6, нечитаемый корень → фолбэк-ветка); кейс нормализатора (не-число/0/отрицательное/601 → 5); кейсы конъюнкции US-3 (порт+маска → убить; порт без маски → не убивать; неатрибутируемый → не убивать, порт занят). Фикстура — отдельный хелп набора, переиспользуется Task 2.
- DoD: новые кейсы зелёные; существующие кейсы набора не тронуты (упадут только те, что пинируют lsof-стабы в заменяемых функциях — их миграция в Task 2, в этом PR).

## Task 2 — замена пяти lsof-точек

Классификация: **standard**. US: US-2, US-3. Required Docs: спека §3.1 (пять замен), §7.

- `scripts/lib/shard-helpers.sh`: (а) `_masked_pids` — источник pairs = `listen_pairs` (парсинг потребителей не меняется); (б) `allocate_shard_ports` — один сэмпл на вызов, фильтр «порт ∈ кандидаты», вместо `lsof -ti` на порт; текст ошибки-подсказки про lsof заменить на подсказку смотреть /proc-таблицы; (в) `_legacy_ports_free` — сэмпл против `SHARD_LEGACY_PORTS`.
- `scripts/test-all.sh`: (г) TOCTOU-recheck «порт занят между проверкой и стартом» — сэмпл; (д) гард `.next`-вайпа на легаси-портах — сэмпл.
- Все пять веток при фолбэке (Task 1) используют прежний lsof-вызов — поведение не-Linux сред не меняется.
- Миграция затронутых кейсов `shard-helpers.dryrun.test.sh` (сегодня строятся на PATH-стабе lsof, включая счётчик вызовов кейса 9): на /proc-фикстуру из Task 1; счётчик вызовов lsof в не-Linux-ветке сохраняется на своей фикстуре; кейсы allocate/legacy/TOCTOU/вайп-гарда прогоняются на фикстуре с занятыми/свободными портами, включая «занят невидимым».
- DoD: весь `shard-helpers.dryrun.test.sh` зелёный; grep: в `scripts/lib/shard-helpers.sh` и `scripts/test-all.sh` lsof остаётся только в не-Linux-фолбэке `listen_pairs`; ручной smoke: живой node-свидетель с переписанным `process.title` держит порт — allocate обходит (протокол в PR).

## Task 3 — fail-fast слой стека

Классификация: **standard**. US: US-4/US-5 (стек-часть), US-3 (trap-добор). Required Docs: спека §3.2 (слой стека, кап лога), §7.

- `scripts/e2e-shard-start.sh`, финальный блок: вместо `wait "$FRONTEND_PID"` — цикл ожидания ЛЮБОГО из двух серверов: пока живы оба — `sleep "$(_watch_interval_s SHARD_STACK_WATCH_S)"`; смерть любого — диагностика «stack shard N: backend|frontend died on :PORT»: путь до файла лога печатается ВСЕГДА + хвост лога (последние 20 строк, case-insensitive фильтр cookie/authorization/auth-token/api-key/bearer/password/secret/token, отсутствующий файл — строка «лог не создан») и exit 1; exit-trap прибирает lease.
- Дополнение exit-trap (`_orig_cleanup`): после TERM своих двух детей — добор внуков: `_sweep_masked` с портами ЭТОГО стека и прежними масками (резолвер делает внуков видимыми).
- `scripts/e2e-shard-start.dryrun.test.sh`: кейсы — смерть бэкенд-пина → rc=1 + адресное сообщение; смерть фронт-пина → rc=1; кейс trap-добора (фейк-держатель порта стека с маской убирается, без маски — остаётся); интервалы — env-переопределением, дети — реальные фоновые.
- DoD: набор зелёный в CI (`shard-script-checks`); ручной smoke: остановка стека не оставляет держателей его портов (протокол в PR).

## Task 4 — fail-fast слой оркестратора

Классификация: **standard**. US: US-4, US-5 (вердикт), US-6. Required Docs: спека §3.2 (оркестратор, exit-семантика, маркер), §7.

- `scripts/lib/shard-helpers.sh`: watchdog-примитив оркестратора — фоновый цикл: каждый тик `kill -0` по списку PID стек-обёрток; провал `kill -0` → `wait "$pid"` (рептинг + статус) → вердикт «умер»: печать диагноза (стек, порт, хвост стека-лога с капом Task 3), создание маркер-файла в `$LOG_DIR` (каталог логов прогона), TERM обеим Playwright-стадиям с эскалацией (TERM → грейс-полл бюджетом существующей лестницы → SIGKILL); завершение, когда все стадии вышли (стадии передаются списком; их завершение отслеживается тем же `kill -0`+`wait`-приёмом — без `wait -n`).
- `scripts/test-all.sh`: запуск watchdog сразу после старта стеков (до readiness-ожидания); жёсткий порядок завершения: финальный wait → ОСТАНОВ watchdog → проверка маркера → вердикт (живой watchdog во время exit-trap teardown зелёного прогона не должен успеть поставить ложный маркер); маркер существует → FAIL=1 (смерть обёртки после зелёной её стадии краснит прогон, US-6). Обёртки в ALL_PIDS НЕ вводятся; exit-семантика стадий и нормальный teardown зелёного прогона не меняются.
- `scripts/lib/shard-helpers.dryrun.test.sh`: кейсы на реальных фоновых детях с env-интервалами: смерть обёртки при живых стадиях → маркер + TERM обеих стадий (сосед остановлен — жёсткая форма rev4); смерть обёртки после завершения стадии → маркер; без смертей → чистый выход без маркера; заклинившая стадия → эскалация до KILL в пределах грейс-бюджета.
- DoD: кейсы зелёные; ручной smoke с реальным стеком: kill -9 uvicorn посреди полного прогона → красный вердикт и полное завершение прогона ≤ 2 интервалов, обе стадии остановлены, lease снят (протокол в PR).
