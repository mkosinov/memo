# План: замок тяжёлых прогонов + починка ожидания готовности (#472)

## Goal

Реализовать спеку `docs/specs/2026-10-22-test-concurrency-lock-472-design.md` (рев.2): машинный замок на тяжёлые прогоны внутри контейнера + единый источник лимитов готовности, маркер готовности с ранним отказом, проверка живости в циклах опроса. Поведенческая дельта — в спеке (`## Behavioral Delta`), здесь не повторяется.

## Architecture

Харнес-уровень без кода приложения: `scripts/` (test-all.sh, e2e-shard-start.sh, lib/shard-helpers.sh, новый with-test-lock.sh) + канон запуска (`docs/tests_workflow.md`, `.opencode/skills/dev-workflow/SKILL.md`). Замок — `flock` на файле тома контейнера вне git-копий; готовность — константы-дедлайны в общей библиотеке и маркер, передаваемый переменной окружения. Существующие механизмы переиспользуются: сторож #448 (обёртки, тик 5 с), EXIT-трап и startup-clean test-all, dryrun-тесты харнеса.

## Tech Stack

bash; `flock` (util-linux — наличие в контейнере проверено панелью); dryrun-сценарии по образцу `scripts/lib/shard-helpers.dryrun.test.sh` (исполняются внутри test-all); без новых зависимостей.

## Task 1: Константы-дедлайны и живость в циклах опроса стека

### Classification: standard

### Required Docs

- `docs/specs/2026-10-22-test-concurrency-lock-472-design.md` — `## Починка ожидания готовности`, `## Behavioral Delta` (семантика дедлайнов).

- В `scripts/lib/shard-helpers.sh`: `READY_BUDGET_BACKEND_S=60`, `READY_BUDGET_FRONTEND_S=120` (env-переопределяемые по существующей идиоме файла), `READY_ORCHESTRATOR_S` — производная (сумма + 180).
- В `scripts/e2e-shard-start.sh`: циклы опроса бэкенда и фронтенда перевести со счётчиков итераций на дедлайны стенового времени (шаг не длиннее остатка: curl `--max-time` ограничен остатком, сон усечён); на каждом шаге `kill -0` — цикл бэкенда проверяет `BACKEND_PID`, цикл фронтенда `FRONTEND_PID` и `BACKEND_PID`; смерть — немедленный фатальный провал с хвостом лога умершего (переиспользовать существующий механизм хвостов).
- Реализует US-5 (часть обёртки стека).
- DoD: сценарная проверка US-5 (уровень обёртки стека) проходит — убитый до готовности бэкенд даёт фатальный провал за секунды с хвостом лога, а не выжигание бюджета; значения констант видимы в одном месте.

## Task 2: Маркер готовности и ожидание оркестратора по маркерам

### Classification: standard

### Required Docs

- `docs/specs/2026-10-22-test-concurrency-lock-472-design.md` — `## Починка ожидания готовности`, `## User Scenarios` (US-5, US-6).

- В `scripts/e2e-shard-start.sh`: после успешного опроса фронтенда (до warmup) создавать маркер по пути из `SHARD_READY_MARKER`; переменная не установлена — записи нет (CI/ручной запуск); при старте стека пролежавший маркер удаляется.
- В `scripts/test-all.sh`: убрать дублирующий HTTP-опрос готовности; ждать маркеры обоих осколков с потолком `READY_ORCHESTRATOR_S`; на каждом тике проверять живость обёрток (`kill -0` и/или маркер сторожа #448) — смерть обёртки = немедленный провал с хвостами логов; по исчерпании потолка — провал с хвостами логов стеков.
- Реализует US-5 (часть оркестратора) и US-6.
- DoD: сценарные проверки US-5/US-6 (уровень оркестратора) проходят — смерть обёртки во время ожидания проваливает прогон в пределах одного тика; задержка открытия порта фронтендом до 90 с не приводит к сдаче оркестратора раньше стека.

## Task 3: Обёртка замка и самозахват полного прогона

### Classification: standard

### Required Docs

- `docs/specs/2026-10-22-test-concurrency-lock-472-design.md` — `## Механизм замка`, `### Точки входа под замком`, `## Behavioral Delta`.

- Новый `scripts/with-test-lock.sh <команда...>`: захват `flock` на `${MEMO_TEST_LOCK_PATH:-/root/workspace/.memo-heavy-tests.lock}`; очередь — немедленная попытка, затем повторы каждые `MEMO_LOCK_POLL_S` (300), потолок `MEMO_LOCK_WAIT_S` (3600) по фактическому времени (сон усечён до остатка); статус-строка каждую попытку; провал по потолку — код 75 и сообщение «машина занята чужим тяжёлым прогоном дольше 60 мин; перезапусти прогон позже»; экспорт `MEMO_TEST_LOCK_HELD=1` и сквозной запуск при ней; команда запускается БЕЗ дескриптора замка, обёртка ждёт её завершения; обход без замка с однострочным уведомлением (подавление при `CI=true`), если каталог отсутствует/недоступен для записи, нет `flock` или `MEMO_TEST_LOCK_DISABLE=1`; каталог никогда не создаётся.
- В `scripts/test-all.sh`: встроенный самозахват в самом начале, до ветки `SEQUENTIAL=1`, с теми же условиями обхода и предохранителем `MEMO_TEST_LOCK_HELD`; фоновые стадии порождаются с закрытым дескриптором замка.
- Реализует US-1 (вложенность), US-2, US-3, US-7 (механизм).
- DoD: ручные прогоны сценариев US-2/US-3/US-7 (малые константы, временный путь) демонстрируют мгновенное освобождение после `kill -9` держателя, провал кодом 75 на потолке, обход с уведомлением; вложенный вызов (test-all под уже взятым замком) не встаёт в очередь за самим собой — захват ровно один.

- По образцу `scripts/lib/shard-helpers.dryrun.test.sh` — сценарный набор для замка (временный `MEMO_TEST_LOCK_PATH`, малые `MEMO_LOCK_POLL_S`/`MEMO_LOCK_WAIT_S`): US-1 сериализация + вложенность (два шага), US-2 освобождение после `kill -9` держателя, US-3 провал по потолку кодом 75 (допуск — один интервал опроса), US-4 короткий прогон без очереди, US-7 обход (недоступный каталог / нет flock / DISABLE). - Реализует US-1–US-4, US-7 (проверки).
- DoD: сценарные проверки US-1–US-4, US-7 проходят автоматически в составе dryrun-тестов test-all; сценарии детерминированы (без реальных стеков и сетей).

## Task 5: Сценарии с реальным стеком (US-5, US-6) и контрольный прогон очереди
