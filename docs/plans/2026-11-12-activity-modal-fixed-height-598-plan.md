# План #598 — Модалка занятия: постоянная высота 85dvh + кнопка «Создать» в футере

## Goal

Модалка занятия во всех режимах получает постоянную высоту 85dvh (суперсед #262 в скоупе одной модалки), тело владеет скроллом без клиппинга, кнопка «Создать» переезжает в фиксированный футер. Спека: `docs/specs/2026-11-12-activity-modal-fixed-height-598-design.md` (рев.2).

## Architecture

Frontend-only: общий `Modal` получает опциональный проп класса фиксированной высоты (дефолтное поведение всех остальных модалк не меняется); `ActivityDetailsModal` передаёт фикс-класс во всех режимах; скролл — внутренние div-обеих вкладок потребителя (+`min-h-0`, `overscroll-behavior: contain`); кнопка создания — в футер через минимальный мост состояния (по образцу существующего `onSavingChange`).

## Tech Stack

Next.js (admin), Tailwind (arbitrary `dvh`), vitest (юниты), Playwright (e2e admin, `toHaveScreenshot` базлайны).

## Task 1: Проп фикс-высоты общего Modal + расширение тест-замка

### Classification: small

### Required Docs

- `docs/domain-rules/activities.md` — пункт «Activity modal fixed height (GH #598)»
- спека §4 (проп, суперсед #262, замок)

### Steps

1. `Modal`: опциональный проп `heightClass?: string`; при заданном — класс добавляется к контейнеру **в дополнение** к базовому `max-h-[85vh]` (потолок остаётся, при фикс-высоте 85dvh ≤ 85vh он не активен).
2. `ModalShell.test.tsx`: замок переписан — без пропа контейнер не содержит фикс-класса высоты (регэкс расширен на `vh` **и** `dvh` с сохранением якоря: `/(?:^|\s)h-\[\d+(d)?vh\]/` — якорь обязателен, иначе матчер ловит `h-[85vh]` внутри базового `max-h-[85vh]` и дефолтный ассерт падает), с пропом — содержит переданный класс.

### DoD

Юниты замка зелёные: дефолт чист (vh+dvh), с `heightClass` класс присутствует у контейнера.

## Task 2: Модалка занятия — фикс 85dvh, владелец скролла, кнопка в футере

### Classification: standard

### Required Docs

- `docs/domain-rules/activities.md` — пункт GH #598
- спека §4 (скролл-владелец, мост, form-ассоциация)

### Steps

1. `ActivityDetailsModal` передаёт `heightClass="h-[85dvh]"` во **всех** режимах (create + edit/quickAdd).
2. Скролл-владелец — существующие внутренние div-обеих панелей (`flex-1 flex flex-col overflow-y-auto`): добавляется `min-h-0`, `overscroll-behavior: contain` и тестид скроллящегося тела (селектор геометрических ассертов US-2, Task 3). Обёртка тела в общем `Modal` не трогается.
3. Мост кнопки: вкладка создания публикует наверх `canSave` и `submit` (колбэки/регистрация по образцу существующего `onSavingChange`; `saving` уже поднят). Подъём всей формы состояния — НЕ делать.
4. Футер create-режима: кнопка «Создать» (`data-testid="btn-create-activity"`, disabled при `!canSave || saving`) рендерится через `footer`-проп `Modal`, работает тем же механизмом `onClick={submit}` — `<form>` во вкладке не существует и не вводится (Enter-отправка не заявлена, её нет и сегодня); inline-кнопка из тела удаляется. Футер edit/quickAdd (кнопка удаления) не меняется.
5. Пере-дом юнитов: тесты кнопки из `CreateActivityTab.test.tsx` (матрица `canSave`, submit-payload) переезжают в `ActivityDetailsModal.test.tsx` (рендер панели с футером) — покрытие гейтов сохранено.

### DoD

Юниты: фикс-класс во всех режимах; кнопка в футере с правильным disabled; тестид скролл-тела присутствует; перенесённая матрица `canSave` зелёная в новом доме.

## Task 3: E2E — стабильность высоты, геометрия футера, клиппинг; базлайны

### Classification: standard

### Required Docs

- спека §6, §8
- `docs/tests_workflow.md` (CI vs local, визуальные прогоны только в CI)

### Steps

1. `modal-no-jump.spec.ts` (расширение, US-1): данные с заведомо разной натуральной высотой вкладок («Клиент» с несколькими записями); ассерт — высота контейнера ≈ 0.85 окна и инвариант в пределах 5px при переключении вкладок (геометрия, не класс-строка).
2. `dayview-slot-create.spec.ts` (US-2): ассерты через тестид скролл-тела из Task 2 — bbox кнопки внутри bbox модалки и вне скролл-тела, `elementFromPoint` в центре кнопки не перехвачен перекрывающим слоем, bbox футера в пределах вьюпорта.
3. `activity-details-modal.spec.ts` (US-3): длинная вкладка прокручивается до последнего элемента (клиппинг #262 не возвращается).
4. `visual-regression.spec.ts`: перегенерация базлайнов модалки занятия в закреплённом окружении (viewport 1280×720, Desktop Chrome); при полёте PR #595 параллельно — базлайны обновляет PR, смёрженный вторым (красный CI второго до ребейса ожидаем).

### DoD

E2E для US-1 (`modal-no-jump`), US-2 (`dayview-slot-create`), US-3 (`activity-details-modal`) проходят (RED-GREEN-REFACTOR); визуальные базлайны обновлены.
