# План #595 — Мультивыбор локаций при создании занятия (N событий)

## Goal

Одно нажатие «Создать» в форме создания занятия создаёт N независимых событий — по одному на каждую отмеченную чекбоксом локацию; вместимость при 2+ берётся по умолчанию каждого зала; частичный сбой оставляет форму открытой со снятыми успешными галочками. Спека: `docs/specs/2026-11-12-multi-location-create-595-design.md` (рев.4).

## Architecture

Frontend-only: `CreateActivityTab` (состояние формы, группа чекбоксов вместо комбобокса через режимное ветвление общего `ActivityForm`), `ScheduleDataContext` (промисный `addActivity` + батч-метод `addActivities` с одной инвалидацией кэша на пакет), шов открытия DayView (префилл локации колонки). API и модель не меняются.

## Tech Stack

Next.js (admin), TanStack Query v5 (`mutateAsync`), vitest (юниты), Playwright (e2e admin).

## Task 1: Промисный путь создания в ScheduleDataContext

### Classification: standard

### Required Docs

- `docs/domain-rules/activities.md` — пункт «Create-form multi-location (GH #595)»
- `docs/specs/2026-11-12-multi-location-create-595-design.md` §4.3, §5

### Steps

1. Мутация создания в контексте переводится на `mutateAsync`; авто-инвалидация убирается из хукового `onSuccess` (N параллельных вызовов давали бы N инвалидаций — панель #595, best-practices).
2. `addActivity(input, callbacks?)` — колбэки сохранены (вызываются вручную по resolve/reject), метод **возвращает промис**, после settle — инвалидация семейства `activities` (поведение одиночных потребителей неизменно).
3. Новый метод `addActivities(inputs: AddActivityInput[])`: N параллельных `mutateAsync` → `Promise.allSettled` → ровно одна инвалидация → возвращает массив исходов (id локации → fulfilled/rejected + ошибка). Тосты — не здесь, во вкладке.
4. Вкладка/потребители не полагаются на `isPending` наблюдателя и `mutationKey` (per-call колбэки `mutate` в v5 срабатывают только для последнего вызова — см. спеку §4.3).

### DoD

Юниты: `addActivity` промис резолвится/реджектится, колбэки вызваны, инвалидация 1 раз; `addActivities` на 3 вызовах (2 успеха + 1 отказ) — инвалидация ровно 1 раз, исходы корректны.

## Task 2: Чекбокс-группа локаций и правила вместимости

### Classification: standard

### Required Docs

- `docs/domain-rules/activities.md` — пункт GH #595
- `docs/design-system.md` — форм-паттерны
- спека §4.1–§4.2

### Steps

1. `ActivityForm`: поле локации ветвится по режиму — create → группа чекбоксов, edit → прежний `Combobox` (разметка edit не меняется).
2. Группа: `<fieldset><legend>` «Локация», каждая строка `<label>` + чекбокс; контейнер `data-testid="create-location"`, чекбокс `data-testid="create-location-check"`; состав/порядок списка — из `locations` контекста (как комбобокс).
3. `CreateActivityTab`: состояние `locationIds: string[]`; `canSave` = мастер + услуга + ≥1 локации + дата-время + длительность > 0 + условие вместимости; при рефетче списка отсутствующие id отбрасываются из набора; предзаполненный префилл-ид отмечается по прибытии списка.
4. Вместимость §4.2: ровно 1 (по клику) — автозаполнение `defaultCapacity` с ручной правкой (нет/0 → блок до ввода); 2+ — поле скрыто, подсказка «Вместимость — по умолчанию каждого зала» (`aria-live="polite"`); зал без умолчания (отсутствует или 0) блокирует «Создать», подсказка называет первый такой по порядку чекбоксов.

### DoD

Юниты §8: автозаполнение/ручная правка при 1; скрытие и блок с названием при 2+; `canSave` при 0 локаций; aria-live подсказок.

## Task 3: Мульти-отправка, частичный/полный сбой, тосты

### Classification: standard

### Required Docs

- `docs/domain-rules/activities.md` — пункт GH #595
- спека §4.2–§4.3

### Steps

1. Кнопка «Создать» (inline, testid сохранён; футер — задача #598, тут не трогаем) вызывает `addActivities`: для каждой локации свой `locationId`, вместимость — умолчание локации при 2+ / значение поля при ровно 1.
2. Saving-лок до `allSettled`; поля и чекбоксы `disabled` на время полёта.
3. Полный успех: закрытие, тост N=1 прежний / N≥2 «Создано занятий: N (…)».
4. Частичный (0 < K < N): форма открыта, успешные локации автосняты, поле вместимости при переходе к ровно 1 появляется с умолчанием оставшейся; тост «Создано K из N (…): {сообщение первой по порядку чекбоксов}» (сообщение — через `parseApiError`, сетевой фолбэк включён).
5. Полный сбой: ничего не снимается, разблокировка после лока; тост N≥2 «Создано 0 из N (…)» / N=1 прежний error-тост.

### DoD

Юниты §8: порядок ошибки exercised (2 отказа, завершающиеся в обратном порядке чекбоксов → тост несёт первую по порядку); 0 из 2 (чекбоксы не сняты, тост со счётчиком); автоснятие успешных; тексты тостов N=1/N≥2; disabled в полёте.
