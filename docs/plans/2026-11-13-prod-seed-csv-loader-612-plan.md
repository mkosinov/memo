# План: Предзагрузка прода — вход CSV напрямую (#612)

## Goal
`src/seed/reference.py` читает CSV формата владельца (`--csv <файл>`) вместо YAML-набора; YAML-вход и шаблоны удаляются; слой проверок и записи не меняется (+1 кросс-проверка должностей); в репо — CSV-шаблон-инструкция и переписанный README.

## Architecture
Однофайловый CLI-загрузчик. Шов — `ReferenceData`: новый парсер CSV собирает те же типизированные модели `*_In` (pydantic, `extra="forbid"`), далее существующие `load_reference_data` → `apply_reference_data` без изменений логики. Волна идёт **после мержа #599** (`depends-on`): к старту волны в дереве есть `_apply_specialties` и обработка направлений из его Задачи 7 (сегодня, до мержа #599, их ещё нет — стартовать раньше нельзя) — парсер кормит их по контракту спеки #612 §4.8 («#612 меняет только парсер», спека #599 §6).

## Tech Stack
Python (stdlib `csv` с `strict=True`), pydantic (существующие модели), pytest; `uv` для зависимостей.

## Behavioral Delta
В спеке: `docs/specs/2026-11-13-prod-seed-csv-loader-612-design.md` §3.

## Инварианты волны
- Слой проверок и записи: ни одна существующая гарантия не убавляется; единственное добавление — кросс-проверка `staff.positions` → секция `positions` на этапе `--check`.
- Одна транзакция, rollback при `--dry-run`, идемпотентность — как были.
- Реальный прод-CSV владельца в репо не попадает (`.gitignore`, Задача 5); шаблон — только выдуманные данные.
- Тексты ошибок — на русском, с номером строки CSV (номер начала записи).

## Task 1: CSV-парсер — чтение файла и сборка секций в модели
### Classification: large
### Required Docs: docs/specs/2026-11-13-prod-seed-csv-loader-612-design.md (§4 целиком)

- Чтение: `open(..., encoding="utf-8-sig", newline="")` + `csv.reader(..., strict=True)`; BOM снимается декодером (файл без BOM тоже валиден); отслеживание номера строки **начала записи** (кавычка может переносить строки — `reader.line_num` показывает конец записи, парсер хранит старт каждой записи).
- Конечный автомат секций: маркер-строка (имя в 1-й колонке, остальные пусты; непустой хвост → ошибка с номером строки) → шапка (1-я колонка пуста) → строки данных (1-я колонка пуста) до пустой строки/следующего маркера. Повтор уже встречавшейся секции → ошибка; неизвестная секция → ошибка; порядок секций свободный (секции собираются, валидация позже).
- Валидация шапки поимённо: отсутствие обязательной колонки → ошибка с номером строки; лишняя колонка → предупреждение «секция + колонка» (список выводится в конце прогона); дубль имени колонки → ошибка; хвостовые пустые ячейки шапки игнорируются (в реальном файле есть). Строка данных короче/длиннее шапки → ошибка с номером строки.
- Типизация ячеек (спека §4.4): int-колонки с веткой «пустая → null» только для `int | None` полей (`max_age`, `sort_order`), для остальных пустая → ошибка; bool `True`/`False` без учёта регистра, пустая → ошибка (исключение — `master_is_active` вне собранного блока); `audience` ∈ {kid, adult, all}, пустая/иное → ошибка; строковые пустые → `""`. Парсер передаёт в модели настоящие int/bool — lax-режим pydantic не задействован.
- Групповые правила master_* (спека §4.3): блок собирается при любой непустой `master_*`; частичное заполнение → явная ошибка с номером строки; `master_specialty`/`master_color` в блоке обязательны.
- Мультизначения — список через `;` с обрезкой пробелов (`positions`, `tags`, `master_tags`, `master_specialty`).
- Секции `service_materials`/`tariffs` вкладываются в услуги по `service_title`; секция `specialty` — плоский список значений во 2-й колонке без шапки (спека §4.2/§4.8); секция `tags` опциональна — при отсутствии теги всех сущностей = `[]`.
- Все ошибки входа — `SeedDataError` с номером строки, операторский текст на русском.

- **DoD:** юнит-тесты спеки §6 № 1, 2, 3 зелёные на CSV-фикстурах (сборка/вложения/master-группы; типы и их ошибочные ветки, включая «пустая не-nullable числовая → ошибка, не 0/null»; BOM±, CRLF и LF, многострочная кавычка — ошибка указывает на строку начала записи).

## Task 2: Кросс-валидация + направления (пост-#599 контракт)
### Classification: standard
### Required Docs: docs/specs/2026-11-13-prod-seed-csv-loader-612-design.md (§4.5–§4.8), docs/domain-rules/specialties.md (Сид/предзагрузка)

- `load_reference_data` принимает собранный `ReferenceData` от парсера (вместо чтения каталога YAML); вся существующая кросс-валидация сохраняется: natural keys, дубликаты, `max_age < min_age`, `#RRGGBB`, ссылки service_materials→materials, tariffs→services, теги.
- **Новая кросс-проверка:** `staff.positions` → секция `positions` — на этапе валидации (зеркало текста существующей ошибки слоя записи); `--check` ловит необъявленную должность.
- Направления: секция `specialty` → список названий для `_apply_specialties`; `services.specialty` и `master_specialty` — названия-ссылки, резолв без учёта регистра; неизвестное название → ошибка с именем значения; D5: живой master-блок без направлений → ошибка (контракт #599, парсер-агностик).
- Тексты ошибок: ссылки на «файл YAML» заменяются на «строка N CSV».

- **DoD:** юнит-тесты спеки §6 № 6 и 7 зелёные + ветка «ссылка на несуществующую услугу» теста № 5; существующие ассерты кросс-валидации зелёные на CSV-фикстурах.

## Task 3: CLI `--csv` и режимы прогона
### Classification: small
### Required Docs: docs/specs/2026-11-13-prod-seed-csv-loader-612-design.md (§1, §4.1)

- `--csv <файл>` — обязательный аргумент (вместо `--dir`); `--check`/`--dry-run` как были, взаимоисключающие (совместно → ошибка argparse, exit 2). Коды выхода: 0 успех, 1 ошибка данных/файла, 2 ошибка вызова.
- Несуществующий путь/каталог, файл без единой секции → внятная ошибка, exit 1.
- `--check` — без БД (парсер + кросс-валидация + сводка); `--dry-run` — существующая семантика: прогон в откатываемой транзакции + печать сводки; предупреждения (лишние колонки) печатаются во всех режимах.

- **DoD:** юнит-тесты спеки §6 № 4, 5, 9 зелёные (предупреждение с перечнем «секция + колонка»; все ветки ошибок входа с exit 1; dry-run на ин-memory БД — сводка есть, содержимое БД не изменилось; `--check --dry-run` вместе → exit 2).

## Task 4: Перенос существующих тестов слоя на CSV-фикстуры
### Classification: standard
### Required Docs: docs/specs/2026-11-13-prod-seed-csv-loader-612-design.md (§4.6, §4.7, §6)

- Сюита независимых тестов существующего слоя переезжает с YAML-фикстур на CSV-фикстуры: дубликаты natural keys; `max_age < min_age`; цвет; точная синхронизация связей; одна транзакция + rollback; идемпотентность перезаливки; встроенные должности по фиксированным id. Ассерты поведения — без изменений; ассерты текстов сообщений обновлены под CSV.
- Тест тег-семантики §4.7: пустые тег-колонки → связи перечисленных сущностей очищены, сущности-теги не удалены; заполненные → связи созданы.
