# Релиз v1 memo — 1 декабря 2026

> Создан: 2026-11-07. Источник правды по объёму и срокам релиза. Исполнение — на GH Project доске (milestone «v1 — 2026-12-01»); приоритет/траекторию задаёт владелец в web UI.

## Цель

Первая рабочая версия memo в продакшене 1 декабря 2026: студия ведёт расписание в админке, клиенты видят мастер-классы на вебе и записываются через форму, запись попадает в БД и видна админу.

## Скоуп v1

### Web — минимальная функциональность (слова владельца)

- Клиент видит расписание мастер-классов: описание, фото
- Вместимость клиенту НЕ показываем (решение владельца 2026-11-08); overbooking исключается серверной проверкой `check_activity_capacity` (409 over capacity с откатом) в create/update/patch путях, включая веб-бронирование
- Запись через форму (телефон + OTP; учётка не обязательна). OTP доставляется **SMS** (решение владельца 2026-11-08: #586 транспорт, #587 аккаунт провайдера); Telegram-канал остаётся выключенным
- После успешной записи — подтверждение: «Вы записаны \<когда\> на \<мастер-класс\>. \<N\> гостей. Студия \<локация\>»
- Уведомления через мессенджеры в v1 НЕ работают (Telegram-канал остаётся выключенным)

### Admin

- Всё, что нужно для поддержки веб-функционала; запись клиента видна в интерфейсе (клиент + запись в БД)
- Занесение данных — задача #575 (шаблоны прод-справочников уже на main: #573)

### Фичи, обязательные для v1 (неделя 1)

- #493 — жёсткость публичного создания записи (серверная цена из тарифа, запрет client_id/visitor_id анонимам, лимиты)
- #538 — локализация booking-error по кодам ошибок (сейчас 409 может показать английский текст клиенту)
- #553 — редактирование занятия: честная календарная дата
- #551 — валидация вместимости занятия (capacity ≥ 1)

### Гэпы веба из аудита 2026-11-07 (read-only explore)

- #576 — фото занятия не показываются в расписании: `buildWebSchedule` жёстко ставит `photos: []`, фото из API выбрасываются (`frontend/web/app/lib/mappers/buildSchedule.ts:100`)
- #547 — мёртвые URL фото сида (ph3/ph4/ph5) в гостевой галерее

(#577 «показ вместимости» закрыт как not planned — решение владельца 2026-11-08, см. скоуп выше.)

Аудит подтвердил: бронирование end-to-end работает (анонимно по телефону+OTP или под учёткой), подтверждение содержит дату/время, название, число гостей, локацию — формат совпадает со скоупом. Запись через `POST /api/v1/my/records` создаёт клиента по телефону + Record + Visit-строки, видимые в админке (`GET /api/v1/records/view`).
