# Notificore как SMS-провайдер OTP — API-исследование для #586/#587

Дата: 2026-11-10. Статус: исследование до DESIGN #586, не спека.
Решение владельца (2026-11-10): провайдер — **Notificore** (notificore.ru, ООО «ЕПОЧТА»), обычные SMS с общим именем отправителя; их 2FA-продукт не используется (требует индивидуальное альфа-имя: Мегафон 2541/МТС 3000 ₽/мес — съедает выгоду «от 2 ₽/авторизацию»).

## Экономика (объём ~100 смс/мес)

Прайс «с общим именем отправителя» — без абонентской платы за имя:

| Оператор | ₽/смс |
|---|---|
| МТС | 7,95 |
| Мегафон/Yota | 10,35 |
| Билайн | 10,65 |
| Теле2 | 8,86 |
| Ростелеком | 7,38 |
| Прочие | 6,83 |

Итого ~800–1000 ₽/мес при 100 смс. Минимальных дневных/месячных квот нет («нет установленной минимальной квоты», FAQ). SLA: «задержка доставки более 60 секунд по нашей вине — вернём деньги за простой». Индивидуальные имена для сравнения: Мегафон 2541,66 / МТС 3000 / Билайн 2074 / Теле2 первое имя 0 ₽, далее 2440 ₽/мес — не используются.

## Модерация

- Сообщения проходят модерацию (запрещённые ссылки, подозрительный контент) — «обычно не более 5 минут».
- Модерацию можно **отключить по запросу** менеджеру («согласовать условия деактивации»).
- ⚠️ Открытый вопрос: применяется ли модерация к сервисным/авторизационным SMS через API и на каких условиях её отключить. (Отзывы родственного ePochta SMS жаловались на модерацию до часа — у Notificore в FAQ 5 минут, но подтвердить.)

## API (REST)

- **Версии API**: v1.0 — базовый `https://api.notificore.ru/rest/`, авторизация заголовком `X-API-KEY: live_…|test_…` (подтверждено вызовом баланса 10.11); v2.0 — базовый `http://one-api.notificore.ru/`, Bearer-токен, получаемый через `POST /api/auth/login` с `{"api_key": "live_…"}`. **Для #586 берём v1.0.** Ключ — вкладка «SMPP/API Password» раздела «Интеграции и API» ЛК (там же лежит SMPP-пароль — не перепутать; тестовый ключ начинается с `test_`).
- Баланс (пробник): `GET https://api.notificore.ru/rest/common/balance` → `{"error":0,"amount":"-1.08","currency":"RUB","limit":"50"}` — **валюта счёта RUB** (EUR в примерах доков — дефолт), постоплатный лимит 50 ₽.
- Отправка (подтверждено, POST работает): `POST https://api.notificore.ru/rest/sms/create`. ⚠️ Статья «Отправка» в примере даёт путь `/v1.0/sms/create` и намекает на Bearer — это смешение версий в доках, на практике v1.0 = `/rest/sms/create` + `X-API-KEY`.
- Без `originator` API отказывает: `{"error":25,"errorDescription":"Invalid originator"}` — общего имени по умолчанию нет; значение для общего имени сервиса — открытый вопрос (кандидат `"Notificore"`, проверка идёт).
- Запрос (JSON), одиночное сообщение:

```json
{
  "destination": "phone",
  "originator": "<имя отправителя>",
  "body": "Код для входа в MEMO: 123456",
  "msisdn": "79001234567",
  "reference": "<наш id попытки OTP>",
  "validity": "300",
  "callback_url": "<наш webhook URL>"
}
```

| Поле | Обяз. | Смысл |
|---|---|---|
| destination | да | `"phone"` для одиночного, `"phones"` для массива |
| originator | — | имя отправителя: телефон или буквенно-цифровое ≤11 символов; ⚠️ как передать ОБЩЕЕ имя сервиса — не документировано (вопрос поддержке) |
| body | да | текст сообщения |
| msisdn | да | телефон с кодом страны без `+`: `79001234567` |
| reference | да | клиентский идентификатор сообщения — используется для idempotency и запроса статуса |
| validity | — | срок жизни сообщения, сек |
| tariff | — | код тарифа |
| callback_url | — | вебхук статуса по этому сообщению |
| phones | (bulk) | массив получателей, максимум 50 номеров на запрос |

- Ответ: `{ "result": { "error": 0, "errorDescription": "No errors", "reference": "...", "id": "213", "price": 0.23, "currency": "EUR" } }` — ⚠️ в примере `currency: EUR`; в каком виде будет RUB-счёт, уточнить.
- Статус (pull): `GET /rest/sms/{id}` или `GET /rest/sms/reference/{reference}`; также по `task_id` для массовых.
- Статусы: `scheduled, sent, delivered, expired, undeliverable, rejected, unknown`. Финальные: `delivered / expired / undeliverable / rejected`; время последнего статуса — `time_dr`.
- Вебхук: задаётся полем `callback_url` в запросе (и/или глобально в ЛК — неясно); формат payload не документирован — посмотреть в ЛК после регистрации или спросить поддержку.

## Текст сообщения

- Стандарт GSM: сегмент = 70 символов кириллицей (UCS-2) или 160 латиницей (GSM-7); длиннее — нарезается на сегменты и тарифицируется по сегментам. Notificore-специфику нарезки в открытых доках не нашли — подтверждается у поддержки, но для OTP некритично: шаблон ниже укладывается в 1 сегмент.
- Целевой шаблон для спеки #586: **«Код для входа в MEMO: {код}»** (~25 символов, 1 сегмент). Имя отправителя — общее (чужое), поэтому бренд несёт текст: требование к шаблону «называть сервис» — из решения владельца об общем имени (2026-11-10).
- Код генерирует наш бэкенд (#586, `OtpTransport`), провайдер только доставляет текст; длину/алфавит кода выбираем сами.

## Вводные для спеки #586 (собрано)

1. Транспорт — синхронная отправка: POST create → получаем `id`+`reference`; статус доставки — асинхронно через `callback_url` (или polling по `reference` как запасной путь).
2. `reference` обязателен → использовать id попытки OTP (идемпотентность и отладка без преобразований).
3. Телефон в API — `7XXXXXXXXXX`; конвертация из входной формы — на стороне транспорта.
4. Fail-closed сохраняется: нет конфига (ключ/URL/имя) → 503 `NOTIFY_TRANSPORT_UNAVAILABLE`, вне git — `.env`.
5. Маскирование кода в логах (§4.2 #499) остаётся в силе.
6. Смена провайдера = адаптер под `OtpTransport` + конфиг — интерфейс не завязывать на Notificore-специфику (originator/validity → конфиг).

- **Тестовый ключ (`test_`) — отправка прошла**: `originator: "ArtStudio"` (имя из заявки, в одобрении) принят в тестовом режиме; ответ `{"error":0,"id":"38371830","price":10.19824,"currency":"RUB"}`. Текст «Код для входа 123456» (20 симв., 1 сегмент) → 10,20 ₽ — совпадает с прайсом общего имени (Мегафон/Билайн 10,35/10,65). Сегментная тарификация по факту подтверждена.

Повторить после: (а) пополнения баланса (пополнено 50 ₽ 10.11), (б) одобрения ArtStudio; если не пройдёт — спросить поддержку про значение общего имени для боевого канала.
