# Исследование API sms.ru: авторизация звонком (callcheck)

- Дата: 2026-11-11. Для: #593 (вход по звонку — метод авторизации наряду с SMS-кодом). Обновлено 11.11: полная статья ЛК «Авторизовать пользователя по звонку с его номера» — подтверждения ниже (формат телефона, вебхук, `callto:` в `call_phone_html`); цена из ЛК (см. §Цена).
- Метод: только документация и лендинг провайдера — живых вызовов НЕ было (аккаунта нет; регистрация — ручной шаг владельца, как в #587). Источник: `https://sms.ru/api`, `https://sms.ru/api/call`, `https://sms.ru/call`, `https://sms.ru/price`.

## Модель (важное отличие от flash call)

Это НЕ «сервис звонит клиенту, код = последние цифры входящего номера». У sms.ru обратная модель: **клиент сам звонит** на выданный сервисом номер; сервис опознаёт номер звонившего (АОН) и подтверждает совпадение с заявленным телефоном. Кода и ввода кода нет вообще; подтверждение = факт звонка с заявленного номера.

- Звонок сбрасывается — бесплатен для клиента, «даже для тех, кто звонит из-за рубежа» (лендинг).
- Окно проверки: 5 минут.
- Для роуминга: необязательный параметр `ip` (реальный IP клиента) — по нему сервис подставляет обычный номер вместо 8-800. «Никаких ограничений или блокировок по нему не применяется» (доки).

## Эндпоинты

### Создание проверки — `POST https://sms.ru/callcheck/add`

Параметры: `api_id` (ключ; либо `login`+`password` по HTTPS), `phone` (проверяемый номер — **формат подтверждён статьёй ЛК: `79996531803`, `7XXXXXXXXXX` без плюса**), `ip` (необяз., см. выше), `json=1` (рекомендуется). `check_id` в ответе — строка вида `201737-542`. `call_phone_html` в примере провайдера использует нестандартный `callto:` — #593 строит собственную `tel:`-ссылку (RFC 3966).

Ответ (цитата из доков):

```json
{
  "status": "OK",
  "status_code": 100,
  "check_id": "201737-542",
  "call_phone": "78005008275",
  "call_phone_pretty": "+7 (800) 500-8275"
}
```

Плюс `call_phone_html` — готовая `callto:`-ссылка для одной кнопки на мобильном.

### Статус проверки — `POST https://sms.ru/callcheck/status`

Параметры: `api_id`, `check_id`, `json=1`. Ответ (цитата):

```json
{
  "status": "OK",
  "status_code": 100,
  "check_status": "401",
  "check_status_text": "Авторизация по звонку: номер подтвержден"
}
```

### Коды `check_status`

| Код | Смысл |
|---|---|
| 100 | проверка принята, ждём звонка |
| 202 | неверный формат телефона |
| 400 | звонка ещё не было (не подтверждён) |
| 401 | номер подтверждён (звонок с заявленного номера зафиксирован) |
| 402 | время истекло / неверный `check_id` |

Несогласованность в доках: PHP-пример читает поле `call_number`, а JSON-спека даёт `call_phone` — клиент должен терпеть оба имени (аналог нестабильных доков Notificore, риск №5 спеки #586).

### Вебхуки

Статья ЛК подтверждает: вебхук для статусов проверок существует, бесплатен и «настоятельно рекомендуется» провайдером. Формат оповещения (payload) и способ регистрации в статье callcheck **не описаны** — отдельный общий API `callback_add/del/get`. Решение #593 v1: НЕ строим — фронт всё равно опрашивает наш бекенд, вебхук лишь переносил бы исходящий цикл на приёмный эндпоинт с аутентификацией источника; при появлении документированного формата — возможен второй итерацией.

## Цена и аккаунт

- **Подтверждено из личного кабинета sms.ru (2026-11-11, владелец): сейчас система бесплатна; планируется 0,8 ₽ за каждую успешную авторизацию.** Успешная = клиент позвонил на выданный номер в течение 5 минут с момента подачи номера; неуспешные (без звонка) не тарифицируются. Решающая ячейка — пессимистично 0,8 ₽ за успешную.
- На сайте цена не публикуется (лендинг и тарифы молчат; на `/price` только SMS по прямым каналам операторов «от 8,36 ₽» с абонплатой за имя). Внешний обзор называл 0,40 ₽ (РФ) / 1 ₽ (мир) — источник ненадёжен (ошибся в механизме).
- Не проверено живым вызовом (закрыть при первой живой проверке, Task 1 имплементации #593): квоты аккаунта на `callcheck/status` (объём у нас ограничен окном и дебаунсом, ~100 обращений на проверку), лимиты нового аккаунта. Формат телефона в запросе подтверждён статьёй ЛК (`7…` без плюса); формат номера **пользователю** — строго `+7…` (см. §Факты провайдера для UI).

## Факты провайдера для UI (2026-11-11)

- **Номер клиенту — строго с «+»**: передавать `+7499…` или ссылкой `<a href="tel:+7499…">`. Номер без плюса (`7499…`) часть операторов не пропускает («неправильно набран номер»), особенно звонящих из-за рубежа. Вариант с ведущей `8` (`8499…`) подходит только звонящим из РФ.
- **Звонок бесплатен конечному пользователю** — в роуминге и с зарубежного номера тоже: голосовое сообщение об успешности передаётся как мелодия гудка, затем звонок сбрасывается; звонок не считается установленным (голос не получают) и операторами не тарифицируется.

## Ограничения модели

- Подтверждение фиксирует только факт звонка с заявленного номера: скрытый АОН — проверка не подтвердится; городской/корпоративный номер, с которого не набрать — не подходит.
- Один `check_id` — одно окно 5 минут; повторная проверка = новый `callcheck/add` (новая строка расходов).
