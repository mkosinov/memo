# Спека: создание занятия кликом по слоту + пустая неделя с сеткой (#258+#259)

- Дата: 2026-09-14. Ревизия 2 — правки по панели G1b (5 ревьюеров: 4× PASS WITH FINDINGS, consistency FAIL; все находки внесены, решения не менялись). G1a утверждён юзером 14.09.
- Issues: #258 (клик по свободному слоту не открывает создание — регрессия), #259 (неделя без занятий показывает «Нет занятий» вместо сетки — создать событие нельзя). Один трек, один PR, `Closes #258, Closes #259`.
- Роль трека: вторая (параллельная) IMPL-дорожка — не зависит от #262/#263/#260. Чисто фронтовый: бэкенд не трогается ни одной строкой.

## 0. Решения (G1a утверждён юзером 14.09; D8–D10 — по панели и правке юзера 14.09)

- **D1. Клик по свободному слоту открывает большую модалку `ActivityDetailsModal` в новом режиме «создание занятия»** — юзер-решение против «лёгкой отдельной модалки». Режим создаёт именно занятие (activity), а не запись (record): существующая вкладка «новая бронь» создаёт запись клиента на существующее занятие (`NewBookingTab` → `POST /api/v1/records`) и для создания занятия не реюзнится.
- **D2. Пустая неделя/день рисует сетку всегда** + подсказка обычным элементом в потоке. Ветка-заглушка «Нет занятий» вместо сетки удаляется как класс.
- **D3. Вид дня унифицируется на то же поведение** — см. §1: у дня НЕТ ветки-заглушки, там сетка уже рендерится, а текст пустоты выдаёт заголовок колонки; унификация = та же подсказка в потоке, сетка остаётся.
- **D4. Маскирующий e2e чинится**: `admin-clicks-empty-slot.spec.ts` сегодня проглатывает свой главный ассерт через `.catch(() => {})` — убирается, тест становится настоящим регрессионным на S1.
- **D5. Юнит-тесты, закреплявшие заглушку пустой недели, переписываются** под новое поведение.
- **D6. Предзаполнение день/время из слота возвращается**: сегодня `openCreateModal` координаты слота не сохраняет (WeekView-версия не принимает их вовсе, DayView-версия принимает и отбрасывает).
- **D7. Z-индексы не трогаем, новых `z-[N]` не добавляем** — параллельный трек #260 работает в тех же файлах (§4).
- **D8. Никакой конфликт-валидации «слот занят» не существует и не вводится** — юзер-домен 14.09: несколько занятий в одном слоте (у одного мастера/локации) разрешены осознанно, по согласованию с мастером. Правило записано в `docs/domain-rules/activities.md` (Invariants).
- **D9. Сценарий S5 (различие текстов подсказки) проверяется юнит-тестами**, e2e остаются за S1–S4 (принято по рекомендации панели simplicity; отклонение от изначальной раскладки G1a, озвучено юзеру).
- **D10. Клавиатурная активация слотов — вне трека** (слоты и сегодня не фокусируются; общий a11y-долг сетки, не этих багов).

## 1. Фон и диагноз (факты живого кода, scout 14.09, якоря сверены панелью consistency)

**Регрессия #258 старше, чем казалось: сломано коммитом `d202d6a5` от 2026-06-03** (замена `ActivityModal` на табbed-`ActivityDetailsModal`). Старая `ActivityModal` умела создание с нуля (`initialActivity=null`, поля + `defaultDay`/`defaultStartTime`, сохранение через родителя). Новая модалка везде требует существующее занятие, а клик по слоту остался на старом контракте:

- `openCreateModal` — `WeekView.tsx:44-48`: ставит `modalActivity=null`, `modalMode='edit'`, `modalOpen=true`; координаты слота НЕ принимает вовсе. В `DayView.tsx:85-89` функция принимает `(_dayIndex, _startMinutes)` и отбрасывает их.
- Гейт рендера — `WeekView.tsx:329-336`: `{modalActivity && (<ActivityDetailsModal … activity={modalActivity} …/>)}` — при `null` модалка не монтируется никогда. Тот же мёртвый гейт в `DayView` (его гейт ~`:550`).
- Пропс `activity: ScheduleAdminDTO` обязателен и не-nullable (`ActivityDetailsModal.tsx:21-25`). Безусловные разыменования до гварда `isOpen`: `useRecordMutations(activity.id, …)` (`:39`), `services.find(s => s.id === activity.serviceId)` (`:43`), `useActivityRecords(activity.id, isOpen)` (`:49`), `deleteActivity(activity.id)` (`:103`), `activity.date + 'T' + activity.time` (`:187-189`), `title={activity.serviceTitle || 'Мероприятие'}` (`:202`). То есть починка «просто снять гейт» невозможна — режиму создания нужны гварды этих мест (механика — §2.1).
- Клик по слоту: `DroppableSlot.handleClick` — `DayColumn.tsx:142-150`, при неактивном штампе зовёт `onOpenModal(dayIndex, slotMinutes)`; гардовое условие `e.target === e.currentTarget`; свободный слот имеет `data-testid="empty-slot"` (`DayColumn.tsx:155`). Проводка: `DayColumn.tsx:442` → `WeekView.tsx:275` → `openCreateModal`.

**Пустая неделя (#259):** `WeekView.tsx:201-209` — при `activities.length === 0` early return с центрированным `<span>` («Нет занятий по выбранным фильтрам» при активных фильтрах, иначе «Нет занятий на эту неделю»). В этой ветке пропускается ВСЁ: заголовки колонок, ось времени, `DayColumn`/`DroppableSlot`, `DndContext` — значит недоступны и клик-создание, и штамп (`handleCreateActivity`, `WeekView.tsx:100-122`). Загрузка и ошибка — отдельные ветки (`:180-191`, `:193-199`), их не трогаем.

**Вид дня — иначе, чем в неделе (уточнение рев.2):** у `DayView` НЕТ раннего возврата-заглушки: сетка рендерится всегда (loading/error `:325-344`, `DndContext` с `:346`), а текст «Нет занятий на этот день» выдаёт заголовок колонки (`ScheduleColumnHeader`, ~`:434-438`, при пустых колонках). Починка дня = не «удалить ветку», а заменить заголовочную надпись единой подсказкой (§2.2) — сетка и слоты там уже есть.

**Пути создания сегодня:** (1) штамп — услуга выбрана в списке, клик по слоту, `addActivity` из `useScheduleData()` (`ScheduleDataContext.tsx:200-223`): payload `master_id, service_id, location_id, start (floating local ISO из dayIndex+текущая неделя), duration, capacity, is_private, comment, record_info: null` → `POST /api/v1/activities` (`endpoints.ts:341-347`); префиллы штампа: `duration = service.durationMinutes`, `capacity = первой локации defaultCapacity ?? 0`, `isPrivate: false` (`WeekView.tsx:102-116`). (2) «+» на карточке занятия → `mode='quickAdd'` (вкладка новой записи) — не трогаем. (3) Кнопки «Создать» в тулбаре нет и не было.

**Тесты сегодня:** юнит-тесты закрепляют заглушку пустой недели (`__tests__/page.test.tsx:57-65`, `__tests__/WeekView.test.tsx:93-99`) и штамповый путь клика (`__tests__/DayColumn.test.tsx:247-299`). E2E `admin-clicks-empty-slot.spec.ts` кликает `[data-testid="empty-slot"]` и ассертит `role="dialog"`, но завёрнуто в `.catch(() => {})` — именно поэтому #258 не ловился. Инфраструктура: `workers: 1`, per-test seed-reset (#252), логин-сессия в globalSetup; хелпер навигации недели ждёт появления карточек — на пустой неделе нужен ожидание элементов сетки (§6). Пустую неделю e2e получает навигацией на далёкую будущую неделю от сида.

## 2. Целевое поведение

### 2.1 Клик по свободному слоту (неделя и день — одинаково)

1. Клик по пустому слоту открывает `ActivityDetailsModal` в новом режиме `mode='create'` при `activity=null`. Гейт рендера перестаёт требовать `modalActivity` — модалка монтируется по `modalOpen`, а режим определяет содержимое.
2. **Механика режима (по панели, обязательна):** пропсы меняются — `activity` становится nullable, `mode` пополняется `'create'` (сегодня `'edit' | 'quickAdd'`). Хуки вызывать по условию нельзя (Rules of Hooks) — режимы выделяются в подкомпоненты: родитель держит только состояние открытия/режима/координат слота; record-хуки (`useRecordMutations`, `useActivityRecords`, `services.find` по `serviceId`, `deleteActivity`) живут в подкомпоненте редактирования и в режиме создания гарантированно не выполняются. Все шесть точек падения (§1) закрыты конструктивно, а не точечными `if`.
3. **Панель вкладок и футер в режиме создания:** `TabNav` рисует единственную вкладку — форму «Создание занятия»; клиентских вкладок и кнопки «+ Запись» нет; футер с удалением скрыт, `deleteActivity` не регистрируется.
4. **Поля формы** (состав старой `ActivityModal` минус ручная «занятость», которая теперь определяется записями): мастер (select), услуга (select), локация (select), день недели (select, предзаполнен из слота), время начала (предзаполнено из слота, редактируемое), длительность, вместимость, чекбокс «приватное». Заголовок модалки в режиме создания — «Новое занятие», привязанный к видимому заголовку через `aria-labelledby` (не фолбэк «Мероприятие»).
5. **Правила предзаполнения:** день/время — из слота (редактируемые). До выбора мастера/услуги/локации длительность и вместимость пустые; при выборе услуги длительность = `service.durationMinutes`, при выборе локации вместимость = `defaultCapacity ?? 0`; смена услуги/локации обновляет значения. Ровно как у штампа (`WeekView.tsx:102-116`), чтобы оба пути вели себя одинаково.
6. **Валидация:** кнопка «Создать» активна только при выбранных мастере, услуге и локации (и заполненных длительности/времени).
7. **Сохранение и его семантика:** `addActivity({ dayIndex, startMinutes, masterId, serviceId, locationId, durationMinutes, capacity, isPrivate })` — тот же путь, что у штампа, тот же `POST /api/v1/activities`. На время запроса кнопка «Создать» задизейблена (анти-даблклик) и закрытие модалки заблокировано (крестик/Esc/клик мимо не срабатывают, гонки «закрыл и создалось» нет). Успех → тост-поведение ровно как у штампа (один тост, владелец тот же — без задвоения), модалка закрывается, карточка появляется в сетке; к деталям не переходим. Ошибка сервера → тост уровня «ошибка» общего стека (UIContext), форма остаётся открытой с введённым, дубль не создаётся. Конфликт-ошибки «слот занят» НЕ существует (D8).
8. Закрытие без запроса в полёте (крестик/Esc/клик мимо) — просто закрытие, без подтверждений; сознательное решение, не менять.

### 2.2 Пустая неделя и пустой день

- Ветка-заглушка недели удаляется; сетка (заголовки колонок, ось времени, `DayColumn` со слотами, `DndContext`) рендерится всегда.
- **Подсказка** — ненавязчивый баннер над областью сетки в обычном потоке (без позиционирования с z), с `role="status"` и `aria-live="polite"`. Тексты сохраняются оба: «Нет занятий на эту неделю» / «Нет занятий по выбранным фильтрам». «Активные фильтры» = выбранные фильтры мастера/локации в view-состоянии расписания (тот же источник, что использует `hasFilters` сегодня); единая логика для обоих видов.
- В виде дня надпись заголовка колонки «Нет занятий на этот день» заменяется той же подсказкой; сетка и слоты дня, которые и так рендерятся, остаются.
- На пустой неделе работают и клик-создание (§2.1), и штамп — это тот же код, что на заполненной; отдельных ветвей для пустой недели в поведении создания нет.

### 2.3 Что остаётся неизменным (регрессионные риски, проверяются тестами)

- Вход «+» на карточке занятия (quickAdd/новая запись) — поведение и вкладки без изменений; это главный сосед по компоненту.
- Штамп-режим на заполненной неделе — без изменений. Пути штампа и клика независимы: взаимных блокировок нет, выбор штампа сохраняется после создания через модалку.
- Существующие вкладки модалки для существующего занятия (настройки, записи, новая запись) — без изменений.
- Ветки loading/error расписания — без изменений. Линия «сейчас» на пустой текущей неделе работает без правок (проверить при IMPL).
- Бэкдор-события `__memo-*` для e2e — без изменений и без расширения.

## 3. Границы: сознательно НЕ делаем

- Кнопку «Создать занятие» в тулбаре — создание живёт в сетке (клик по слоту, штамп), как и до регрессии.
- Отдельную лёгкую модалку создания — отклонено юзером на G1a (D1).
- Конфликт-валидацию пересечений занятий — домен разрешает параллельные занятия (D8).
- Клавиатурную активацию слотов — общий a11y-долг сетки, не этих багов (D10).
- Переход к деталям созданного занятия сразу после сохранения — модалка просто закрывается.
- Любые изменения бэкенда, схем, API.
- Любые изменения z-индексов и z-токенов (зона #260).
- Оптимистичное создание; черновики формы; подтверждение при закрытии с введённым.
- Бэкдор-события для e2e — новые тесты кликают настоящие слоты через `data-testid`.

## 5. User Scenarios (каждая → тест)

- **S1. Создание кликом по слоту на обычной неделе.** Админ кликает пустой слот → открывается модалка «Новое занятие» с предзаполненными днём и временем → выбирает мастера/услугу/локацию → «Создать» → модалка закрылась, карточка занятия в сетке. → e2e `admin-clicks-empty-slot.spec.ts` (чинится: без `.catch`, полный ассерт диалога и карточки).
- **S2. Пустая неделя: сетка + создание.** Админ открывает неделю без занятий → видит сетку (7 колонок, ось времени) и подсказку «Нет занятий на эту неделю» → кликает слот → создаёт занятие → карточка появилась, подсказка исчезла. → e2e `schedule-empty-week.spec.ts` (новый).
- **S3. Вид дня: клик по слоту.** То же, что S1, в виде дня — создание работает одинаково, подсказка унифицирована. → e2e (спек вида дня).
- **S4. Штамп на пустой неделе.** Услуга выбрана в штампе → клик по слоту пустой недели создаёт занятие без модалки. → секция e2e `schedule-empty-week.spec.ts`.
- **S5. Подсказка различает причину пустоты.** Без фильтров — «Нет занятий на эту неделю»; с активными фильтрами, скрывающими всё, — «Нет занятий по выбранным фильтрам». → юнит-тесты (D9).
