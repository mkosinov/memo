## 1. Проблема и поправка предпосылки issue

Issue #94 просит: при удалении показывается undo-тост, и хочется видеть, сколько времени осталось до автозавершения — анимированное SVG-кольцо (`stroke-dashoffset`, убывает за 5 секунд) и цифры обратного отсчёта.

Предпосылка issue устарела (проверено скаутом 16.09): тоста «Запись удалена через 5 секунд» в системе нет и не было. Фактическое состояние:

- **Undo-тост уже существует** для визитов и оплат: «Удалено. Отменить», окно 5 секунд, механизм `PendingActionsContext` (`deleteVisitDeferred`/`deletePaymentDeferred`, `frontend/admin/hooks/useRecordMutations.ts:409-482`).
- **Удаление записи (records) — мгновенное**: `deleteMutation` + тост «Запись удалена» после успеха; 409-конфликт зависимостей открывает DeleteDialog (`RecordsTable.tsx:37-51`, `useDeleteRecord.ts:54-67`); бэкенд — жёсткое удаление с dry-run (`backend/src/api/v1/records.py:153-203`).

Принятая трактовка задачи (решение юзера 16.09): **#94 — чистый UI-полиш** — кольцо + цифры на существующих undo-тостах; перевод записей на отложенное удаление выделен в #285 и в этой спеке не решается.

## 3. Решения

**D1 — скоуп: кольцо рендерится по наличию `countdownMs`, а не по наличию undo.** Кольцо с цифрой появляется тогда и только тогда, когда у тоста передано `countdownMs`; его проставляет только `enqueuePendingAction` (D3). Из трёх производителей undo-тостов кольцо получают визиты (`useRecordMutations.ts:425`) и оплаты (`:461`); удаление занятия (`ActivityCard.tsx:78`) остаётся без кольца — его undo работает как сегодня (синхронное удаление + «пересоздание»). Обычные тосты (включая «Сохраняем…» #261 и «Данные обновлены» #239) не меняются. Флоу удаления записей не трогается — #285.

**D2 — размещение: слева от текста.** Для undo-тоста с кольцом слева от сообщения появляется блок кольца с цифрой внутри (сегодня слева иконки нет — блок добавляется); кнопка «Отменить» остаётся справа как есть; тексты не меняются («Удалено. Отменить»). Размеры — как у существующего спиннера (≈16 px, штрих ≈1.5-2 px); дорожка кольца — нейтральный токен рамки, прогресс — `currentColor`; читаемость цифр в light/dark входит в DoD.

**D3 — единый источник окна: `countdownMs` из отложенного действия.** В `Toast` (`UIContext.tsx:7-12`) добавляется необязательное поле `countdownMs?: number`; сигнатура расширяется 4-м опциональным параметром — `showToast(message, kindOrUndo?, undo?, countdownMs?)`. Единственный производитель — `enqueuePendingAction` (`PendingActionsContext.tsx:54-61`), передаёт свой `delayMs`. Таймер автоскрытия undo-тоста (`UIContext.tsx:89`) при переданном `countdownMs` берёт длительность из него: `undoFn ? (countdownMs ?? 5000) : 4500`. Тем самым окно отсчёта, время жизни тоста и момент commit сходятся в один источник — `delayMs`. Это **не** per-call duration для всех тостов (решение #261 D1 не пересматривается): параметр внутренний, читается только у undo-тостов (у не-undo игнорируется), сигнатура остальных 40+ вызовов не меняется; undo-тост без `countdownMs` ведёт себя как раньше (5000 мс). Моки `showToast` в `PendingActionsContext.test.tsx` обновляются осознанно (новая арность).

**D4 — кольцо и цифры от одного таймера.** Новый компонент `frontend/admin/app/components/toast/CountdownRing.tsx`: SVG-круг (геометрия как у спиннера `ToastContainer.tsx:34-46`; `stroke-dasharray` = длина окружности) и цифры управляются **одним** секундным интервалом: тик сдвигает и цифру (`ceil(остаток/1000)`, минимум 1), и шаг кольца (`stroke-dashoffset` пропорционально прошедшей доле окна). CSS-кефреймы и inline `animationDuration` не нужны — исключён дрейф двух часов внутри кольца; на ≈16 px ступенчатое движение неотличимо от плавного. Очистка интервала при размонтировании. По достижении 0 commit уже сработал штатно — тост исчезает (существующее поведение); отдельной «финишной» анимации нет.

**D5 — a11y: кольцо и цифры молчат.** Блок кольца помечен `aria-hidden="true"`: живой регион тоста уже озвучивает появление с текстом («Удалено. Отменить»); ежесекундная озвучка цифр — спам. Семантику прогрессбара (`role="progressbar"`, `aria-busy`) не добавляем — YAGNI.

**D6 — e2e без цифр и таймингов.** e2e проверяет появление/исчезновение undo-тоста и восстановление/удаление строки; точность отсчёта покрывается unit-тестами на фейковых таймерах (решение юзера 16.09).

**D7 — тесты.**
- Unit: `PendingActionsContext.test.tsx` — `countdownMs = delayMs` доходит до тоста; новый `CountdownRing.test.tsx` — фейковые таймеры: цифры убывают 5→4→…→1, минимум 1, шаг кольца синхронен цифре, cleanup интервала, `aria-hidden`; `ToastContainer.test.tsx` — пара «кольцо есть при `countdownMs` / нет без него» рядом с существующими тестами «Отменить» (`:47-54`); `UIContext` — undo-тост без `countdownMs` живёт 5000 мс, обычные виды не тронуты (ассерт 4500 в `UIContext.test.tsx` остаётся валидным).
- E2E: новый отдельный файл не заводится. S1–S3 и S6 покрывают существующие `unified-rows.spec.ts` / `unify-caches.spec.ts` (см. §6); добавляется один тест S4 (повторное удаление после отмены) в `unified-rows.spec.ts` — с ожиданием deferred DELETE-ответа перед reload-ассертами (паттерн уже есть в этом файле); S5 — существующий `activity-details-modal.spec.ts:154`, без правок.

**D8 — документация.** `docs/design-system.md`: секция Toast (`:458-463`) дополняется кольцом отсчёта (размер, токены, поведение «Отменить» закрывает тост, «×» скрывает без отмены), в таблицу motion (`:269`) — строка «Undo ring — ступенчатое заполнение, шаг 1 с, синхронен цифрам». `prefers-reduced-motion` — без специальной обработки: кольцо декоративно (`aria-hidden`), смысл несёт текст и цифры; в дизайн-системе пока нет ни одного media-правила (решение 16.09, зафиксировано, чтобы позже не «чинили» как дыру).

**D9 — «×» остаётся на undo-тостах; dismiss ≠ cancel (решение юзера 16.09).** Кнопку «×» у undo-тостов не убираем: тост может мешать, и пользователь имеет право его скрыть. Закрытие скрывает только тост — отложенное действие продолжается и commit выполняется по истечении окна (стандартная семантика снекбаров: dismiss не отменяет действие). Ошибка commit показывает существующий красный тост. Это существующее поведение, фиксируем явно, чтобы будущий аудит не счёл его багом.

## 4. Детали поведения и края

- **Быстрый повтор того же id (удалил → отменил → удалил снова):** каждое enqueue создаёт новый тост (`showToast` всегда новый id) — новое кольцо начинает отсчёт заново (S4). Существующая особенность «старый тост живёт до своего таймера» не меняется.
- **Два таймера на undo-тост:** после D3 длительность автоскрытия = `delayMs`, т.е. тост, кольцо и commit живут ровно одно окно; существующее удвоение часов (UIContext 5000 / PendingActions delayMs) для undo-тостов устраняется. Двух часов внутри кольца нет (D4).
- **Закрытие по «×»:** тост скрыт, commit выполняется молча по истечении окна (D9); undo после закрытия «×» невозможен — это осознанный выбор.
- **Тема:** дорожка — токен рамки, прогресс — `currentColor`; визуальная проверка в light/dark входит в DoD (без новых visual-базлайнов — тосты маскируются).
- **Много undo-тостов одновременно:** каждое отложенное действие — свой тост со своим кольцом; лимит стека 5 (`ToastContainer.tsx:11-12`) работает как раньше.

## 5. Что сознательно НЕ строим

- Перевод удаления записей на отложенную схему — выделено в #285 (там же решаются dry-run/409 в commit и `resolveDelete`).
- Общий per-call `duration` для всех тостов — решение #261 D1 в силе; `countdownMs` — внутренняя метадата undo-окна (D3).
- Кольцо на тостах без отложенного действия, включая undo-тост занятия (`ActivityCard.tsx:78`) — гейт по `countdownMs` (D1).
- Рестарт отсчёта на живом тосте по клику «Отменить» — undo закрывает тост; «сбрасывает таймер» в issue трактовано как «снимает отсчёт» (решение 16.09).
- Aria-семантика прогресса и озвучка цифр — YAGNI (D5).
- Изменения текстов тостов, бэкенда и таймингов существующих тостов.

## 6. User Scenarios (каждая → e2e)

- **S1. Отложенное удаление визита.** Админ удаляет визит: строка исчезает, появляется undo-тост «Удалено. Отменить» с кольцом отсчёта; кольцо убывает, цифра тикает. (e2e: существующий `unified-rows.spec.ts:773-812` — появление тоста, optimistic-удаление, истечение → deferred DELETE → строка остаётся удалённой)
- **S2. Отмена в окне отсчёта.** Админ нажимает «Отменить» до истечения: тост исчезает, строка возвращается; после перезагрузки визит на месте. (e2e: существующий `unify-caches.spec.ts:274-279`)
- **S3. Истечение окна.** Окно истекает без клика: тост исчезает; deferred DELETE уходит; после перезагрузки визита нет. (e2e: входит в существующий `unified-rows.spec.ts:773-812`)
- **S4. Повторное удаление после отмены.** Админ удаляет, отменяет, удаляет снова: новый undo-тост, отсчёт заново. (e2e: новый тест в `unified-rows.spec.ts`; ждать deferred DELETE перед reload-ассертом)
- **S5. Удаление записи — как было.** Админ удаляет запись (records): мгновенный тост «Запись удалена» без кольца и «Отменить»; при 409 — DeleteDialog. (e2e: существующий `activity-details-modal.spec.ts:154`, остаётся зелёным без правок)
- **S6. Отложенное удаление оплаты.** Админ удаляет платёж: тот же undo-тост с кольцом; «Отменить» возвращает. (e2e: существующий `unified-rows.spec.ts:996-1030`, `unify-caches.spec.ts:274-279`)

- Тосты без undo и флоу записей не изменились; существующие e2e зелёные.

## 10. Протокол панели G1b (rev1 → rev2)

Пять ревьюеров: полнота (PASSED_WITH_CONCERNS), консистентность (PASSED_WITH_CONCERNS), феасабилити (PASSED_WITH_CONCERNS), простота (PASSED_WITH_CONCERNS), best-practices (FAILED — веб-исследование недоступно, штатный отказ; исключён из вердикта).

- **Приняты:** пин механизма передачи окна (4-й опциональный параметр `showToast` + поле `Toast`; противоречия с #261 D1 нет — D3); гейт кольца по `countdownMs` — панель нашла третий undo-производитель `ActivityCard.tsx:78`, которому наивный гейт по `undo` нарисовал бы лживое кольцо (D1); «×» остаётся у undo-тостов, семантика dismiss ≠ cancel зафиксирована (D9, решение юзера; файндинг полноты о «ловушке ×» закрыт документированием, не удалением кнопки); новый e2e-файл срезан — S1–S3/S5/S6 уже покрыты `unified-rows`/`unify-caches`/`activity-details-modal`, добавлен только тест S4 (простота; минор феасабилити про шарды снялся вместе с файлом); один таймер кольца вместо CSS-анимации + интервала (простота); ToastContainer-пара «кольцо есть/нет»; в S4 ждать deferred DELETE перед reload (гонка снятия тоста vs. DELETE, феасабилити); `prefers-reduced-motion` — без специальной обработки, одной строкой в D8; пометка «visual не покрывает internals» в §2/§7.
- **Отклонены как ложные:** «§2 пишет, что 5000 только у отложенных» (формулировка §2 точна — любой undo-тост 5000); «undo-тосту нечего показывать слева» (появление блока — целевое поведение D2, реализация, а не дыра).
- **Вне скоупа (зафиксировано):** перевод удаления занятий на общую схему PendingActions — решение юзера: переводить обязательно, заведён issue #286 (§9).
