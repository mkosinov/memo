## 3. Решения

**D1 — Линт: весь проект + исключения, порог = факт.** Скрипт в
`frontend/admin/package.json` (вариант Б, юзер-решение 17.09):
`eslint . --max-warnings 37`; в `frontend/admin/.eslintrc.json` добавляется
`ignorePatterns`: `.next/`, `e2e/`, `__tests__/` (тесты и Playwright-спеки
остаются вне линта, как и решено на G1a; корневой `__tests__/` подтверждён
панелью). node_modules игнорируется ESLint'ом по умолчанию. Выгода
механизма: будущие верхнеуровневые кодовые каталоги подхватываются сами.
Инвариант порога — **потолок, не равенство** (семантика `--max-warnings`:
exit 0 ⇔ счёт **≤** порога, официальные доки ESLint): новые warnings сверх
порога роняют CI; цифра 37 — снимок 17.09, на IMPL счёт пересчитывается от
факта, порог = фактически измеренный. RED-GREEN-рецепт для IMPL: прогнать
`npx eslint .` после иконочных правок → снять счёт → выставить порог →
ввести заведомый warning в тестовый файл → убедиться exit ≠ 0 → убрать.

**D2 — Web — вне скоупа, отдельным issue.** У `frontend/web/package.json:9`
тот же скрипт дословно; решение юзера 17.09 — отдельная карточка:
**#300** (app:web, sub-issue направления #279), не зависит от #143.

**D3 — Иконки Menubar → lucide-react (прямые импорты).** Соответствие (все
экспорты проверены на установленной версии 1.21.0): Calendar→`Calendar`,
Clipboard→`ClipboardList`, Users→`Users`, Palette→`Palette`,
Book→`BookOpen`, Image→`Image` (импортировать с алиасом
`import { Image as ImageIcon } from 'lucide-react'` — коллизия имени с
`next/image`). Габариты: `size={18}` + `strokeWidth={2}` повторяют текущие
18×18/strokeWidth 2 (дефолт lucide 24×24). Точные глифы сверяются на IMPL
по факту (допустима замена на более близкий экспорт, если визуальная пара
лучше). lucide-react tree-shakable (ESM, per-icon modules) — статические
импорты не раздувают бандл; динамические импорты НЕ вводим.

**D4 — Мёртвые иконки: удаляются ВСЕ четыре, включая чат.** Компоненты
Chat/Package/MapPin/Tag и ключи `chat/package/mapPin/tag` удаляются.
Решение юзера 17.09: «удали» — пересмотр первоначального «чат оставь»;
аргумент простоты (мёртвый ключ — тот же паттерн, что и остальные три;
возврат = одна строка импорта lucide) принят. При появлении чат-раздела
иконка возвращается импортом `MessageCircle`.

**D5 — (ранее часть D5, сохранено)** Package/MapPin/Tag: компоненты и
ключи карты удаляются — см. D4.

**D6 — Inline-шевроны Menubar → lucide.** :311 и :356 — `ChevronLeft` /
`ChevronRight` с `size={12}` (тот же глиф); :709 — `ChevronLeft` с
`size={16}` (под `w-4 h-4`) и сохранением `rotate-180`-логики.

**D7 — UserMenu → lucide.** Локальные `SunIcon`/`MoonIcon`/`LogoutIcon`
заменяются на lucide-экспорты `Sun`, `Moon`, `LogOut` (проп `size={14}` —
текущие SVG 14×14; без явного размера дефолт 24 удвоит иконки). Пометка:
юзер утверждал Sun/Moon; LogOut в UserMenu обнаружен после (скаут
пропустил) — включён по правилу «весь файл, тот же тип правки»; юзер
подтвердил при выборе («2 переделать» затрагивает весь файл).

**D8 — Gitignore: без правок.** Пункт 3 issue закрывается как устаревший:
артефакты уже игнорируются, базлайны трекаются сознательно (см. §1).

**D9 — Спуск порога до 0 — отдельным issue: #301** (app:admin,
`depends-on: #143`): порядок unused-vars → any → img → exhaustive-deps,
порог опускается ступенями (пересчитывая счёт между группами — чистки
`no-unused-vars` могут порождать/снимать `exhaustive-deps`), exhaustive-deps
чинятся в последнюю очередь с ручной проверкой поведения каждого хука.
В #143 не смешивать (решение юзера 17.09).

**D10 — ICON_MAP удаляется; иконка живёт прямо в пункте меню
(юзер-решение 17.09, «переделать»).** Пункты навигации и PHOTO_ITEM несут
компонент напрямую: `{ label: 'Расписание', Icon: Calendar, href:
'/schedule' }`; рендер `<item.Icon />`. Карта `ICON_MAP` и её строковые
ключи удаляются целиком. `ChevronIcon` остаётся **тонкой локальной
обёрткой** над lucide `ChevronRight`: проп `expanded` вращает глиф классом
`rotate-90` (текущее поведение :605/:643) — lucide-компонент сам пропа
`expanded` не умеет. Три способа шеврона после D6/D10 сведены: обёртка —
только для `expanded`-кейса, остальные — прямые импорты.

**D11 — Механический страж порога НЕ строится (юзер-решение 17.09).**
Скрипт-диффер счёта и порога в CI отклонён: #301 опускает порог до 0 и
снимает сам сценарий дрейфа. Если в будущем порог снова замораживается
выше нуля — тема может вернуться отдельным issue.

## 5. Проверяемость (DoD IMPL)

1. `pnpm lint` (frontend/admin) exit 0; счёт warnings при прогоне
   `npx eslint .` (с исключениями из D1) равен порогу из package.json на
   момент коммита; RED-GREEN: заведомый warning в тестовом файле роняет
   линт (exit ≠ 0).
2. `grep -c '<svg'` в Menubar.tsx и UserMenu.tsx == 0; `grep ICON_MAP`
   в Menubar.tsx — ноль вхождений (карта удалена).
3. Пункты навигации и PHOTO_ITEM несут lucide-компоненты напрямую
   (`Icon:`-поле); ключи-строки для иконок отсутствуют.
4. E2E: auth-session, auth-roles, cabinet зелёные; visual-регрессия зелёная
   от пересозданных базлайнов (`pnpm run test:e2e:update`; требует живого
   dev-сервера :3001 и бэкенда :8000 либо CI-пути `update-snapshots.yml`).
5. CI frontend-checks зелёный на PR.

## 6. Не меняется

Domain-rules не затрагиваются (доменных сущностей касается только
библиотека отрисовки иконок — правил на неё нет). `docs/design-system.md`
(#287, смержен) описывает структуру Menubar, не содержимое иконок —
обновления не требует.
