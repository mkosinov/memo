## 2. Концепт (Gate A, авто)

Один концепт: **закрыть нейминговый и a11y-хвосты #139 без изменения видимого поведения и без правок e2e-сценариев.**

Отвергнутые подходы:

- **`aria-disabled="true"` + правка e2e** (force-click или реструктуризация сценариев) — нарушает зафиксированное решение §6.5 (`ColumnPicker.tsx:67-72`), тянет churn в e2e; семантика спорна: контрол не «выключен» — операция «скрыть» неприменима в данный момент.
- **`title` на label/input** (предложение панели simplicity) — отвергнут по research-верdictу панели best-practices: MDN документирует `title` как ненадёжный для вспомогательных технологий (непоследовательная exposes браузерами/скринридерами, бесполезен для touch и части клавиатурных сценариев). Экономия была бы illusory: цель пункта — гарантированная озвучка.
- **sr-only-текст внутри `<label>`** (исходный вариант rev1) — отвергнут после панели: текст внутри label входит в доступное имя контрола, что (а) семантически грязно — пояснение-ограничение читается как часть имени, (б) ломает 2 существующих юнит-теста с точным сопоставлением имени (`DataTable.test.tsx:278` `getByLabelText('Тег')`, `ColumnPicker.test.tsx` `getByLabelText('Вместимость')`).
- **wontfix по пункту 3** — противоречит цели issue; снят выбором механизма, который §6.5 не нарушает.

Выбранный механизм — **`aria-describedby` → вынесенный sr-only-текст** (рекомендация панели best-practices как семантически чистый): имя контрола остаётся «Тег», пояснение подаётся как описание (description) — отдельная реплика скринридера после имени.

Границы скоупа (сознательно НЕ строим):

- Никаких правок поведения гарда: нативный `disabled`, `aria-disabled`, изменение toggle-логики — решение §6.5 остаётся в силе.
- Никаких правок e2e-сценариев.
- Никаких правок page-clamp (пункт 1 issue закрыт фактом «уже сделано»).
- Имена экспортов (`materialColumns`, `recordColumns`) не меняются — переименовывается только файл.

## 3. User Scenarios

**S1. Скринридер озвучивает гард.** Пользователь со скринридером открывает ColumnPicker (например, над таблицей записей) и клавиатурой доходит до чекбокса последней оставшейся видимой колонки. Сейчас скринридер читает только название колонки — приглушение не озвучивается, непонятно, почему переключение не работает. После: читается название, затем отдельной репликой-описанием — «Последняя видимая колонка — скрыть нельзя».
Проверка: юнит-тесты в `ColumnPicker.test.tsx` (§5.3).

**S2. Видимое поведение не меняется.** Пользователь с мышью: последний пункт в пикере по-прежнему приглушён, курсор `not-allowed`, клик — no-op; остальные колонки скрываются/показываются как прежде; таблица Tags (ровно одна колонка, гард активен всегда) работает как раньше. Пользователь только с клавиатурой (без скринридера): Space/Enter на защищённом пункте по-прежнему даёт no-op (ранний возврат toggle), видимый отклик не меняется — осознанно в границах скоупа «без изменения видимого поведения». Пикер рендерится только в открытом состоянии (`open`-гейт, `ColumnPicker.tsx:54`), поэтому описание отсутствует в DOM, когда пикер закрыт.
Проверка: существующие e2e (tags-crud — клик по label единственной колонки `Тег` с ожиданием no-op; visual-regression — локатор `label:has(input[type=checkbox])`) зелёные **без правок тестов**; юнит-тесты без правок — доступное имя не меняется, существующие `getByLabelText('Тег')` / `getByLabelText('Вместимость')` продолжают совпадать. Страховка: если visual-regression всё же покажет дрифт снапшотов `*-table-picker-open` сверх порога (sr-only — `position:absolute`, в раскладку не вмешивается, поэтому дрифт не ожидается), перегенерация этих снапшотов — штатный шаг приёмки.

**S3. Конвенция нейминга полная.** Разработчик открывает любую папку `*/components/`: все `*Columns.tsx` называются по своему экспорту (`materialColumns.tsx` → `materialColumns`; `recordColumns.tsx` → `recordColumns`).
Проверка: сборка + линт + типчек зелёные; юнит-тесты таблиц материалов и записей зелёные (после правки путей импорта в двух тестовых файлах — §5.2); grep-конвенция «файл = экспорт» выполняется для всех `*Columns.tsx`.

## 5. Технические решения

### 5.1 Механизм озвучки гарда

В `ColumnPicker.tsx` каждый пункт рендерится как фрагмент: `<label>…(как сейчас)…</label>`, а при активном гарде (`disabled = checked && lastVisible`, где `lastVisible = visibleKeys.length === 1`) сразу после label — `<span className="sr-only">Последняя видимая колонка — скрыть нельзя</span>`. Чекбоксу защищённого пункта добавляется `aria-describedby`, указывающий на id этого span; у незащищённых пунктов атрибут не ставится и span не рендерится.

- Идентификаторы: `useId()` компонента + ключ колонки (`${uid}-guard-${col.key}`) — уникальны даже при двух таблицах на странице. React 18 (в проекте), `useId` доступен.
- Tailwind 3.4 (в проекте) даёт `sr-only` из коробки; в кодовой базе класс ещё не использовался — это первое применение. `sr-only` — `position:absolute` + clip: элемент не участвует в раскладке и ничего не рисует, поэтому visual-regression-снапшоты не затрагиваются (см. S2).
- Доступное имя контрола не меняется: текст вне label в имя не входит → существующие `getByLabelText('Тег')` / `getByLabelText('Вместимость')` остаются зелёными, скринридер подаёт пояснение как description.

### 5.3 Тесты

Два новых кейса в `ColumnPicker.test.tsx` (гранулярность файла — один purpose на кейс):

1. **Гард активен** (одна видимая колонка): у чекбокса защищённого пункта есть `aria-describedby`; элемент с этим id содержит точный текст «Последняя видимая колонка — скрыть нельзя»; у незащищённых пунктов атрибута нет. Плюс контрольная проверка доступного имени: `getByRole('checkbox', { name: '…' })` находит по чистому названию колонки — имя не загрязнено.
2. **Гард не активен** (две и более видимых колонок): ни у одного чекбокса нет `aria-describedby`, sr-only-описаний в DOM нет.

Существующие юнит-тесты и e2e не правятся — их зелёный статус и есть проверка S2.
