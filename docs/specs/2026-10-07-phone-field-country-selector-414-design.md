# Спека #414: поле телефона — селектор кода страны + ввод остатка номера (rev4, 2026-10-07)

Rev4 (решение пользователя после Gate C): вставка из буфера строки с ведущей «8» и ровно 11 цифрами распознаётся как номер РФ — селектор на «+7 Россия», остаток без ведущей 8.

Rev3: замечания consistency-ревьюера (6-я перспектива панели, повтор после смены модели) свёрнуты в текст — риск дубля переатрибутирован (текущий код уже сверяет обе стороны одной редукцией; риск возникал бы только при смене представления ввода), редукция получает единый дом в новом модуле, payload входа получил явный предикат привязки страны, PATCH аккаунтного телефона сотрудника (#348) гейтится валидатором полноты, механика бэкенда входа описана честно.

Rev2: замечания пяти ревьюеров (completeness, feasibility, security, simplicity, best-practices) — единая редукция цифр на обеих сторонах, инициализация виджета существующими значениями, поведение входа и пустых значений, вставка «+», видимая часть селектора, проверка полноты через «возможность» номера.

## Контекст

Поле телефона в админке построено спекой #221 как адаптивная маска (`libphonenumber-js/AsYouType`, страна по умолчанию RU, автоподхват страны по набранному «+», без выпадающего списка стран). Поиск клиента по хвосту номера работает, но ввод выглядит «голым»:

- первые 3–4 набранные цифры показываются без кода страны и разделителей («900»);
- подсказка пустого поля обещает «+7 (___) ___-__-__», а реальное содержимое поля никогда так не выглядит;
- правка середины набранного номера прыгает курсором в конец (заявленное ограничение v1 #221).

Помимо формы записи, телефон в админке вводится ещё в трёх местах свободным текстом без маски и валидатора: карточка клиента, два поля телефона у сотрудника (создание/правка аккаунта), экран входа.

Разведка (два скаута, 2026-10-07, обе зоны «актуально»): все три жалобы подтверждаются кодом; хранение (`clients.phone`, `String(20)`, без нормализации) и поиск (`memo_phone_national` + LIKE по хвосту национальных цифр) терпимы к любому написанию номера; русский словарь названий стран в `libphonenumber-js` отсутствует — словарь наш.

Сверка «тот же клиент?» при сохранении записи в текущем коде корректна: обе стороны проходят одну и ту же редукцию по **полным** цифрам (введённая сторона — видимая строка целиком, включая код страны; проверено по коду при ревизии rev3 — первоначальная формулировка разведки приписывала риску неверную сторону). Риск появляется только вместе с этим выпуском: представление ввода меняется на «остаток без кода страны», и если бы сверка пошла по остатку, не-русские коды перестали бы совпадать. Поэтому спека фиксирует инвариант: сверка всегда по полным цифрам (введённая сторона — компакт), как сегодня.

Решения #221, которые настоящая спека пересматривает: «без выпадающего списка стран» и автоподхват страны по набранному «+» — уходят, страна выбирается явно селектором (вставка «+» — см. §Виджет). Движок сохраняется: та же библиотека `libphonenumber-js`, поиск по хвосту номера национальными цифрами не меняется. Меняется проверка полноты при сохранении: вместо строгой валидности `isValid()` (решение #221) — «возможность» номера `isPossiblePhoneNumber` (длина/полнота для страны; рекомендация автора библиотеки для проверки пользовательского ввода; на `min`-метаданных строгая проверка всё равно вырождается в длину).

## Решения Gate A (пользователь, 2026-10-07)

1. **Охват — все поля ввода телефона в admin, включая экран входа.** web в этом выпуске не трогаем, но компонент строится изолированным (без admin-специфики), чтобы web мог взять его в будущем.
2. **Список стран — короткий кураторский** (см. §Список стран).
3. **Хранение — компакт в базе, красота на экране:** при новом вводе в базу пишется компактная международная форма («+79996531803»); на экране номера группируются единым форматтером во всех местах показа, включая старые записи.

Решения, принятые без развилок: инвариант сверки клиента (полные цифры, обе стороны одной редукцией) сохраняем при новом представлении ввода — обязательно; прыжок курсора при правке середины — снова принимаем как ограничение v1; поисковые поля фильтров (текстовый ввод в фильтрах таблиц) не переводим на виджет — это поиск, а не ввод номера.

## Единая редукция цифр

Ключевой механизм сверки — существующее правило `to_national_digits` (Python) / `toNationalDigits` (TS-зеркало): оставить только цифры; если ровно 11 цифр и первая 7 или 8 — отбросить первую. Оно применяется **на обеих сторонах** любого сравнения:

- сверка «тот же клиент?» при сохранении записи: введённая сторона — компакт «+<код><нац. цифры>», сторона записи — сохранённая строка; обе через редукцию; равенство редукций = совпадение;
- поиск аккаунта при входе (бэкенд): отправленная строка и `User.phone` — обе через редукцию.

Свойства (проверены по правилу): все русские написаниия («+7999…», «+7 999…», «8999…», «999…») сводятся к одному ключу; не-русские коды («+375…», «+1…») ключ не теряют (11-значное отбрасывание срабатывает только на 7/8); обе стороны любого сравнения используют один и тот же ключ. Общий код +7 у России и Казахстана редукцией не различается («+7 701…» и «8 701…» — один ключ): на входе такая коллизия закрывается отказом (§Экран входа), при привязке клиента берётся первое равное совпадение из уже отфильтрованной выдачи — практически недостижимо (у валидных RU-номеров нет национальных префиксов 6xx/7xx). Гарантия «без дубля» действует для номеров, чьи сохранённые формы сводятся редукцией; неразбираемый мусор не матчится — создаётся новый клиент, как сегодня.

**Единый дом правила (ревизия rev3):** TS-копия переезжает из `hooks/useRecordMutations.ts` в новый модуль `phone/format.ts` (экспорт оттуда, обновление импортов, тесты рядом); Python-копия остаётся на месте (`backend/src/domain/phone_digits.py`) — вторых копий не появляется.

## Концепт

### Виджет PhoneField

Составное поле в одну рамку: `[селектор «+7 Россия ⌄»] │ [инпут остатка номера] [×]`.

- **Селектор кода страны** — кнопка с кодом и русским названием страны («+7 Россия ⌄»; название обязательно — в списке v1 у России и Казахстана одинаковый код +7, только код их не различает). Открывает выпадающий список (тот же паттерн, что существующие listbox: абсолютное позиционирование, `--z-popover`): «+375 Беларусь»…, отметка выбранной строки. Выбор кликом; закрытие — клик вне или ESC. Навигация мышью (клавиатурной навигации по списку в v1 нет — как у существующих выпадающих списков админки; путь развития — паттерн WAI-ARIA Combobox/Listbox).
- **Инпут остатка номера** — форматирование на лету через `AsYouType(выбранная страна)`; не-цифровые символы игнорируются; ручной набор «+» в остатке не вводится (код страны задаётся селектором), но **вставка из буфера** строки, начинающейся с «+», разбирается как международный номер: страна из разбора выбирается селектором, если есть в списке; страна вне списка — поле переходит в состояние «без страны» (см. ниже), цифры остаются в остатке, селектор не меняется. Вставка строки, начинающейся с «8» и содержащей ровно 11 цифр, распознаётся как российский номер (транк 8): селектор → «+7 Россия», остаток = цифры без ведущей 8. Placeholder инпута — честный шаблон национального формата выбранной страны (RU: «999 123-45-67»; шаблоны хранятся в словаре стран рядом со списком). Атрибуты инпута: `type="tel"`, `dir="ltr"`; автозаполнение — по существующей семантике каждого экрана.
- **Состояние «без страны» (`country = null`):** номер не привязан ни к одной стране списка (вставка вне списка, мусорная инициализация). Компакт в этом состоянии не определён. Выбор страны в селекторе выводит из состояния. Для карточки клиента и сотрудника изменённый непривязанный номер блокирует сохранение сообщением «Выберите страну из списка»; для входа — не блокирует ничего (см. §Экран входа).
- **Ввод не обрезается:** слишком длинный остаток не усекается автоматически — сохранение блокирует валидатор полноты (ниже).
- **Смена страны посреди ввода** сохраняет набранные цифры и переформатирует остаток под новую страну (поле покидает состояние «без страны»); если длина остатка не подходит новой стране, валидатор полноты сообщит при сохранении — видимое и честное состояние, а не ошибка механизма.
- **× (очистка)** — очищает остаток, возвращает страну RU и снимает «без страны».
- Страна по умолчанию — RU.
- Значение поля — `{ country, national, pristine }` (controlled): `country` — код страны списка или `null`; `pristine=true`, пока пользователь не изменил номер (см. §Инициализация существующих значений). Производные: `visible` (сгруппированный остаток), `compact` («+79996531803»; определён только при `country ≠ null`), `isComplete` (`country ≠ null` и `isPossiblePhoneNumber(остаток, страна)`).

### Список стран

Кураторский массив в словаре компонента: код страны, код вызова, русское название, шаблон плейсхолдера. Состав v1 (9): Россия RU +7, Беларусь BY +375, Казахстан KZ +7, Украина UA +380, Латвия LV +371, Литва LT +370, Эстония EE +372, Польша PL +48, Германия DE +49. RU первым, далее по алфавиту русских названий. Расширение списка — правка одного массива (библиотека форматирует и проверяет любую страну по её коду; отдельной миграции не нужно).

### Инициализация существующих значений

При открытии карточки клиента / полей сотрудника сохранённая строка разбирается в состояние виджета (`parseStoredPhone`):

- разбирается как номер страны из списка → селектор на этой стране, остаток = национальные цифры;
- не разбирается или страна вне списка (мусор, «+1 …») → состояние «без страны» (селектор RU, остаток = только цифры строки).

**Нетронутое значение (`pristine`) сохраняется буквально как лежит в базе** — без перекладывания в компакт и без валидатора полноты; канонизация в компакт и валидация применяются только к изменённому номеру. Этим гарантируется: открыл карточку и нажал «Сохранить» — в базу уйдёт то же значение, что лежало (виджет ничего не меняет и не ломает сам по себе).

### Форматирование, валидация, хранение

- **Валидатор полноты один на все поля:** изменённый номер блокирует сохранение, если он без страны («Выберите страну из списка») или неполон для выбранной страны («Проверьте номер телефона — возможно, он введён не полностью» — текст #221 сохраняется). Полнота = `isPossiblePhoneNumber` (длина/полнота для страны), проверка «настоящести» диапазонов не выполняется — осознанно. Сообщение показывается инлайн под полем по существующему паттерну ошибок каждого экрана. Экран входа — исключение: там валидатор полноты не применяется вовсе (ни блокировки, ни сообщения; см. §Экран входа).
- **Сотрудник (#348, важно):** аккаунтный телефон сохраняется отдельным запросом PATCH `/users/:id`, который модалка отправляет **до** сохранения карточки. Поэтому валидатор полноты обоих телефонных полей входит в общую проверку модалки (`validate()`) — она выполняется первой и тем самым гейтит и PATCH аккаунтного телефона, и создание аккаунта, и PUT карточки.
- **Пустое значение:** допустимость пустоты не меняется относительно сегодняшнего поведения каждого поля — карточка клиента: телефон можно очистить и сохранить (колонка nullable); форма записи, поля сотрудника, вход — телефон обязателен, пустое поле блокирует сохранение существующей required-логикой экрана (не валидатором полноты).
- **Хранение:** при сохранении изменённого номера в базу пишется `compact` («+<код страны><национальные цифры>»). Компакт валидного номера из списка стран ≤ 16 символов — укладывается в `String(20)`; защитная проверка длины при сохранении с понятным сообщением остаётся. Инвариант компакта — фронтовой; бэкенд хранит `clients.phone` как прислано (см. «Что сознательно не делаем»).
- **Показ:** общий форматтер `formatPhoneDisplay(строка)`: `parsePhoneNumber(строка, 'RU')` → международный формат с группировкой («+7 999 653-18-03»); не распарсилось — показать как есть (терпимость к мусору); пустая строка/`null` → пусто. Точки применения: колонка «Телефон» таблицы клиентов, шапка записи (`RecordHeader`), метка клиента в модалке занятия (`ClientLabelById`), карточка клиента (оба места), краткая карточка клиента на странице записей (`ClientQuickCard`). Аудит-лог не трогаем (значения приходят замаскированными с бэкенда). Сид-данные уже компактные — показ становится группированным и для них.

### Поиск и привязка клиента (форма записи)

- Поиск подсказок не меняется: с 4-й национальной цифры, `GET /clients?phone=<нац. цифры>&per_page=10`, дебаунс 300 мс, только активные клиенты, строка подсказки «Имя · телефон» (телефон — через форматтер показа).
- Выбор из подсказок: привязка по id, поле замораживается «Имя · телефон» в режиме только-чтение, × снимает выбор (поведение #221).
- **Сверка (сохранение инварианта):** сегодня обе стороны уже идут через `toNationalDigits` по полным цифрам (введённая — видимая строка целиком). В #414 введённая сторона становится компактом; сверка остаётся `toNationalDigits(компакт) === toNationalDigits(client.phone)` — та же семантика, работающая для RU и не-RU написаний. При сохранении непикнутого номера клиент ищется свежим запросом по нац. цифрам и сопоставляется по равенству редукций (§Единая редукция цифр). Мусор не матчится → создание нового клиента (как сегодня).
- Создание нового клиента — на бэкенд уходит `compact` (bind-by-id путь #221 остаётся основным; резервный `get_or_create_by_phone` бэкенда не меняется).

### Экран входа

- Инпут логина заменяется на PhoneField; **валидатор полноты на входе не применяется** — ни блокировки, ни сообщения (иначе аккаунты с телефонами вне кураторского списка или в неполных написаниях физически не смогли бы войти). Пустое поле блокирует существующей required-логикой. Ввод «+» и вставка — по общим правилам виджета.
- **На сервер отправляется:** `compact`, если поле привязано к стране списка (`country ≠ null`); иначе — только цифры введённого («15551234567»). Предикат определён состоянием `country` виджета — отдельной эвристики нет.
- **Точечная правка бэкенда (единственная):** поиск аккаунта при входе: (1) точное совпадение строки (сегодняшнее поведение); (2) если нет — совпадение по редукции `to_national_digits` обеих сторон; ровно одно совпадение — вход; ноль или несколько — отказ с единым сообщением «Неверный телефон или пароль» (множественная коллизия закрывается отказом — детерминированно; сообщение единое для всех причин отказа, включая неверный пароль). Поиск по редукции — линейное чтение активных пользователей с вычислением редукции (таблица пользователей мала; точный индекс `User.phone` продолжает обслуживать путь (1)). Существующая лестница защиты не меняется: блокировка аккаунта, пер-IP счётчик и тайминг-паритет проверяются до верификации пароля; in-memory счётчики остаются ключеванными по набранной строке (как сегодня). Семантика хранения и уникальности `User.phone` (точная строка) не меняется; нового парсинга на бэкенде не появляется. Окна установки/восстановления пароля не затрагиваются (там ввода номера нет).

### Интеграция в кодовую базу

- Новый модуль `frontend/admin/app/components/shared/phone/`: `PhoneField.tsx` (виджет), `countries.ts` (словарь), `format.ts` (форматтер показа, компакт, `parseStoredPhone`, **единый дом `toNationalDigits`** — переезд из `useRecordMutations.ts` с обновлением импортов). Модуль не импортирует admin-специфику (только React, `libphonenumber-js/min`, дизайн-переменные и общие стили) — кандидат на перенос в web в будущем; отдельный кросс-прикладной пакет сейчас не создаём. Новый код парсинга использует `parsePhoneNumber` (не legacy-псевдоним `parsePhoneNumberFromString` из #221).
- `RemoteSearchSelect` получает один опциональный проп `prefix` (узел, рендерящийся внутри рамки поля перед инпутом; поведение потребителей без пропа не меняется — Photos и словари не затронуты; в план добавляется регрессионный тест «без пропа»). Клик по префиксу не открывает список подсказок (стоп клика); в режиме только-чтения (выбран клиент) селектор страны неактивен. Проп — общий слот-адornment составного поля, а не телефонная логика в общем компоненте.
- `PhoneInput` (форма записи) собирается из PhoneField-логики + существующего типахида `RemoteSearchSelect` с `prefix` = селектор страны; форматирование/поиск — от выбранной страны.
- Поля карточки клиента, сотрудника и входа используют PhoneField напрямую.
- E2E-якорь `data-testid="input-phone"` сохраняется за инпутом остатка в форме записи; селектор получает свой якорь (`phone-country-select`).

## Behavioral Delta

| Что | Было | Стало |
|---|---|---|
| Поле телефона (везде в admin) | один инпут; в форме записи адаптивная маска с «голыми» первыми цифрами, в остальных полях свободный текст | составное поле: код страны и её название видны всегда, остаток группируется с первых цифр под выбранную страну |
| Подсказка пустого поля | ложный шаблон «+7 (___) ___-__-__» | честный шаблон остатка выбранной страны |
| Страна номера | по умолчанию RU, автоподхват по «+» | явно селектором; автоподхвата при наборе нет; вставка «+» выбирает страну (вне списка — состояние «без страны») |
| Что сохраняется | видимая строка как есть (разнобой форматов) | компакт «+79996531803» — при изменении номера; нетронутое legacy-значение уходит в базу как лежало (без канонизации и валидации) |
| Показ номеров | сырая строка из базы | группировка единым форматтером, включая старые записи |
| Карточка клиента / сотрудник | без маски и валидации | виджет + валидация полноты изменённого номера (у сотрудника гейтит и отдельный PATCH аккаунтного телефона) |
| Вход | свободный текст, буквальное сравнение | виджет, компакт/цифры на отправку; поиск аккаунта: точная строка → уникальная редукция → отказ |
| Сверка «тот же клиент?» | по полным цифрам, обе стороны одной редукцией | без изменений — инвариант сохранён при новом представлении ввода (компакт) |
| Проверка полноты | строгая валидность `isValid()` | «возможность» номера `isPossiblePhoneNumber` (длина/полнота для страны) |

## User Scenarios

1. Администратор создаёт запись, страна RU выбрана по умолчанию, набирает остаток — цифры группируются с первых введённых; с 4-й цифры выпадают подсказки; сохраняет без выбора → клиент создан, в базе компакт, в таблице клиентов номер показан группировкой. (E2E: запись с новым номером)
2. Администратор выбирает клиента из подсказок → поле замораживается «Имя · телефон», × снимает выбор и возвращает ввод. (E2E: выбор из подсказок)
3. Администратор вводит белорусский номер: выбирает «+375 Беларусь», остаток группируется по белорусскому шаблону, сохраняет; повторный ввод того же номера привязывается к уже созданному клиенту — дубля нет. (E2E: не-RU без дубля)
4. Администратор переключает страну посреди ввода (RU → Латвия) — плейсхолдер и группировка остатка меняются, набранные цифры сохраняются; вставка скопированного «+375 29 123-45-67» выбирает страну из вставки; вставка «8 999 123-45-67» переводит поле на «+7 Россия». (E2E: смена страны и вставка)
5. Администратор открывает карточку клиента с legacy-номером («+7 999 …») и сохраняет, не трогая телефон, — в базу уходит то же значение; правит телефон виджетом — неполный номер блокирует сохранение сообщением о неполноте. (E2E: карточка клиента, нетронутое и изменённое)
6. Администратор создаёт сотрудника: оба поля телефона — виджет; неполный аккаунтный телефон блокирует и PATCH аккаунта, и сохранение карточки; в базу аккаунта пишется компакт. (E2E: сотрудник)
7. Администратор входит, набирая логин-номер в виджете: аккаунт со старым написанием («+7 999 …») и аккаунт со страной вне списка («+1 …») входят как раньше; неверный номер даёт единое сообщение отказа. (E2E: вход — старое написание, вне списка, отказ)

## Граничные случаи и ограничения v1

- Курсор: правка середины остатка прыгает в конец (наследственное ограничение #221; известные пути лечения — картирование позиции по счёту цифр или форматирование на blur — в v1 не берём).
- Клавиатурная навигация по списку стран отсутствует (мышь, ESC, клик-вне) — паритет с существующими listbox админки.
- Автоподхват страны по набранному «+» удалён (осталась вставка); страны вне словаря при ручном наборе требуют расширения массива.
- Вставка длиннее валидного номера не обрезается — блокируется валидатором полноты при сохранении.
- Вставка «8 …» (ровно 11 цифр) распознаётся как номер РФ: селектор на Россию, остаток без ведущей 8; ручной набор «8» первой цифрой при выбранной России остаётся обычным набором (AsYouType показывает «8 (…», национальные цифры без 8).
- Вставка международного номера страны вне списка: состояние «без страны»; сохранение в карточке/сотруднике потребует выбора страны из списка (или расширения списка); вход — цифрами как есть.
- Показ старых записей, не разбираемых парсером, — как есть (терпимость к мусору).
- Множественная коллизия редукции при входе (два аккаунта — одни цифры, включая RU/KZ при общем +7) закрывается отказом; пользовательский разбор коллизии вне рамок (данные чистятся вручную).
- Нецифровые логины: виджет оставляет только цифры, поэтому аккаунт с полностью нецифровым `User.phone` (теоретически возможен при свободном вводе) войти не сможет. Перед внедрением — разовая проверка сохранённых логинов: все ли значения сводимы к цифрам; нецифровые (если найдутся) правятся вручную. Риск принят сознательно после проверки.

## Тесты

- Юнит (vitest): PhoneField — выбор страны, формат по странам (RU/BY/LV), плейсхолдеры, × и сброс к RU, валидатор полноты (`isPossiblePhoneNumber`), `compact`, вставка «+» (в списке / вне списка → «без страны»; «8…» с 11 цифрами → RU, остаток без 8), смена страны с сохранением цифр; `parseStoredPhone` — компакт / легаси «+7 999…» / «8 999…» / мусор / страна вне списка; pristine — нетронутое значение не перекладывается и не валидируется; словарь стран (уникальность кодов, шаблоны на месте); `formatPhoneDisplay` (компакт / легаси / мусор → как есть / пустое → пусто); `toNationalDigits` — переезд в `phone/format.ts`, тесты переезжают вместе; PhoneInput — порог 4 цифры от выбранной страны, источник цифр (`getNationalNumber`, не с экрана), read-only после выбора, подъём `compact`; редукция (кейсы «+7…», «8…», «999…», «+375…», «+1…», 11-значные с 7/8 и без, RU/KZ общий +7); RemoteSearchSelect — регрессия «без prefix поведение прежнее»; StaffModal — валидатор полноты гейтит PATCH до отправки; бэкенд — вход: точная строка → уникальная редукция → отказ, коллизия редукции (включая RU/KZ) → отказ.
- E2E (Playwright): сценарии 1–7 выше; существующие спеки типахида обновляются под новый якорь/состав поля.

## Правки канона

- `docs/domain-rules/clients.md`: абзац «Record-form phone typeahead (GH #221)» переписывается под новую механику (селектор страны, компакт-хранение при изменении, единая редукция сверки — инвариант полных цифр, форматтер показа, `isPossiblePhoneNumber`).
- Правка коммитится вместе со спекой.

## Что сознательно не делаем

- web не переводится на виджет (только изоляция модуля для будущего переноса); отдельный общий пакет не создаётся.
- Серверная нормализация/валидация записи `clients.phone` не добавляется: инвариант компакта — фронтовой, бэкенд хранит как прислано (существующее поведение; показ и поиск терпимы к любому написанию). Осознанный остаточный риск из ревью безопасности, принятый ради минимума бэкенд-правок.
- Уникальность `User.phone` не переводится на редукцию цифр (остаётся точной строкой); коллизии редукции на входе закрываются отказом, а не чисткой данных.
- Канонизация/миграция старых написаний `clients.phone` не выполняется: показ лечится форматтером, поиск и так терпим.
- Клавиатурная навигация, курсорная правка и `getExampleNumber`-плейсхолдеры — вне v1 (заявленные ограничения; шаблоны хранятся в словаре стран).
