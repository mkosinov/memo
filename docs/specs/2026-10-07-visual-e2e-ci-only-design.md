# Спека: визуальные e2e — сравнение картинок только в CI (#278)

Дата: 2026-10-07. Статус: ревизия 2 (после панель-ревью 6 агентов; ключевые правки: `--update-snapshots=none` в проверочном прогоне, честные условия запуска воркфлоу, строгие проверки env, исправление устаревшего перечня визуальных поверхностей в доке).

## Контекст и проблема

Визуальные e2e-тесты сравнивают снимки страниц админки с эталонными PNG. Эталоны записываются и обновляются только в CI (workflow `update-snapshots.yml`, раннер `ubuntu-latest`) — это канон и он не меняется. Но локальный полный прогон (`scripts/test-all.sh` в контейнере opencode) по-прежнему **исполняет** пиксельные сравнения — и краснеет целиком из-за среды:

- Замер 2026-10-07 (воркдерево от origin/main `1fecaa65`, коммит принят CI зелёным): **46 падений из 71 визуальной проверки**; расхождения ~1 % пикселей на каждой странице + смещение ширины мелких надписей (96→99 px); плюс 3 таймаута ожидания селекторов — шум медленного dev-режима, к шрифтам отношения не имеющий.
- Причина — не пакеты шрифтов (они в контейнере уже совпадают с `playwright install --with-deps`), а база дистрибутива: контейнер — Debian 12 (fontconfig 2.14 / freetype 2.12), раннер — ubuntu-latest (fontconfig 2.15 / freetype 2.13).
- Следствие: каждый UI-PR локально выглядит сломанным; время уходит на ложные разбирательства; появляется соблазн перезаписать эталоны локально, что ломает CI.

Рассмотренные альтернативы (Gate A, витки 1–2): ребейз образа контейнера на Ubuntu (2а) — отвергнут пользователем как тяжёлая правка инфраструктуры; отдельный паритетный образ для тестов (1') — отвергнут (дублирование окружения сборки); точечная донастройка Debian (2б) — отвергнута как хрупкая и без гарантии совпадения. Выбран концепт C: локально картинки не сравниваем вовсе, вердикт по картинкам — только CI.

Отвергнуто и на ревизии 2 (панель-ревью): предложение выбросить узкий воркфлоу, потому что полный ручной запуск `test.yml` (у него есть `workflow_dispatch`) уже покрывает потребность формально — оставлено по явному решению пользователя: разница в скорости и узости (полный прогон против ~10 минут только по визуальной части). Предложение заменить пропуск файлов на официальный флаг `ignoreSnapshots` (сценарии визуальных спеков продолжали бы исполняться локально без сравнения) — отвергнуто: остаточные тайминговые флейки dev-режима внутри этих сценариев сохраняли бы редкую локальную красноту, а требование концепта — детерминированно зелёный локальный прогон.

## Концепт

Сравнение картинок становится исключительной компетенцией CI тремя способами сразу:

1. **Локальный прогон не запускает визуальные спеки** (конфигурация Playwright: пропуск вне CI; визуальные сценарии не исполняются вовсе — детерминированная зелёность и скорость).
2. **Осознанное локальное расследование** — opt-in переменной `E2E_VISUAL=1` возвращает визуальные спеки в локальный прогон. Ценность: локальный осмотр диффов для триажа — отличить дрейф среды (~1 % на каждом тексте) от реально сломавшейся структуры страницы до отправки в CI.
3. **Ручной узкий CI-прогон** — новый workflow `visual-check.yml`: только три визуальных спек-файла, только проверка (`--update-snapshots=none`), без перезаписи эталонов; при пиксельных падениях — артефакт с диффами. Уточнение против ревизии 1: GitHub запускает `workflow_dispatch`-воркфлоу только когда его файл есть на ветке по умолчанию (main), а ветка запуска (`--ref`) должна содержать этот файл — то есть «любая ветка» означает «любая ветка, уже содержащая этот воркфлоу» (ветки, отпочкованные после слияния). Полный ручной прогон всего набора на любой ветке существует и раньше (`gh workflow run test.yml --ref <ветка>`); новый канал — его узкая и быстрая версия по явному запросу пользователя.

CI-автоматика не меняется: шард 2 (`shard-rest`) гоняет все визуальные спеки как раньше (все три файла принадлежат только ему — patterns `testMatch` не захватывают их в `shard-schedule`); `update-snapshots.yml` остаётся единственным способом записи эталонов. Побочная защита: локальный запуск `test:e2e:update` больше физически не может перезаписать визуальные эталоны (файлы не запускаются) — канон «никогда не обновлять эталоны локально» получает механический сторож.

## User Scenarios

- **СЦ1. Агент или разработчик запускает полный локальный прогон в контейнере** (`bash scripts/test-all.sh`; корневой `pnpm test:all` ведёт себя одинаково). Раньше: e2e-часть краснела на ~2/3 визуальных проверок при исправном коде. После: визуальные файлы не запускаются, локальная проверка сигнализирует только о реальных функциональных проблемах. → Проверки В1, В6.
- **СЦ2. Разработчик расследует визуальную поломку и хочет увидеть диффы локально.** Запускает `pnpm run test:e2e:visual` (или `E2E_VISUAL=1 playwright test …`) — визуальные спеки исполняются, диффы доступны для триажа «среда против поломки»; краснота от среды ожидаема и документирована. → Проверка В2.
- **СЦ3. Нужен быстрый вердикт по картинкам на ветке** (например, в предымержевой проверке, без полного прогона). Разработчик запускает `gh workflow run visual-check.yml --ref <ветка>` (после того как воркфлоу слит в main; ветка должна содержать его файл) — ~10 минут, зелёный/красный вердикт только по визуальной части; при красном — артефакт с диффами. Для старых веток без файла — уже существующий полный запуск `test.yml --ref` либо ребейз. → Проверка В4.
- **СЦ4. Новый участник читает канон тестов** и видит: локально картинки не сравниваются (почему — с цифрами замера), вердикт и эталоны — CI, ручной узкий прогон — как и когда запускать; перечень визуальных поверхностей — ровно три файла (устаревшее упоминание четвёртой, `visual-compliance-checks.spec.ts`, исправляется — у него нет пиксельных сравнений). → Проверка В5.

## Behavioral Delta

| До | После |
|---|---|
| Локальный полный прогон исполняет визуальные сравнения и краснеет от среды (46/71 на зелёном main) | Локальный полный прогон визуальные файлы не запускает; локальная проверка — функциональная |
| Вердикт по картинкам — полный CI-прогон (автоматически в PR; вручную — `test.yml --ref`) | Тот же + ручной узкий визуальный прогон `visual-check.yml` (~10 мин, после слияния воркфлоу в main) |
| Локальное пиксельное сравнение доступно всегда (и всегда красное) | Локальное пиксельное сравнение — осознанный opt-in `E2E_VISUAL=1` / `test:e2e:visual` |
| Локальный `test:e2e:update` мог записать визуальные эталоны (запрещено только правилом) | Не может физически: визуальные файлы локально не запускаются |
| Эталоны записывает только `update-snapshots.yml` | Без изменений |

## Решение

### 1. Пропуск визуальных спеков локально — `frontend/admin/playwright.config.ts`

```ts
// #278: pixel comparison is CI-only. The container's font stack (Debian 12)
// differs from the runner's (ubuntu-latest): every text drifts ~1% pixels,
// so local visual runs are pure environment noise (2026-10-07 measurement:
// 46/71 failed on a CI-green main commit). E2E_VISUAL=1 opts back in for
// deliberate local investigation.
const RUN_VISUAL = process.env.CI === 'true' || process.env.E2E_VISUAL === '1';
const VISUAL_SPECS = /(^|\/)(visual-regression|week-view|wave6-status-snapshots)\.spec\.ts$/;
```

- `testIgnore: RUN_VISUAL ? [] : [VISUAL_SPECS]` — верхнеуровневая директива, действует для всех проектов.
- Строгие сравнения (`=== 'true'`, `=== '1'`) вместо истинности строк: `E2E_VISUAL=0` или случайный `CI=false` не включают визуальные прогоны.
- Семантика `CI` корректно различает среды: GitHub ставит `CI=true` в оба CI-workflow; `scripts/test-all.sh` на время вызова Playwright принудительно очищает `CI=` (существующая конвенция, та же, на которой сидят `retries`/`forbidOnly`; проверено по строкам 47 и 265 скрипта).
- Список визуальных файлов явный, ровно три имени; `visual-compliance-checks.spec.ts` (DOM-проверки; пиксельных сравнений не имеет) продолжает гоняться локально.

### 2. Opt-in для расследования — `frontend/admin/package.json`

Скрипт `"test:e2e:visual": "E2E_VISUAL=1 playwright test visual-regression.spec.ts week-view.spec.ts wave6-status-snapshots.spec.ts"`.

### 3. Ручной узкий CI-прогон — `.github/workflows/visual-check.yml` (новый)

Каркас — зеркало `update-snapshots.yml` (та же среда записи эталонов: `ubuntu-latest`, те же версии Node 22/pnpm/uv, тот же стек шарда 2: SHARD_ID=2, фронт :3003, бэкенд :8002), отличия:

- запуск: `workflow_dispatch` (файл обязан лежать в main; ветка запуска — через `--ref`, должна содержать файл);
- guard пустого списка: `playwright test --project=shard-rest <3 файла> --list` обязан разрешить ≥1 спек. Назначение guard — поймать опечатку в имени проекта/файлов и регрессию фильтров (зеркало guard #209); рассинхрон списка визуальных файлов он сознательно не ловит (страховка от него — локальная краснота нового файла, см. «Издержки»);
- прогон: `pnpm exec playwright test --project=shard-rest visual-regression.spec.ts week-view.spec.ts wave6-status-snapshots.spec.ts --workers=1 --update-snapshots=none` — режим `none` гарантирует, что проверочный прогон ничего не запишет (без флага Playwright по умолчанию дописывает отсутствующие эталоны — режим `missing`);
- при падении — артефакт `visual-check-diffs` из `frontend/admin/test-results/**` (`if: failure()`, `if-no-files-found: ignore` — артефакт есть только при пиксельных падениях; провал стека или guard виден в логе, артефакта не даёт; версия action — v4, зеркалит существующие воркфлоу репо, отдельный перевод на свежие мажоры — самостоятельная забота);
- ожидаемое время: зелёный прогон ~10 минут; красный — до ~15 (CI-ретрай 1 даёт повтор упавших).

### 4. Канон — `docs/tests_workflow.md`

Раздел «Screenshot e2e can pixel-diff locally while CI is green» (строки ~229–263, до «See also») **заменяется целиком** (не правится построчно — иначе в нём выживет устаревший перечень из четырёх поверхностей, включая `visual-compliance-checks.spec.ts`, у которого пиксельных сравнений нет). Новый текст канона:

- терминология единая: «screenshot e2e (визуальные спеки)» — три файла;
- локально визуальные спеки не запускаются (механизм: `testIgnore` + строгая проверка `CI`/`E2E_VISUAL`);
- почему: замер 07.10 — дистрибутив контейнера ≠ дистрибутив раннера, пакеты шрифтов уже совпадают, дрейф сидит в fontconfig/freetype; цифры (46/71 на зелёном main-коммите);
- `E2E_VISUAL=1` / `test:e2e:visual` — осознанное расследование с целью триажа диффов; краснота от среды ожидаема и не чинится локально; прямой вызов `playwright test visual-regression.spec.ts` без opt-in даёт «No tests found» — это ожидаемо, включай opt-in;
- `test:e2e:update` локально физически не пишет визуальные эталоны; правило «эталоны записывает только `update-snapshots.yml`» — без изменений;
- ручной вердикт по картинкам: `gh workflow run visual-check.yml --ref <ветка>` (ограничения запуска — как выше); полный ручной прогон — `test.yml --ref`;
- прецедент 2026-07-29 (IMPL #182) сохраняется в новом разделе как история.

## Границы (что сознательно НЕ строим)

- Не меняем пороги `maxDiffPixels` — они защищают CI-сторону от дрейфа раннера, их семантика не связана с локальным пропуском.
- Не трогаем `test.yml` и `update-snapshots.yml`.
- Не ребейзим образ контейнера и не заводим паритетный образ (решения Gate A).
- Не трогаем `visual-compliance-check.sh` и `pair-visual-debugging` (живой осмотр правок разработчиком — другой механизм, канон не затронут).
- Не правим скиллы контейнера в этом PR: устарела ровно одна строка одной таблицы (`vitest-playwright-patterns`, пункт 9 — «локальный пиксельный диф = не регрессия, смотри CI»); правка харнесса идёт через конвейер superagents (сначала там, потом синхрон в проекты) — отдельный маленький ход после этого. Упоминания визуальности в `fast-track-protocol` и `pair-visual-debugging` проверены — касаются других механизмов, не правятся.
- Не выносим общий каркас стека в переиспользуемый workflow (`workflow_call`): третье зеркало принято сознательно; рефакторинг — если появится четвёртое.

## Издержки и риски

- **Локально расхождения вёрстки не видны до CI, а сценарии визуальных файлов не исполняются вовсе.** Сознательная потеря: локальная среда не авторитетна для пикселей (канон и до этого объявлял локальные визуальные прогоны «не гейтом»), а шум полностью съедал сигнал; взамен — детерминированная зелёность (альтернатива `ignoreSnapshots` отвергнута — сохраняла бы остаточные локальные флейки).
- **Список визуальных файлов — явный, в трёх местах** (regex конфига, скрипт, вызов в воркфлоу). Новый визуальный спек-файл нужно добавить одной правкой. Забыть — нельзя не заметить: новый файл погонится локально и покраснеет от среды сразу же (а в узкий CI-прогон не попадёт, пока не добавлен).
- **Воркфлоу становится запускаемым только после слияния в main** — проверка В4 выполняется пост-мердж; до этого узкий ручной вердикт недоступен (полный `test.yml --ref` существует и раньше).
- **Дублирование каркаса стека** между test.yml / update-snapshots.yml / visual-check.yml — третье зеркало существующего паттерна, принято сознательно.
