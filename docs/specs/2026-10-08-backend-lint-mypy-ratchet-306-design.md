# Спека: бэкенд lint/mypy — рахет-гейт в CI и волновая чистка до нуля (#306, design)

- **Статус:** черновик (гейт B — на утверждении пользователя).
- **Дата:** 2026-10-08.
- **Разведка:** счётчики сняты на дереве, идентичном `origin/main` (2026-10-08).

## Контекст

Бэкенд несёт большой давний долг статических проверок, и он растёт:

| Проверка | 2026-09-17 (создание трекера) | 2026-10-08 (разведка) | Динамика |
|---|---|---|---|
| `uv run ruff check src tests` | 288 | **269** (117 исправимы `--fix`) | −19, почти стоит |
| `uv run mypy src` | 382 | **531 в 49 файлах из 147** | **+~150, растёт** |

CI бэкенда гейтирует только тесты и покрытие — линт и тайпчек не запускаются ни в одной джобе. Правило «+0 новых ошибок» держалось руками в волнах разработки и не выдержало: три недели без стража добавили ~150 mypy-ошибок.

Разбивка долга (разведка 2026-10-08):

- **mypy по семьям:** services 170, admin 148, api 110, domain 28, seed 26, repositories 24, schemas 9, прочее (main/auth/cli/models/core) ≈ 16. `models/` почти чист. (Сумма семей сходится с тоталом 531; точные стартовые пороги волны 0 переснимаются на `origin/main` в момент волны — числа здесь для масштаба.)
- **ruff по правилам (топ):** I001 44, B008 37 (вызовы `fastapi.Depends` и родня в дефолтных аргументах), F401 29, RUF012 23, TC002 14, RUF100 13, UP037 11, F841 10, RUF001 9, RUF059 9, W292 9, UP042 8, TC003 7, TC001 6, F811 4. Около 130 ошибок — чистая механика (сортировка импортов, неиспользуемые импорты, `noqa`-мусор, перенос строки в конце файла, `TYPE_CHECKING`-импорты).
- **Конфиг:** ruff — наборы `E,W,F,I,N,UP,B,SIM,TCH,RUF`, `extend-immutable-calls` нет; mypy — `strict = true` и полный строгий стек, единственный оверрайд `tests.*` → `disallow_untyped_defs=false`. Файла-бейзлайна/рахета нет.
- **Прецедент в этом же репо:** чистка линта админ-фронта (38 → 0) завершена по механике «порог в команде проверки равен фактическому остатку, каждая волна сносит группу ошибок и опускает порог» — механика доказана, финальное состояние «0 и полный гейт» достигнуто.

## Проблема (сценариями)

- Разработчик запускает локально `ruff`/`mypy` — получает сотни старых ошибок, в которых не видно новых. Проверки бесполезны как сигнал.
- Новые ошибки типизации молча попадают в main: CI их не видит.
- Долг монотонно растёт без механического препятствия.

## Цели

1. Немедленно остановить рост: CI-гейт «счётчик не больше порога», порог = текущему остатку.
2. Монотонно спустить остаток до нуля волнами, не блокируя обычную разработку.
3. Дойти до постоянного полного гейта: ruff = 0 и mypy = 0 в CI, без порогов.

## Non-goals (сознательно не делаем)

- Разовый мега-PR со всеми правками — заведомо непроверяем; поэтапность выбрана ранее в трекере mypy-долга.
- Pre-push-хуки — механизма в репо нет, гейт живёт в CI; локальные проверки остаются добровольными.
- Изменение поведения приложения: все правки волн сохраняют поведение и проверяются существующим тест-сьютом.
- Ослабление `strict = true` глобально.
- Фронтенд-линт (admin/web) — отдельные закрытые треки.
- Миграция FastAPI-зависимостей на форму `Annotated[..., Depends(...)]` (правило FAST002 у fastapi-линтеров) — отдельная содержательная правка ~40 мест рантайм-резолва зависимостей; этой спекой B008 закрывается конфигом (стандартный ваивер для FastAPI-репо), Annotated — возможный будущий трек.

## User Scenarios

Сценарии процессные (пользователь инструмента — разработчик репо); «Проверка» в каждом — механическая команда или состояние CI, не E2E-прогон браузера: задача не меняет пользовательский интерфейс приложения.

- **US-1. Новая ошибка блокирует PR.** Разработчик пушит PR, добавляющий mypy- или ruff-ошибку → джоба `backend-lint` красная с дельтой («стало N+1, порог N»). Проверка: локальный прогон скрипта бюджета на дереве до/после — exit 1 только при превышении.
- **US-2. Волна сносит ошибки и опускает порог.** Автор PR-волны (например, семья services) сносит часть ошибок → джоба зелёная, и тем же PR порог в скрипте бюджета опущен до нового факта. Проверка: механическая сверка «пороги в `backend/scripts/lint_budget.py` == фактическим счётчикам на main».
- **US-3. Механика не мешает ревью.** Волна 0 (конфиг B008 + безопасные автоправки) сносит ~150 позиций до содержательных волн → ревьюер волны services видит только аннотации типов, без шума импортов. Проверка: после волны 0 в `ruff check --statistics` нет I001/F401/RUF100/W292/UP037/TC00x, а B008 = 0.
- **US-4. Локальная проверка снова осмыслена.** К финалу `uv run ruff check src tests` и `uv run mypy src` дают 0; в промежутке локальная точка входа — `uv run python scripts/lint_budget.py` — печатает счётчики против порогов, показывая, сколько осталось. Проверка: обе команды на финальном main возвращают 0 и exit 0.

## Behavioral Delta (до → после)

- До: линт/mypy в CI не запускаются; локально — сотни старых ошибок без сигнала; долг растёт (~+150 mypy за три недели).
- После: джоба `backend-lint` гейтирует оба инструмента рахет-порогом, равным фактическому остатку; PR, добавивший ошибку, — красный; PR, снёсший ошибки, обязан опустить порог (заниженный и поднятый порог одинаково красные — рахет не разболтается); остаток монотонно спускается волнами до нуля и остаётся нулём под полным гейтом (прямой вызов инструментов без скрипта сравнения).

## Решение

### Концепт (единственный выживший)

**Рахет-гейт немедленно + волновая чистка до нуля.** Отсечение альтернатив:

- «Чистка без гейта, гейт после обнуления» — опровергнута фактом: политика «+0 новых» без стража дала +~150 mypy-ошибок за три недели; обнуление без барьера не наступает.
- «Разовый мега-PR» — отвергнут ранее в трекере mypy-долга как непроверяемый; кроме того, не останавливает рост до мержа.

### Механика гейта

1. Новая джоба `backend-lint` в существующем workflow `test.yml`, параллельно тестам (без `needs`, как быстрый сигнал; существующая `backend-coverage` ждёт тесты — новой этого не нужно). Триггеры — те же, что у остальных джоб workflow: `pull_request` и `push` в main (прямые пуши не обходят гейт). Установка зависимостей: `uv sync --extra dev` — `ruff` и `mypy` объявлены в dev-экстре (как и в остальных трёх бэкенд-джобах). Enforcement — через существующую merge-дисциплину репо (зелёный CI — единственный триггер мержа), как у `backend-coverage`.
2. Пороги — константы в едином скрипте `backend/scripts/lint_budget.py` (отдельного файла-бюджета нет — порог виден в диффе PR так же, сущностей меньше):
   - ruff — **per-rule** словарь `{"I001": 44, "F401": 29, …}`: правила — независимые классы нарушений, тотал пропустил бы компенсацию «снёс 10 сортировок импортов, добавил 10 опасных»;
   - mypy — **тотал** `M`: у mypy нет стабильного машиночитаемого per-кода вывода, итоговая строка стабильна годами.
3. Скрипт — единственный исполнитель обоих инструментов и владелец их exit-кодов:
   - запускает `ruff check src tests scripts --output-format json` (стабильный машиночитаемый формат; `scripts` включён, чтобы обвязка гейта сама была под линтом);
   - запускает `mypy src --no-incremental` и берёт тотал из итоговой строки `Found N errors`;
   - **fail-closed:** exit-код инструмента, не означающий «нарушения найдены» (ruff ≥ 2, mypy = 2, пустой/непарсимый вывод) → красный «инструмент сломан, счётчик недостоверен» — падение проверки никогда не читается как «0 ошибок»;
   - отчёт по обоим инструментам печатаются целиком, без короткого замыкания на первом.
4. Правила сравнения (на инструмент):
   - факт > порога → exit 1, «PR добавил ошибок: было N, стало F»;
   - факт < порога → exit 1, «порог разболтался: опусти до F» (равенство порога факту — канон рахета, как в чистке админ-фронта);
   - факт == порогу → exit 0.
5. **Порог не растёт.** Скрипт в CI читает версию порогов на базе ветки (`git show <merge-base>:backend/scripts/lint_budget.py`, для пуша в main — `HEAD~1`) и краснеет, если хоть один порог поднялся: «бюджет не растёт — сначала снеси ошибки». Единственное исключение — создание скрипта волной 0 (до неё порогов в базе нет) и осознанный сдвиг при бампе версий инструментов (отдельный PR с пересчётом, см. Риски).
6. Версии инструментов зафиксированы `uv.lock` — счётчик детерминирован между локальным запуском и CI.

### Волны

- **Волна 0 — механика и конфиг (один PR):** джоба + скрипт с порогами = факту на main (пересняты в момент волны); в ruff-конфиг, секция `[tool.ruff.lint.flake8-bugbear]`, — `extend-immutable-calls` для семейства FastAPI-аннотаций (`fastapi.Depends`, `Query`, `Body`, `File`, `Form`, `Header`, `Path`, `Cookie`, `Security`) — уходит основная масса B008 без правок кода; если после конфига остаётся хвост B008 от вызовов вне списка — эти места правятся в той же волне (цель волны: B008 = 0); `uv run ruff check src tests --fix` — безопасные автоправки (~117). После волны 0 порог ruff ≈ 115, mypy = 531. Полный тест-сьют зелёный — автоправки импортов проверяются тестами и e2e-шардом PR.
- **Волны 1..k — mypy по семьям, от большей к меньшей:** services (170) → admin (148) → api (110) → domain+seed (54) → repositories+schemas+прочее (~69). Крупная семья делится на под-PR по файлам; каждый под-PR опускает порог до своего факта.
  - Внутри волны: сначала разбивка по кодам ошибок (`--show-error-codes`), механика (недостающие аннотации) — честными аннотациями; типизационный паттерн, нерешаемый без искажения кода — точечный `[[tool.mypy.overrides]]` для конкретного модуля как последнее средство, с обоснованием в PR-описании.
- **Волна r — ruff-хвост:** RUF012 (`ClassVar`-аннотации), F841, RUF001/RUF059 (строки), UP042, F811. F811 (переопределения имён) проверять на реальный баг, не удалять вслепую. Идёт между mypy-волнами или последней — план закрепит.
- Финал (обязательный, не опциональный): оба порога 0 → скрипт с порогами и логикой сравнения удаляется, джоба зовёт `ruff check` и `mypy` напрямую по exit-коду — полный гейт без прокладки, сравнивающей ноль с нулём.
- **Параллельные под-PR одной семьи сериализуются:** равенство «порог == факту» превращает гонку в принудительный ребейз — после мержа первого под-PR второй ребейзится и опускает порог до своего факта; тихого дрейфа порога это не допускает (а запрет роста из «Механики гейта» закрывает подъём).

### Политики

- `strict = true` не ослабляется; оверрайды — точечные, обоснованные, ревьюируемые.
- Автоправки — только безопасные (`--fix` без `--unsafe-fixes`); небезопасные — вручную и осмысленно.
- Каждая волна: полный тест-сьют зелёный; порог опущен до факта в том же PR.
- mypy в CI добавляет ~1–2 минуты к джобе — приемлемая цена.

## Координация с трекером

- mypy-часть поглощает узкий трекер «поэтапная чистка mypy» (#383): его разбивка по семьям и критерий «+0 новых / baseline монотонно падает» вошли в эту спеку; закрытие #383 — решение пользователя (ожидается как «поглощён»).
- Трекер типизации `@transactional`-декоратора (#394) остаётся отдельным слайсом: волна services не трогает его файлы (или чинит их последними в семье — план зафиксирует границу).
- Возможное удаление мёртвого `src/cli.py` (#390) — вне скоупа; его 2 ошибки уйдут аннотациями в волне «прочее».

## Риски

- **Автоправки импортов** (TC00x/UP037) в рантайм-паттернах FastAPI/Pydantic → волна 0 обязательно проходит полный тест-сьют и e2e-шард CI, а не только линт.
- **Флуктуация счётчика** между окружениями исключена `uv.lock`; любое обновление `ruff`/`mypy`, сдвинувшее счётчик (мажор, минор, патч) — отдельный PR с пересчётом порогов, единственный законный подъём (и он виден в диффе скрипта). Локальный стейл-кэш mypy исключён: скрипт зовёт `--no-incremental`.
- **Крупная семья** (services 170) тянет на большой PR → деление по файлам, порог опускается каждым под-PR (равенство порога факту это поощряет).
- **Забытый порог** — невозможен как тихий долг: и превышение, и занижение красные (US-2).
