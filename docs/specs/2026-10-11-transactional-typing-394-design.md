# Спека: типизация @transactional — одна обёртка без слота, честные типы без подавлений (#394, вариант C)

- Issue: #394 (refactor(services): типизировать @transactional-декоратор)
- Дата: 2026-10-11, ревизия 4 (вариант C + влития панели 394-r2: каноническая типизация обёртки, инспекция сигнатуры на декорировании, контракт с валидацией)
- Поток: STANDARD (спека → панель → гейт B → план → гейт C)

## Контекст и проблема

Декоратор `@transactional` из `backend/src/services/decorators.py` используется в двух формах:

1. **Методы сервисных классов** (`src/services/*.py`, 31 применение, проверено AST-обходом): первый параметр — настоящий `self`; вызываются как привязанные методы — `await service.create(db_session=..., data=...)` (~40 мест в `src/api/v1/*`).
2. **Selfless-сценарии** (бизнес-мутации в `src/usecases/`: records ×4, staff ×5, user ×2, password_setup ×2, activities ×1, clients ×1 — 15 определений): определение — самостоятельная функция без `self` (`create_record(db_session: AsyncSession, data: ...)`), но вызов обязан нести ведущий литерал `None` (`create_record(None, db_session=..., ...)`), потому что у обёртки декоратора зарезервирован первый слот `self: Any`, который сценарию нечем занять.

Археология: декоратор родился для методов (транзакция + события #239 + аудит #344, привязанные к сущности сервиса, резолвимой по `self`). Потом мутации подняли в слой `usecases` (сценарии дирижируют несколькими сервисами, поэтому им плохо быть методами) — и вместо отдельной обёртки переиспользовали существующую: слот остался, сценарии заняли его заглушкой `None`. Конвенция «ведущий `None`» задокументирована в заголовках шести модулей usecases и плане #327. Предпосылка «нужен единый слот» — не дизайн, а аренда чужой формы: инстанс метода приезжает и через `*args` (привязанные методы подставляют его первым позиционным автоматически), слот для этого строить не нужно.

Следствие слота сегодня: контракт вызова сценария не соответствует объявленной сигнатуре, mypy strict не пропускает вызов, и каждое место гасится парой подавлений. По живому main: **15 мест × 2 кода = 30 комментариев** (`# type: ignore[misc]` + `[arg-type]`) в 7 файлах:

| Файл | Мест | Сценарии |
|---|---|---|
| `backend/src/api/v1/records.py` | 4 | create/update/patch/delete записи |
| `backend/src/api/v1/staff.py` | 5 | операции сотрудников |
| `backend/src/api/v1/users.py` | 2 | смена телефона (`update_user_phone`), выдача ссылки установки пароля (`issue_password_link`) |
| `backend/src/api/v1/clients.py` | 1 | удаление клиента |
| `backend/src/api/v1/activities.py` | 1 | удаление занятия |
| `backend/src/auth/router.py` | 1 | установка пароля по ссылке |
| `backend/src/cli.py` | 1 | бутстрап-команда CLI |

Конфигурация: mypy strict, `warn_unused_ignores = true`, python 3.12; mypy в dev-зависимостях запинен `>=1.13.0`, в окружении репозитория стоит 2.1.0 (на нём прогнаны пробы). Рачёт #306 (`mypy src --no-incremental`) явно вывел `decorators.py` из своего охвата и передал этой работе. Охват mypy — только `src/`: ~45 selfless-вызовов в `tests/` подавлений не несут и mypy не проверяются.

## Цель и границы

Цель: убрать из обёртки слот-заглушку, чтобы вызов сценария совпадал с его объявленной сигнатурой; типизировать обёртку канонически; снять все 30 подавлений; удалить конвенцию ведущего `None` как класс явления.

Не делаем (границы):

- НЕ меняем слой сценариев и слой сервисов структурно: определения (обеих форм) не трогаем ВООБЩЕ — ни сигнатур, ни строк декоратора, ни тел.
- НЕ вводим второй декоратор и НЕ переименовываем существующий.
- НЕ трогаем транзакционное ядро: коммит/откат, события #239, аудит #344, поиск сессии по имени параметра, маркер `__memo_transactional__`.
- НЕ трогаем настройки mypy и рачёт #306.
- НЕ чистим посторонние подавления вне паттерна selfless-вызова.

## Контракт декоратора (валидация на момент декорирования)

Поддерживаются ровно две формы, и обе валидируются при декорировании (ошибки контракта — громкие, на импорте, а не IndexError'ы в глубине вызова):

1. **метод инстанса**: первый параметр `self`, дальше сессия (`db_session`/`session` и т.п.) именованной передачей;
2. **самостоятельная функция** (сценарий; статик-метод-стайл): первого `self` нет, первый параметр — сессия.

Вне контракта (отвергается при декорировании): первый параметр `cls` (classmethod-форма); функция без параметров вовсе; `*args` до сессии; метод `self` без сессии. Сегодня нарушений нет — проверено AST-обходом всех 46 применений (31 метод + 15 сценариев): все первые параметры методов — `self`, все сценарии начинаются с сессии, ни одного `*args` в сигнатурах, нул `@staticmethod`/`@classmethod` под `@transactional`.

## Решение (вариант C)

Одна обёртка без слота обслуживает обе формы — инстанс метода приезжает первым позиционным через механику привязанных методов, сценарий вызывается чистыми аргументами. Инспекция сигнатуры выполняется один раз при декорировании (сегодня — на каждый вызов; `inspect.signature` не кэшируется, а шов самый нагруженный в бэкенде), обёртка замыкается над готовыми `has_self`/`session_name`:

```python
def transactional[**P, R](func: _AsyncFunc[P, R]) -> _AsyncFunc[P, R]:
    # контракт: валидация формы здесь, один раз (см. секцию «Контракт»)
    param_names = ...
    has_self = param_names[0] == "self"
    session_name = param_names[1] if has_self else param_names[0]

    @wraps(func)
    async def wrapper(*args: P.args, **kwargs: P.kwargs) -> R:
        if session_name in kwargs:
            session = kwargs[session_name]
        else:                                   # страховка; конвенция — именованная передача
            idx = 1 if has_self else 0          # у метода args[0] — инстанс
            if len(args) <= idx:
                raise TypeError("session not found")
            session = args[idx]
        # владелец сущности для событий/аудита (#239/#344):
        entity_name = resolve_entity_name(type(args[0])) if has_self else None
        ...                                      # ядро дословно
        result = await func(*args, **kwargs)     # одна ветка: инстанс уже внутри args
        ...
        return result

    return wrapper                              # без cast
```

Типизация обёртки каноническая (PEP 612 / доки mypy «Declaring decorators»): `(*args: P.args, **kwargs: P.kwargs) -> R` — присваивание без каста, проверка пересылки аргументов внутри обёртки, честное «сигнатура не изменилась» для обеих форм. `Concatenate`, второй декоратор и Any-слоты не нужны.

Изменения в `decorators.py`:

1. подпись обёртки: `(self: Any, *args, **kwargs) -> Any` → `(*args: P.args, **kwargs: P.kwargs) -> R`; финальный `cast` удаляется;
2. инспекция сигнатуры переносится из обёртки в тело декоратора + валидация контракта;
3. вызов `func`: ветвление `if has_self` исчезает — всегда `func(*args, **kwargs)`;
4. позиционная ветка поиска сессии: индекс `args[0]` → `args[1]` для методов;
5. резолв сущности: `type(self)` → `type(args[0])` под `has_self`;
6. докстринги: конвенция вызова переписана (никакого ведущего `None`); комментарий у `has_self` фиксирует зависимость от имени первого параметра.

Различение форм (`has_self` по имени первого параметра) остаётся — формы реально различны (у метода есть владелец сущности, у сценария нет), но это внутреннее различие накопителей, а не контракт вызова.

Следствия по кодовой базе:

- **15 вызовов в src** (таблица выше): убрать ведущий `None,` и оба подавления.
- **~45 вызовов в tests**: та же одномеханическая правка; пропуск ревёт сразу — `TypeError: got multiple values for argument`.
- **«Громкий» тест-страж устаревшей конвенции** (`tests/usecases/test_records_create.py`, тест позиционного вызова) — удаляется: отказный сценарий невозможен по построению. Его место занимает постоянный юнит-тест контракта декорирования (невалидная сигнатура → громкая ошибка при декорировании) — живой страж, а не разовый артефакт.
- **Заголовки шести модулей usecases**: абзац CALLING CONVENTION переписан — сценарий вызывается обычными именованными аргументами.
- **Определения сценариев и методов не меняются ни одной строкой.**

### Доказательства прототипами (до гейта B; остаются артефактом фазы дизайна, в PR не входят)

- **Рантайм-проба** (полная механика C): пять стилей вызова — метод именованными, метод позиционными, сценарий именованными, сценарий позиционными, метод через класс — работают; владелец сущности корректен; вызов по старой конвенции с `None` падает громко (`TypeError`), тихого сдвига аргументов нет.
- **Mypy-проба** (2.1.0, `--strict`, каноническая обёртка): декоратор без каста принимается; индексация `args[0]`/`args[idx]` и поиск в `kwargs` проверяются; все корректные вызовы проходят без подавлений со строгими типами; ошибочные вызовы ловятся `[call-arg]`.

Отвергнутые альтернативы:

- **A — типовой раскол** (второй декоратор `transactional_scenario` с `Concatenate[None, P]`): решает симптом, `None` остаётся навсегда.
- **B — два декоратора с переименованием** (`transactional_method`/`transactional_scenario`): без слота формы не требуют разных обёрток — слой лишний.
- **Дескрипторный протокол** (`__get__`, wrapt-паттерн) вместо детекта по имени: новый механизм на самом нагруженном шве ради форм, которых в коде нет; контракт + валидация на декорировании дают ту же громкость отказа дешевле.
- **Статус-кво**: подавления растут с каждым сценарием, mypy-гигиена закреплена рачётом #306.

## Потоки отказов

- Сигнатура вне контракта (`cls`, без параметров, `*args` до сессии) → громкая ошибка при декорировании (импорт модуля), не IndexError в вызове.
- Сессия не найдена в вызове (ни именованной, ни позиционной) → `TypeError` при вызове — поведение сегодняшнего кода сохранено.
- Ошибочный вызов сценария → ловится mypy при сборке (`[call-arg]` и др.); после снятия подавлений проверка реально работает.
- Пропущенный при зачистке вызов со старым `None` → `TypeError: got multiple values` на первом же прогоне теста.

## Behavioral Delta

- До: пользователь не видит разницы — подавления в рантайме не проявляются. Код несёт 30 подавлений в 7 файлах, конвенцию-заглушку в заголовках шести модулей и страж-тест устаревшей конвенции; каждая новая бизнес-мутация канона добавляет пару подавлений; инспекция сигнатуры выполняется на каждый вызов.
- После: для пользователя ничего не меняется — все операции работают идентично. Слот-заглушки, конвенции `None` и 30 подавлений нет; вызов сценария совпадает с его сигнатурой; новый сценарий проходит mypy strict без ручных подавлений; ошибки вызова и контракта декорирования ловятся при сборке/импорте; сигнатура инспектируется один раз при декорировании.

## Риски

- Прикасаемся к самому нагруженному шву бэкенда (транзакция/события/аудит): меняется форма обёртки, не логика; ядро переносится дословно; поведение прикрывают юнит-тесты и E2E; «громкие» TypeError на пропусках подметают дают быструю обратную связь.
- Индексация `args[0]`/`args[idx]` при типизации `P.args` подтверждена пробой; при переносе на реальные сигнатуры mypy может найти углы → стоп на гейте плана, а не тихое подавление.
- Детект формы по имени первого параметра — конвенция; зависимость зафиксирована комментарием в коде, нарушения отвергаются валидацией при декорировании.
- Позиционные вызовы методов (сессия не именованной): индекс сдвинут и прикрыт пробой; конвенция — именованная передача, позиционных вызовов в src не найдено.
