# Спека: флейк US-5 anonymous-visits — диагностика длительности и лечение по корню (#462)

Дата: 2026-10-21. Ревизия: 2 (после панельного ревью: рецепт лечения переписан по контракту `withUndoWindow`, критерии вердикта дополнены ветками «нет данных» и «вис по подписи ошибки», локальный замер переведён в мягкий сигнал). Статус: к гейту B.

## Контекст

E2E-сценарий US-5 (`frontend/admin/e2e/anonymous-visits.spec.ts:413-489`, «deleting an anonymous row — undo restores it, auto-commit frees the seat») — таймаут-класс флейк: администратор в тесте удаляет запись анонимного посетителя, нажимает «Отменить» (строка возвращается) и дожидается авто-коммита, освобождающего место. Наблюдалось дважды (CI-прогоны ветки PR #461 — IMPL задачи #359, 2026-10-10; прогоны IMPL задачи #417): падение первого прогона по общему таймауту теста, зелёный повтор. В CI ретраи включены (`retries: 1`, `frontend/admin/playwright.config.ts:73`; локально 0 — статус `flaky` локально невозможен по построению), поэтому такой исход даёт статус `flaky`, а блокирующий флейк-гейт #415 (`scripts/e2e-report-summary.mjs` по `results.json`, шаг «Flake summary» в `test.yml`) краснит e2e-джоб даже на формально зелёном прогоне — мерж блокируется.

Устройство US-5 — два последовательных окна отмены на одной строке:

- **окно (а), строки 434–447** — удаление и undo из тоста: undo отменяет таймер, серверного DELETE нет (undo = откат кеша); фаза событийная, реальная стоимость ≈0;
- **окно (б), строки 449–461** — удаление без отмены: авто-коммит по истечении 5-секундного окна, реальный DELETE; единственная вынужденная реальная пауза теста, перекрытая `waitForResponse` (waiter зарегистрирован ДО клика — паттерн GH #261).

Бюджеты: общий таймаут теста 60 с (`playwright.config.ts:89`, комментарий: «2 Next.js dev servers on 4 cores may still be slow on first compilation»), навигация 60 с, действие 15 с, ожидание 10 с; в самом US-5 шаги несут свои явные бюджеты — 10 с / 5 с / 5 с / 15 с (DELETE-waiter) / 10 с. Трейс пишется только при ретрае (`trace: 'on-first-retry'`); HTML-отчёт и `test-results/` уходят в артефакт `e2e-report-shard-<i>` только у упавшего джоба с удержанием 7 дней (шаг «Upload Playwright report» в `test.yml`; `results.json` в артефакт НЕ входит — исторические длительности доступны только из логов CI).

Факты разведки (2026-10-21, проверка по живому дереву):

- Тело US-5 событийное, фиксированных пауз нет. Заявленные в issue «номинально ~53 с» из задержек теста не выводятся — это наблюдённая wall-clock длительность одного прогона.
- Предварительные замеры по логам CI (list-репортер печатает длительность каждого теста; прогоны 2026-10-21): US-5 проходит за **10.1 с, 20.9 с и 11.0 с** — в 3–6 раз ниже бюджета 60 с. «Номинальные 53 с» не являются типичной длительностью.
- Кандидат из issue «поднять бюджет сценария (`test.slow()`/`setTimeout`)» противоречит канону ожиданий `.opencode/skills/vitest-playwright-patterns/SKILL.md` («Never fix flakes by growing timeouts»; для таймерных фич — управление часами `page.clock`) и решению пользователя от 2026-10-21: флейки лечить корнем, раздувание таймаутов — крайняя мера. Повышенные бюджеты (`test.setTimeout`, `test.slow()`) — наследие в старых спеках (`services-crud`, `cabinet`, `tariff-age-autofill`, `user-settings-guarantee`, `visitors-deferred-delete`, `visitor-delete-invalidation`, `visits-patch-consistency`); они не тиражируются и здесь запрещены.
- Соседний сценарий S2 того же файла уже переведён на перемотку часов `withUndoWindow` (PR #434, задача #417; хелпер `frontend/admin/e2e/fixtures/helpers.ts:746`, порог перемотки по умолчанию 5_500 мс); US-5 сознательно остаётся на реальном таймере и реальном DELETE. Реальное окно отмены — литерал `delayMs: 5_000` в хуках мутаций (реестр PendingActionsContext; сведение литералов в константу — отдельная задача #464).

## Решение по гейту концепта

Пользователь выбрал подход **A — сначала факты** (2026-10-21): измерить, куда уходит время US-5 в CI и локально, лечить по установленному корню. Отвергнуто: подход B «сразу конвертировать US-5 на `withUndoWindow`» — снимает лишь ~5 с из наблюдавшихся ~53 с и не объясняет близость к бюджету; бюджетное повышение — запрещено каноном (см. Контекст).

## Behavioral Delta

- До: e2e-джоб CI изредка краснеет на US-5 (таймаут под нагрузкой, зелёный ретрай → flaky → блокирующий флейк-гейт); причина не установлена — в issue фигурирует необъяснённая цифра «~53 с номинально», лечение не определено, каждый рецидив — ручной разбор и перезапуск.
- После: типичная длительность US-5 и класс причины падений зафиксированы отчётом-комментарием в #462 (распределение длительностей по CI-прогонам, разбор дней флейка, локальный замер с разбивкой фаз) плюс протокол рецидива (см. Диагностика). По вердикту: корень в среде → эпидемиология уходит фактами в #472 (cold-start/нагрузка шардов), тест и бюджеты не трогаются — честное следствие: флейк-гейт продолжит красить редкие рецидивы до решения средовой задачи #472, это осознанное следствие «не лечить тест ради среды»; корень в тесте → точечная правка доминантной фазы. Продукт не меняется; предсказуемость диагностики растёт — рецидив получает готовый ответ вместо нового разбора.

## User Scenarios

1. Разработчик оценивает здоровье US-5 без перезапусков: длительность сценария видна в логе каждого CI-прогона (list-репортер). Проверка: комментарий-отчёт в #462 с таблицей длительностей US-5 по доступным прогонам e2e-джобов (строки берутся только из того шард-джоба, где лежит файл; у flaky-прогона каждая попытка — отдельная строка с пометкой attempt; в таблице указан размер выборки n).
2. Инженер разбирает день флейка (CI-прогоны ветки PR #461, 2026-10-10): в логе видны упавшая попытка (подпись ошибки) и её ретрай с фактической длительностью. Проверка: строки лога процитированы в отчёте либо явно зафиксировано, что логи тех прогонов недоступны.
3. Разработчик получает локальный базовый замер: канон-рецепт standalone (`docs/tests_workflow.md`, «Canonical standalone invocation» — стек-блок дословно: `ENV_FILE=.env.test`, свежая БД, сид с абсолютным `DATABASE_URL`) — серия без трассировки (`--repeat-each 3 --retries 0`) даёт распределение длительности, отдельный прогон с `--trace on` даёт разбивку фаз. Проверка: числа распределения и доминантной фазы в отчёте.
4. Вердикт применяется по критериям этой спеки: выбор ветки не требует новых согласований; обязательные стопы для пользователя — только пограничная полоса, ветка «нет данных» и решение о закрытии #462 после ветки «среда». Проверка: выполненная ветка соответствует вердикту; при ветке среды таймауты и тело US-5 не изменены.
5. (Только ветка «корень в тесте») После правки: PR лечения зелёный (все шард-джобы), локальная серия `--repeat-each 3 --retries 0` зелёная, медиана CI-длительности US-5 в следующих прогонах ниже до-леченческой. Проверка: зелёный CI на PR, локальная серия, «Flake summary» = 0.

## Диагностика (как меряем)

- **D1 — распределение CI-длительностей.** `gh run list --workflow=test.yml` + `gh run view <id> --log` → строки list-репортера вида `US5: deleting an anonymous row — … (N.Ns)`. Собрать по всем доступным прогонам e2e-джобов: run, дата, ветка, шард, длительность, статус, attempt. Отчёт по распределению (медиана, разброс, максимум — не одна медиана) с явным n. Метод проверен 2026-10-21 (три точки: 10.1 / 20.9 / 11.0 с). Источник — логи: `results.json` в артефакты не входит, исторические данные другой дорогой недоступны; правка workflow ради архива JSON вне объёма этой задачи.
- **D2 — день флейка.** CI-прогоны ветки PR #461 (2026-10-10): упавшая попытка US-5 (её подпись ошибки — общий таймаут 60 000 мс или точечный «Timeout …ms exceeded») и ретрай — фактические длительности. Артефакты `e2e-report-shard-*` тех прогонов уже истекли (удержание 7 дней) — трейс недоступен, фиксируется явно, компенсация D1+D3.
- **D3 — локальный базовый замер.** Канон-рецепт standalone (стек-блок дословно по `docs/tests_workflow.md`: `ENV_FILE=.env.test` при старте бэкенда, свежая БД, сид с явным абсолютным `DATABASE_URL`): (1) серия `pnpm exec playwright test e2e/anonymous-visits.spec.ts --repeat-each 3 --retries 0` без трассировки — распределение длительности US-5; (2) один прогон с `--trace on` — разбивка фаз (трейс тянет производительность, поэтому baseline и фазовая картина разделены). Фазы US-5 для разбивки: setup-запросы, навигация и первый рендер, окно (а) undo, окно (б) авто-коммит с DELETE, перезагрузка и финальные ассерты, создание записи на освободившееся место. Доминантная фаза = >50% длительности. Сравнение структуры фаз и порядков, не абсолютов (локальная машина ≠ CI-раннер; локально `retries: 0`, статус flaky невозможен).
- **Отчёт о диагностике** (D1–D3 + вердикт) — комментарием в #462 до начала лечения. В отчёт включается **протокол рецидива**: при новом падении US-5 — в течение 7 дней скачать артефакт упавшего джоба (трейс on-first-retry) и приложить к #462 (копией в #472 при вердикте «среда»); рецидив с другой подписью (не таймаут, а assertion) — вне класса этой спеки, отдельная диагностика.

## Критерии вердикта

- **В-среда** (ожидался по предварительным замерам): распределение CI зелёных прогонов — медиана ≤ 30 с (≤ половины бюджета) при n ≥ 3, без хвостов к 60 с в зелёных прогонах; локальная структура фаз без аномалий (локальный абсолют ≤ 30 с — мягкий, подтверждающий сигнал, не решающий: локальные абсолюты нерепрезентативны). Падение объяснимо только деградацией раннера (чужая нагрузка, cold start; смежная #472). Лечение теста не выполняется: правка ради −5 с при запасе ≥ 30 с не оправдана (YAGNI); факт-комментарий с таблицей уходит в #472; вопрос закрытия #462 «решена диагностикой» — стоп-вопрос пользователю в сессии IMPL.
- **В-тест**: медиана CI-длительностей ≥ 40 с (⅔ бюджета) ИЛИ в D1/D2 у падения подпись точечного виса («Timeout …ms exceeded» с бюджетом меньше общего — свои 5/10/15 с US-5) ИЛИ доминантная фаза по D3 локально ≥ 40 с при подтверждении той же доминанты структурой трейса. Корень в тесте или его сетапе. Лечение — по доминантной фазе из D3.
- **Пограничное** (медиана 30–40 с без виса) — стоп и вопрос пользователю с таблицей: лечение или признание средовым.
- **Нет данных** (доступно < 3 CI-проб ИЛИ D3 невыполним) — стоп и вопрос пользователю с тем, что собрано; вердикт не выбирается принудительно.

## Лечение (ветка В-тест, по доминантной фазе; заранее согласованный сценарий — по предварительным данным маловероятен)

- Доминанта — окно (б) авто-коммита (реальные 5 с): конверсия на `withUndoWindow` по контракту хелпера (`helpers.ts:714-738`): вызвать обёртку ДО клика «×» второй раз; внутри `fn` — зарегистрировать DELETE-waiter (`page.waitForResponse`) ДО клика (никогда после возврата обёртки — ответ, пришедший во время drain, невидим позднему waiter), выполнить клик; `fastForward` порога авто-коммита (дефолт `advanceMs` 5_500 мс перекрывает окно 5_000 с запасом), дождаться waiter и осадить ассерты после возврата обёртки. Окно (а) undo конверсии не подлежит (реальная стоимость ≈0). Риск `page.clock` + React Query (`dataUpdatedAt` от тех же часов) — обязательная проверка в самой задаче лечения (ассерты авто-коммита и перечитки должны пройти на перемотке), не предположение; тот же риск закрывался в задаче #417 / PR #434.
- Доминанта — setup-запросы или UI-шаги: точечная правка этой фазы по данным трейса; событийные ожидания сохраняются (канон).
- Запрещено в любой ветке: `test.slow()`/`test.setTimeout`, добавление фиксированных пауз, рост `expect.timeout`/бюджетов конфига.

## Нерушимые границы

- Продукт не меняется: правится только тестовый код и только в ветке В-тест.
- Бюджеты и таймауты не растут; retries-политика и флейк-гейт #415 не меняются.
- Остальные сценарии `anonymous-visits.spec.ts` (включая S2) и наследие `cabinet.spec.ts`/других старых спек не трогаются.
- Существующий хелпер `withUndoWindow` используется как есть.

## Риски и открытые вопросы

- Логи CI хранятся ограниченное время; если прогоны ветки PR #461 (2026-10-10) уже недоступны — D2 фиксирует это, вердикт строится на D1+D3; при нехватке проб срабатывает ветка «нет данных».
- Локальный базовый замер на iMac нерепрезентативен по абсолютам — поэтому в критериях он мягкий сигнал (структура фаз, подтверждение доминанты), а решение о классе принимается по CI-распределению и подписи ошибки.
- Ветка В-среда не устраняет флейк немедленно — она атрибутирует его среде и передаёт факты в #472; редкие блокировки флейк-гейта продолжатся до решения средовой задачи. Это осознанное следствие запрета лечить тест ради среды.
- Если флейк не повторяется месяцами, медианы остаются низкими — вердикт В-среда по совокупности имеющихся наблюдений (два падения в октябре); рецидив получает готовую таблицу для сравнения и протокол снятия трейса.

Обязательные стопы для пользователя: пограничная полоса вердикта, ветка «нет данных», решение о закрытии #462 после ветки В-среда. В остальном концепт и ветки согласованы 2026-10-21 (подход A).
