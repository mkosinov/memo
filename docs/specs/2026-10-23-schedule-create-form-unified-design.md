# Спека: единая форма создания занятия — унификация с формой редактирования (#280)

- Дата: 2026-10-23
- Приложение: admin (расписание)
- Supersedes: блок D4 спеки `docs/specs/2026-09-14-schedule-slot-create-empty-week-design.md` (состав и вид контролов формы создания занятия; живой статус-док того решения — `docs/status/2026-09-15-258-259-schedule-slot-create-empty-week.md`). Остальные решения той спеки (клик по пустому слоту, префилл из слота, кнопочная механика сохранения, автозаполнение из справочников) не пересматриваются.
- Бэкенд-контракт: без изменений. `POST /api/v1/activities` (`addActivity`) отправляет тот же payload, что и сегодня.

## Контекст и проблема

Админ создаёт занятие кликом по пустому слоту недели. Сегодня форма создания (`CreateActivityTab.tsx`) построена из других контролов и в другом порядке, чем форма редактирования того же занятия (`SettingsTab.tsx`): голые `<select>` вместо комбобоксов с поиском, «день недели» + «время начала в часах» вместо одного поля даты-времени, длительность в минутах вместо «ЧЧ:ММ», чекбокс вместо тумблера, мелкая типографика. Требование пользователя (15.09.2026): формы создания и редактирования практически одинаковы, эталон — форма редактирования. Первая строка эталона — «Дата и время + Длительность + Приватное» — сегодня в создании уезжает на четвёртую позицию и разобрана на другие блоки.

Самодельная форма была честно предписана блоком D4 спеки 2026-09-14; эта спека — смена того решения, а не фикс регрессии. Исходная проблема сопровождаемости: две независимые копии одной формы снова разойдутся при любой правке — поэтому решаем не косметикой, а устранением самой возможности расхождения.

## Концепт

Форма создания строится из тех же блоков, в том же порядке и с той же типографикой, что форма редактирования (эталон `SettingsTab.tsx`). Механика — **один компонент формы с двумя режимами**:

- `edit` — текущее поведение SettingsTab: каждое изменение применяется сразу (instant-patch);
- `create` — локальный стейт, отправка по кнопке «Создать» → `addActivity` (кнопочная механика сохранения — решение спеки 2026-09-14 §2.1.7 — сохраняется).

Общие хелперы эталона `snapMinutes` / `buildDateTimeLocal` выносятся из `SettingsTab.tsx` в модуль рядом с общим компонентом (точное место — план); копирование разметки вместо общего компонента отвергнуто: это воссоздаёт исходную проблему (расхождение форм).

Отвергнутые альтернативы:

1. **Копипаста разметки эталона в создание** — даёт одинаковый вид сегодня, но формы остаются двумя независимыми копиями и расходятся снова; прямо противоречит причине, по которой issue открыта.
2. **Косметика (типографика + тумблер без перестройки блоков)** — не выполняет требование пользователя: первая строка «дата-время/длительность/приватное» остаётся разобранной, комбобоксы не появляются.

## Границы скоупа (что мы сознательно НЕ строим)

- Instant-patch в создании — НЕ вводим: создание остаётся кнопочным (отправка собранного payload одной кнопкой).
- Бэкенд — не трогаем: ни эндпоинтов, ни payload, ни валидаций сервера.
- Форму редактирования — не редизайним: её вид и поведение остаются эталоном и без изменений (рефактор на общий компонент обязан быть незаметным для пользователя). Единственное исключение — гейт вместимости ≥ 1 (см. «Контракт формы создания», решение пользователя): пустое/нулевое значение больше не отправляется. В том числе сохраняется её сегодняшняя конвертация даты в «открытая неделя + день недели» — перенос редактирования на честные календарные даты (как в создании) — отдельная задача, не эта.
- Сервер и его валидации — не трогаем: поле `start` в API уже принимает полную дату-время, меняется только источник значения (поле формы вместо вычисления от открытой недели).
- Новые проверки обязательных полей — не вводим: обязательный набор (мастер, услуга, локация, дата-время, длительность) сохраняется; выражения проверок меняются вместе с контролами — как именно, задано в «Контракте формы создания».
- Список ожидания (waitlist) и прочие вкладки модалки — вне скоупа.

## Контракт формы создания (после)

Порядок и состав блоков — как в эталоне:

| Блок | Контролы |
|---|---|
| Строка 1 | «Дата и время» — нативный ввод даты-времени `datetime-local` (префилл из слота); «Длительность» — текст в формате «ЧЧ:ММ»; тумблер «Приватное» (`role="switch"`) |
| Строка 2 | «Услуга» — комбобокс с поиском; возрастной диапазон — read-only рядом с услугой; «Вместимость» — число; блок тарифов услуги под строкой |
| Строка 3 | «Мастер» — MasterPicker (комбобокс с цветом мастера и поиском); «Локация» — комбобокс с поиском по названию и краткому названию (`title` + `shortTitle`) |

- Типографика полей — та же, что в эталоне (`px-3 py-2 text-sm`).
- Префилл даты-времени: значение слота, по которому кликнули; календарная дата открытой недели передаётся в форму родительской модалкой (сегодня вкладка получает только номер дня и минуты — интерфейс связи расширяется), шаг сетки форма берёт из настроек сетки — того же источника, что и эталон. Минуты приводятся к сетке через `snapMinutes(gridFrequency)` — при префилле И при каждом ручном изменении поля, как в эталоне.
- Поле даты-времени свободно: админ может выбрать любую дату — прошедшую или будущую. Занятие создаётся **на выбранную календарную дату и время**: значение поля передаётся в API напрямую как `start` (API уже принимает полную дату-время; сегодня фронт вычисляет её как «открытая неделя + номер дня» и молча переносит выбор чужой недели в открытую — это поведение исчезает, решение пользователя 2026-10-23). Для этого интерфейс `addActivity` контекста расписания расширяется: форма передаёт готовую дату-время, конвертация через открытую неделю остаётся штампам сетки (перетаскивание заготовки — они знают только день недели и минуты) и редактированию. Сервер не меняется. Отдельные контролы «день недели» и «время начала» исчезают.
- Если выбранная дата вне открытой недели, занятие в текущей сетке не появится (оно в своей неделе) — тост успеха называет выбранную дату и время («Создано: … среда, 20 октября, 14:00»), а не день недели, как сегодня.
- Автозаполнение из справочников сохраняется: выбор услуги заполняет длительность (и возраст для показа), выбор локации — вместимость (`defaultCapacity`); повторный выбор перезаписывает.
- Валидация: обязательный набор полей сохраняется (мастер, услуга, локация, дата-время заполнено, длительность > 0); выражения проверок меняются вместе с контролами (было «часы 0.5–23.5», становится «дата-время непусто»; длительность — разбор «ЧЧ:ММ», некорректный формат блокирует «Создать»).
- Вместимость ≥ 1 в обоих режимах — нулевой вместимости по домену не существует (у локаций допустимо 1–500). Префилл из `defaultCapacity` выбранной локации сохраняется (это и есть доменная договорённость «дефолт локации, если не переопределена в активности»); пустое или нулевое значение блокирует «Создать». Сегодня пустое поле молча отправляется как 0 (`Number(capacity) || 0`) — этот путь исчезает.
- Кнопка «Создать» (`btn-create-activity`) — единственная точка отправки; блокируется на время запроса; занятие появляется в сетке после успеха; при ошибке создания — тост ошибки, форма остаётся открытой (как сегодня). Закрытие формы без «Создать» ничего не создаёт.
- Тестиды. В создании — префикс `create-`: на сами контролы `create-datetime` (новый), `create-duration`, `create-private` (тумблер), `create-capacity`, `btn-create-activity`; на контейнер контрола (обёртку, как `select-service`/`select-location` в эталоне) — `create-service`, `create-master`, `create-location`; блоку тарифов — отдельный `create-service-tariffs`. Для этого у общих `Combobox`/`MasterPicker` появляется необязательный проп тестида контейнера (аддитивное расширение, эталон не меняется). Контролы `create-day` и `create-time` удаляются вместе с полями. В редактировании все существующие якоря (`settings-row-*`, `input-*`, `toggle-private`, `select-*`, `age-display`, `settings-tab`) сохраняются без изменений — на них опираются юнит-тесты эталона.

## User Scenarios

- **US-1.** Админ кликает пустой слот → открывается форма создания, повторяющая форму редактирования: строка 1 «Дата и время + Длительность + Приватное», строка 2 «Услуга + возраст + Вместимость (+ тарифы)», строка 3 «Мастер + Локация». E2E: открытие формы по клику в пустой слот, проверка состава и порядка блоков.
- **US-2.** Админ кликает слот вторника 14:00 → поле даты-времени уже заполнено этим значением (минуты по сетке); админ меняет значение на другую дату (в том числе в другой неделе) и время → занятие создаётся на выбранную дату и время; тост успеха называет выбранную дату. E2E: префилл из слота + создание на изменённую дату (проверка — занятие в своей неделе, не в открытой).
- **US-3.** Админ выбирает услугу через комбобокс с поиском → возраст показывается read-only, длительность и вместимость заполняются из справочников; смена услуги перезаписывает значения. E2E: автозаполнение при выборе услуги и локации.
- **US-4.** Админ переключает тумблер «Приватное» → занятие создаётся приватным. E2E: создание приватного занятия через тумблер.
- **US-5.** Админ закрывает форму без «Создать» → занятие не создаётся, слот остаётся пустым; с «Создать» → занятие появляется в сетке. E2E: отмена без побочных эффектов + happy path создания.

## Behavioral Delta

| Аспект | До | После |
|---|---|---|
| Строка 1 | «Дата/время» отсутствует; день недели и время — отдельные поля на 4-й позиции | «Дата и время» (`datetime-local`) + «Длительность» ЧЧ:ММ + тумблер «Приватное» — первой строкой, как в редактировании |
| Мастер / услуга / локация | голые `<select>` без поиска | MasterPicker (с цветом мастера), комбобоксы с поиском (локация — по названию и краткому названию) |
| Возраст и тарифы услуги | не показываются | возраст read-only + блок тарифов, как в редактировании |
| Приватность | чекбокс | тумблер `role="switch"` |
| Длительность | число в минутах | текст «ЧЧ:ММ» |
| Вместимость | в паре с длительностью | в строке 2 рядом с услугой |
| Вместимость, нижняя граница | от 0 (пустое поле отправляется как 0) | от 1; пустое/нулевое блокирует «Создать»; префилл — дефолт локации |
| Типографика | `px-2 py-1.5 text-xs` | `px-3 py-2 text-sm` |
| Дата создания | выбор даты молча переносится в открытую неделю (слался её день недели) | занятие создаётся на выбранную дату; тост успеха называет дату |
| Механика сохранения | кнопка «Создать» → `addActivity` | без изменений |
| Автозаполнение из справочников | есть | без изменений |
| Бэкенд-контракт | `POST /activities` | без изменений |

Для пользователя: создание занятия выглядит и заполняется так же, как редактирование; исчезает переучивание между двумя формами; поиск по мастерам/услугам/локациям доступен и при создании.

## Риски

- **Рефактор SettingsTab на общий компонент** — главный риск: регрессия редактирования. Защита: рефактор без изменения ожиданий существующих тестов редактирования (критерий выше) + e2e расписания.
- **Создание на дату вне открытой недели** — занятие «исчезает» из текущей сетки (оно в другой неделе); смягчено тостом с выбранной датой. E2E проверяет занятие в его неделе.
- **`datetime-local` в e2e** — заполнение поля программно стабильнее через прямую установку значения, чем через клавиатуру; паттерн уже используется в тестах редактирования.
- **Модалка узкой ширины**: 3 блока эталона рассчитаны на ширину вкладки настроек — вкладка создания той же модалки, риск компоновки минимален, проверяется визуально (VCC ниже).
