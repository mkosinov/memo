# #529: волна миграции `datetime.utcnow` → единый наивный UTC-помощник (рев.2)

## Контекст

Полный backend-прогон (`cd backend && uv run pytest -q`, 3674 теста) выдаёт
~74 303 предупреждения одного класса: `datetime.utcnow()` устарел с Python 3.12
(проект пинит `requires-python = ">=3.12"`). Шум этого класса глушит любые
НОВЫЕ предупреждения — сводка перестаёт работать как сигнал о проблемах.

Факты разведки и панели ревью по живому дереву (main):

- **81 реальный вызов** `datetime.utcnow()`: 26 в `backend/src/` и 55 в
  `backend/tests/` (54 строки — одна строка несёт два вызова:
  `tests/test_password_setup_tokens.py:245`), распределены по 15 тест-файлам.
  Горячие файлы src: `auth/service.py` (11), `usecases/password_setup.py` (4),
  `notify/scenarios.py` (3); крупнейшие тест-файлы: `test_auth_service.py`
  (15), `test_password_setup_tokens.py` (7), `test_auth_otp.py` (5).
- **8 ORM-ссылок вне вызовов (6 строк)** — `utcnow` передан как вызываемое, а
  не вызван (невидим и для счётчика вызовов, и для стража DTZ003, который
  ловит только вызовы): `models/abstract.py:24,27` (базовая модель, 3 ссылки
  — срабатывает на каждой записи каждой строки), `models/master.py:45,48`
  (3 ссылки), `models/audit_log.py:30`, `auth/password_setup.py:60`.
  SQLAlchemy вызывает их при каждом INSERT/UPDATE — вероятно, это главный
  источник умножения предупреждений.
- **7 проза-упоминаний** (docstring/комментарии): `services/payment.py:182`
  (докстринг — из-за скобок попал в строковый счётчик, вызовом не является),
  `notify/journal.py:22,91`, `src/seed/seed.py:141`,
  `tests/test_notify_journal_transactional.py:181`,
  `tests/services/test_generic_service_contract.py:341`,
  `tests/services/test_standalone_patch_contract.py:559`.
- Подавления нигде нет: `[tool.pytest.ini_options]` не содержит
  `filterwarnings`, CI гоняет pytest без `-W`-флагов.
- Идиом «сейчас» в проекте **четыре**: (1) наивный `utcnow()` — 81 вызов;
  (2) осведомлённый `now(UTC)` — 12 мест в src (7 пишут в колонки БД, 3
  собирают Z-суффиксные строки, 2 — источники/конвертации в
  `notify/dispatcher.py`) плюс миграция `alembic/versions/dc47abd1ad2d_…py:48`
  (бэкфилл); (3) наивный локальный `now()` — 4 вызова в одном тест-файле;
  (4) наивное **бизнес-настенное** время `business_now()` из
  `src/notify/time.py` (#482, `now(ZoneInfo(BUSINESS_TIMEZONE))` без зоны) —
  легитимно живёт своей жизнью для сравнений с `activity.start`.
- Эмпирически проверено (in-memory SQLite, SQLAlchemy 2.0.50): привязка
  осведомлённого значения к обычной колонке `DateTime` молча срезает зону —
  хранимые значения в любом случае наивные, без ошибок и предупреждений.

Решение Gate A (пользователь, 2026-10-23): концепт «волна миграции с
сохранением наивного времени». Осведомлённое (timezone-aware) время и
часовые пояса — отдельная задача #498 (бизнес-функции); эта волна семантику
не меняет и #498 не блокирует, а готовит (см. п. 1).

## Решение

1. **Помощник** — новый модуль `backend/src/util/utc.py` (в `src/util/`
   сегодня живут только `__init__.py` и `file_type.py`; имя `utc.py`, а не
   `time.py` — чтобы не дублировать имя существующего `src/notify/time.py` с
   похожей, но другой семантикой):

   ```python
   from datetime import UTC, datetime


   def utc_now() -> datetime:
       """Наивное UTC-«сейчас»: мгновение UTC без tzinfo.

       Для мгновений (TTL, отметки создания/обновления, журнал, аудит).
       НЕ для настенного времени расписания: там своё время —
       src/notify/time.py::business_now() (бизнес-зона, тоже наивное).
       Осведомлённое время и пояса — #498; до него значения наивные.
       """
       return datetime.now(UTC).replace(tzinfo=None)
   ```

   В докстринге `notify/time.py` добавляется перекрёстная ссылка на
   `utc_now()` (и наоборот — уже выше), чтобы пару помощников нельзя было
   молча перепутать.

2. **Механическая замена всех 81 вызова** `datetime.utcnow()` → `utc_now()`
   (импорт по месту, стиль импортов соседних модулей). Замена пословная — по
   вхождениям, не по строкам: в `tests/test_password_setup_tokens.py:245`
   два вызова на одной строке. Семантика идентична: `utcnow()` и
   `now(UTC).replace(tzinfo=None)` возвращают одно и то же наивное
   UTC-мгновение.

3. **ORM-ссылки (главный источник шума)** — 8 ссылок на 6 строках из
   Контекста переводятся на того же помощника: `default=utc_now`,
   `onupdate=utc_now` (`models/abstract.py`, `models/master.py`,
   `models/audit_log.py`, `auth/password_setup.py`; замена по вхождениям —
   в `abstract.py:27` и `master.py:48` по две ссылки на строке). Значения
   идентичны; без этого пункта цель «предупреждений класса — 0»
   недостижима, а страж этого класса ссылок не видит (DTZ003 ловит только
   вызовы) — полнота держится инвентарём в этой спеке и ревью волны.

4. **Нормализация смешанного стиля на того же помощника** (единая точка
   наивного UTC-«сейчас»; хранимые/вычисляемые значения идентичны — зона при
   записи в SQLite срезается, см. Контекст):

   - 7 записей `record.updated_at = datetime.now(UTC)`:
     `src/domain/record_visits.py:50,79`, `src/services/visit.py:252,308,371`,
     `src/services/record.py:569,618` → `utc_now()`.
   - Источник порога чистки в `src/notify/dispatcher.py:250`:
     `datetime.now(UTC).replace(tzinfo=None) - timedelta(...)` →
     `utc_now() - timedelta(...)` (тот же результат одной строкой).
   - 4 вызова `datetime.now()` без зоны в
     `tests/test_location_short_title.py:49,50,65,66` → `utc_now()`. Это
     нормализация, а не эквивалентная замена: сегодня значения наивные
     локальные, станут наивными UTC. CI-контейнеры держат TZ=UTC (сдвига
     нет), ассерты файла сравнивают не часы — значения декоративны.

   **Остаются осведомлёнными осознанно** (aware нужен по назначению):
   `notify/dispatcher.py:121`, `notify/scenarios.py:63`,
   `notify/snapshots.py:45` — сборка Z-суффиксных строк для полезных
   нагрузок оповещений (`now(UTC).isoformat().replace("+00:00", "Z")`);
   `notify/dispatcher.py:129` — конвертация входного осведомлённого значения
   в наивное (`parsed.astimezone(UTC).replace(tzinfo=None)`);
   `alembic/versions/dc47abd1ad2d_…py:48` — осведомлённый бэкфилл миграции.

   **Остается наивным бизнес-настенным осознанно**:
   `src/notify/time.py::business_now()` (#482) — сравнения с плавающим
   `activity.start` (GH #142); не трогаем, докстринги обоих помощников
   перекрёстно связаны (п. 1).

5. **Гигиена проза-упоминаний**: волна подметает за собой — все 7 упоминаний
   из Контекста переписываются на `utc_now()`, чтобы не оставлять лживых
   документаций. Критерий чистоты: `grep -rn 'datetime\.utcnow' src tests`
   → 0 после волны.

6. **Страж** — механизм волн #306. Две части в двух разных файлах:

   - `backend/pyproject.toml`, `[tool.ruff.lint]` select: добавить
     `"DTZ003"` (ловит вызовы `utcnow`) и `"DTZ005"` (ловит `now()` без
     зоны).
   - `backend/scripts/lint_budget.py`, словарь-константа `RUFF_BUDGET`
     (строка ~97): `"DTZ003": 0`, `"DTZ005": 0`. Бюджеты — литеральные
     константы в скрипте (CI перечитывает пороги из базовой версии самого
     скрипта через merge-base, AST-парсинг; pyproject для этого механизма
     ничего не значит). Новые нулевые ключи проходят проверку роста
     (`0 > 0` — ложь).
   - **Атомарность**: замена волны, select и бюджетные ключи приезжают ОДНИМ
     PR (select без волны = факт 81 против порога 0 → красный промежуточный
     CI).
   - Проверено на живом дереве: ruff 0.15.14 `--select DTZ003` находит 81
     (совпадает с числом вызовов: докстринг не считается, двойной вызов на
     строке считается дважды), `--select DTZ005` — 4; контур рахета
     `src tests scripts` покрывает все замены.
   - `DTZ001` (конструктор `datetime(...)` без tzinfo, 90 мест) в страж НЕ
     входит: наивные литералы легитимны — сид с фиксированной неделей
     (`src/seed/seed.py`, `FUNC_WEEK_START = datetime(2026, 6, 1)`), плавающее
     настенное время расписания (GH #142).

7. **pytest-конфиг не меняется**: ничего не подавляем — предупреждения
   этого класса исчезают вместе с вызовами, новые классы остаются видимыми.

## Границы (что мы сознательно НЕ делаем)

- НЕ вводим осведомлённое время — ни в Python-слое, ни в контракте API, ни
  в хранении: территория #498 (решение пользователя на Gate A #529).
- НЕ меняем формат хранения SQLite, генерируемый канон-сид
  `backend/test_memo.db.canon.sql` (генерится из литералов, utcnow не
  содержит), сиды, визуальные базлайны, значения TTL сессий/кодов/токенов.
- НЕ нормализуем осведомлённый `now(UTC)` в тестах (~60+ мест: фабрики
  conftest, сборка ISO-строк для API) — нормализация src-scoped; осведомлённая
  арифметика в тестах не депрекейтед и предупреждений не порождает.
- НЕ включаем `DTZ001` в страж и не трогаем наивные литералы сидов и
  расписания.
- Страж НЕ ловит: инлайновую идиому `now(UTC).replace(tzinfo=None)` в новом
  коде и ссылки-без-вызова (`default=…`) — принятый остаточный риск
  (последнее закрывается инвентарём п. 3 и ревью).
- НЕ разбираем другие классы предупреждений полного прогона: если после
  волны сводка покажет значимые остатки — отдельная задача по факту.

## User Scenarios

- **US-1. Разработчик запускает полный backend-прогон и видит чистую
  сводку предупреждений**: класса datetime-устаревания больше нет (было
  ~74 303, стало 0), новые предупреждения заметны. Проверка: полный
  `uv run pytest -q` зелёный, в warnings summary нет записей класса
  `DeprecationWarning: ...utcnow()...` — вызовы И ORM-ссылки заменены
  (п. 2–3). E2E-якорь: полный backend-прогон в CI.
- **US-2. Разработчик случайно возвращает `utcnow()` в новый код — CI
  падает на страже**: рахет DTZ003=0/DTZ005=0 в `lint_budget.py` красный,
  PR не проходит. Проверка: локально
  `uv run python scripts/lint_budget.py` красный при подсунутом нарушении.
  E2E-якорь: CI-джоба lint-budget.
- **US-3. Пользователь системы (админ, клиент) не замечает ничего**:
  сессии, одноразовые коды, ссылки-приглашения, отметки «создано/обновлено»,
  журнал работают с теми же значениями — замена эквивалентна до микросекунды
  (единственная нормализация с видимой дельтой — 4 декоративных вызова в
  одном тест-файле, п. 4, вне продакшн-поведения). Проверка: существующие
  e2e-сюжеты авторизации, расписания, журнала проходят без правок фикстур и
  ожиданий. E2E-якорь: regression-прогон e2e-шардов.

## Behavioral Delta

- **Для пользователя: ничего не меняется.** Все значения времени
  (TTL, отметки, journal, audit) идентичны — замена механически эквивалентна.
- **Для разработчика: до** — ~74 303 предупреждения одного класса глушат
  сводку полного прогона, идиома «сейчас» размазана по четырём стилям,
  возврат устаревшего вызова ничем не ловится; **после** — сводка чиста от
  класса, в src единая точка наивного UTC-«сейчас» `utc_now()` (рядом
  осознанно живут `business_now()` — бизнес-зона — и перечисленные
  aware-исключения), страж в CI запрещает возврат `utcnow()` и наивный
  локальный `now()`.

## Тестирование и страж

- Юнит-тест самого помощника (чистый, без БД, маркер `pure_unit` если он
  применяется к таким тестам): `utc_now()` возвращает наивное значение
  (`tzinfo is None`), совпадающее с UTC-мгновением в допуске пары секунд —
  фиксирует конвенцию, на которой стоит вся волна.
- `grep -rn 'datetime\.utcnow' src tests` → 0 (вызовы, ORM-ссылки и
  проза-упоминания закрыты п. 2, 3, 5).
- Полный backend-прогон зелёный, в сводке предупреждений нет записей класса
  (локально и в CI) — включая пути ORM-дефолтов (п. 3).
- `uv run python scripts/lint_budget.py` зелёный с бюджетами DTZ003=0,
  DTZ005=0; при подсунутом новом `utcnow()` — красный.
- Существующие юнит-тесты auth/OTP/токенов (TTL-арифметика, сравнения
  с колонками) проходят без правок ожиданий — замена не меняет значения.
- e2e regression (шарды) зелёные без правок фикстур: канон-сид и значения
  не менялись.
