## Контекст

Зонтичная задача #535 собирает e2e-флейки одного класса: тест делает «снимок»
строк таблицы (`allTextContents()` / `rows.all()` с последующими чтениями по
замороженным элементам) и ассертит по нему — а React в этот момент ещё
допечатывает таблицу, элемент отрывается от DOM, ассерт падает «element(s)
not found», автоповтор проходит, блокирующий флейк-гейт краснит джобу
(`docs/tests_workflow.md`: ≥1 flaky → красный).

Записанные проявления:

- **records.spec.ts, тест 25 (US-5 #412)** — 3× FLAKY 20–21.10;
  сигнатура `toContainText('Анна')` element-not-found. Закрыто подсабмитом
  PR #515 (коммит 3b2767c3): settle `toHaveCount(2, 20s)` перед `rows.all()`.
  Смежный тикет #537 на этот же сайт закрыт 24.10 авто-дизайном как
  уже-покрытое этим же подсабмитом — премисса «свести #537 в один заход»
  снята (комментарий в #535 от 25.10).
- **records.spec.ts, тест 12 (Pagination)** — FLAKY 23.10 на PR #546
  **уже поверх** гвардов из #515: poll «имена ушли с подписи страницы 1»
  (строки :491–497) прошёл, а сырые дочитывания после него (:500–506) — нет.
  Урок: негативный сеттл («стало не как раньше») не гарантирует, что таблица
  дошла до терминального состояния.
- **dayview-column-reorder.spec.ts, тест 2 (:163)** — FLAKY 23.10 на PR #542
  с новой сигнатурой: после первого `ArrowLeft` библиотека перетаскивания
  (dnd-kit) разрешила столкновение в «колонка над собой» — перемещение не
  состоялось, служебное смещение (transform) не появилось, тест ждал его 5 с
  и упал. Читающая сторона тут не при чём: сбой на стороне ввода.
  Transform-poll-гварды из PR #523 (:103–109) стоят и не спасают — они ждут
  признак, который в этом состоянии вообще не наступает.

Диагноз: точечные гварды держат свой конкретный ассерт, а класс продолжает
рождать падения по соседству. Решение пользователя (Gate A, 2026-10-25) —
системное: структурно исключить сам приём, а не лечить сайты по одному.

Активная поверхность класса по разведке: 15 сайтов — 11 в records.spec.ts
(тесты 6, 7, 11, 12, 16, 17, 18, 19, 24, 25, `readServerTotal`), по одному
массиву в photos-crud.spec.ts (:224–227) и master-role-payments.spec.ts
(:80–84, плюс одноразовые чтения бейджей :107/:130/:148 того же семейства).
Безопасный класс автоповторяющихся ассертов (`toHaveText`/`toBeVisible` на
локаторах, ~30 сайтов) классом НЕ является и не мигрирует.

### Посылка детерминизма (проверена по инфраструктуре, панель 25.10)

Таблица в момент теста = канонический сид + собственные фабрики теста,
и ничего больше:

- `playwright.config.ts:74` — `workers: 1`;
- `e2e/fixtures/test.ts` — авто-фикстура `seedReset` (scope: test) бросает
  исключение при `workers > 1` и выполняет `resetToSeed()` перед КАЖДЫМ
  тестом, включая ретраи;
- фикс. неделя сида (#422, `FUNC_WEEK_START=2026-06-01`), UUID-сид (#491).

Следствие: точные ожидаемые массивы строк выводимы из сида и фабрик.
Комментарии в тестах 16/17 о «parallel worker's record» (:669–672,
:722–725) датированы 2026-08-14 (PR #191) — эпоха до пер-тестового сброса;
при конверсии они обновляются. Толерантные ассерты (`>=`, `—` в перечислимом
множестве) — до-детерминированные остатки: где их смысл — отношение, они
сохраняются (в повторяющейся форме); где точность бесплатна — уточняются.

## Решение

### Часть 1. Единый примитив чтения строк — `expectRowsExact`

Новый хелпер в `frontend/admin/e2e/fixtures/helpers.ts` (общий дом
e2e-хелперов, уже импортируется всеми спеками):

```ts
// Поллит тексты ячеек до ТОЧНОГО совпадения с ожидаемой последовательностью
// (позитивный сеттл: ждём терминальное состояние, а не «ушли со старого»).
// Совпадение последовательности неявно проверяет и количество строк.
expectRowsExact(cells: Locator, expected: string[], opts?: { timeout?: number })
```

Контракт:

- `cells` — локатор колонки текста (например
  `page.locator('tbody tr td:nth-child(2)')`); хелпер поллит
  `allTextContents()`, нормализует обе стороны (trim + схлопывание пробелов,
  включая NBSP и типографские пробелы в ценах вида «1 500 ₽») и требует
  точного равенства массиву `expected` — порядок значим; пустой `expected`
  легален (пустое состояние, US-3).
- Таймаут по умолчанию 10_000 мс, переопределяется опцией (за тестом 25
  сохраняется бюджет 20_000 — правка #515 не ослабляется).
- Это и есть ассерт: семантика `expect`-полла, автоповтор встроен.
- **Посылка применимости** (см. выше): ожидаемый массив выводим из сида +
  собственных фабрик теста; `expected` вычисляется из сида/фабрик
  переменными, не хардкодом литералов.

Двухуровневый контракт конверсий — уровень выбирает сайт, не implements:

- **Уровень «точный»** — смысл проверки СОДЕРЖАНИЕ и состав строк
  детерминирован: `expectRowsExact` точного массива (тест 25 — эталон;
  тест 12; тесты 6/18/24; тест 11; photos-crud).
- **Уровень «реляционный»** — смысл проверки ОТНОШЕНИЕ или одиночная
  ячейка: сохраняем семантику, переводим в повторяющуюся форму —
  `expect.poll` отношения (`resetTotal >= filteredTotal`), локаторные
  автоповторяющиеся ассерты на конкретной ячейке/строке
  (`expect(row.locator('td').nth(8)).toHaveText(...)`). Запрет класса
  касается замороженных снимков, а не реляционной семантики.

Сопутствующие конверсии:

- скалярные разовые чтения `readServerTotal` (records.spec.ts:41–45):
  там, где значение детерминировано и проверяется по смыслу точно —
  `expect.poll(() => readServerTotal(...))` до точного значения (паттерн
  :1085); в тесте 7 — реляционный уровень, чтения для отношения становятся
  settled-чтениями;
- перечисления бейджей/ячеек после сеттла — на локаторные
  автоповторяющиеся ассерты (`toHaveAttribute`/`toHaveText` на
  `row.locator(...)`), без замороженных снимков `rows.all()`;
- **запрещённый приём сформулирован точно**: «снимок-потом-ассерт»
  (`allTextContents()`/`rows.all()` с чтениями по замороженным элементам)
  и «негативно-сформулированный сеттл как единственное ожидание перед
  сырым чтением». Это НЕ коллизия с легитимным каноном «Negative waits»
  скилла (ассерты отсутствия, #337) и не запрет transition-поллов между
  двумя позитивными состояниями.

**Аудит-правило для тестов 16/17** (единственный неоднозначный сайт):
комментарии допускают «—» для строк, чья активность ещё не подгружена во
фронтендовый activities-map (снимок состояния, не параллельный воркер —
их больше нет). Аудит в плане выясняет: если «—» — переходное состояние
(карта догружается), сеттл — `expectRowsExact` без «—» (точный); если
«—» может оставаться по дизайну — реляционный уровень: membership-ассерт
`[locationName, '—']).toContain` в локаторной повторяющейся форме. В обоих
случаях замороженный снимок уходит, устаревший комментарий обновляется.

Документирующие комментарии о семействе гонок (#479/#515) в тестах
сохраняются и дополняются ссылкой на хелпер.

### Часть 3. dayview — повтор нажатия при «перемещении-пустышке»

Единственная точка входа `settleMoveLeftThenDrop`
(dayview-column-reorder.spec.ts:100–111, через неё ходят оба клавиатурных
теста: вызовы :152 и :192; гварды активации :149 и :173 оба выигрывают).
Продуктовое поведение не меняется; тест приобретает поведение живого
человека — «нажал, не подвинулось — нажал ещё раз».

**Шаг 0 плана — эмпирическая проба** (по прецеденту «probe-verified» самого
файла): на дев-гриде выполнить клавиатурный drag и зафиксировать (а) точный
узел анонсов dnd-kit и (б) точные строки анонсов установленной версии
библиотеки. Причина: на странице несколько live-регионов (собственный hint
DayView `aria-live="polite"`, toast-контейнер, регион dnd-kit; в
unified-rows.spec.ts:570 регион dnd-kit наблюдался как несколько узлов
`#DndLiveRegion`, первый пуст) — голый локатор `[aria-live]` поймает не
тот элемент. Регулярки по тексту анонсов пишутся ТОЛЬКО по результатам
пробы (строки — английские дефолты dnd-kit, зависят от версии).

**Машина состояний** (нажатия нумеруются; «≤3» считает ТОЛЬКО move-фазы):

1. **Pickup** (без изменений): `Space`, гвард `aria-pressed='true'`.
2. **Move-фаза** (заменяет первое нажатие :101): нажать `ArrowLeft` (попытка
   1 из ≤3) → полл (≤2 с) узла анонсов dnd-kit до сообщения вида «moved
   over droppable Y» с **Y ≠ X** (id перетаскиваемой колонки X фиксируется
   по анонсу pickup из того же узла). Не дождались (последний анонс всё ещё
   называет X или новых нет) → следующая попытка: ещё `ArrowLeft`.
3. **Settle-фаза** (без изменений, :103–109): poll transform `''`, затем
   ВТОРОЕ итоговое нажатие `ArrowLeft` (:106), poll `translate3d(-`.
   Settle-нажатие — отдельное, всегда одно, в лимит ≤3 НЕ входит.
4. **Drop**: `Space` (без изменений).
5. Исчерпаны 3 move-попытки, «пустышка» держится — тест падает с текстом
   узла анонсов в сообщении (диагностируемость рецидива).

Обе гипотезы корня из тикета (несвежие замеры колонок под нагрузкой CI /
потерянный первый ивент) лечатся одним повтором нажатия, поэтому гвард
вводится сейчас, без ожидания рецидива для доказательства корня.

## Границы (что мы сознательно НЕ делаем)

- **Без CI-сторожа** на сырые чтения — решение пользователя 2026-10-25;

- **Без тотальной миграции** ~30 безопасных автоповторяющихся сеттлов

  записанного флейка не трогаем.
- **Одноразовые чтения того же семейства вне записанных флейков остаются
  вне охвата до первого зафиксированного флейка** (правило границы):

- **Продуктовый код не трогается** (0 строк): dayview-лечение — на стороне

- **Без инфляции бюджетов**: таймауты по сайтам сохраняются (20 с за

## User Scenarios

- **US-1. Разработчик открывает старую ссылку с фильтрами (US-5 #412) —
  таблица ассертится в терминальном состоянии**: тест 25 records.spec.ts
  ждёт точных двух имён из сида, пер-ячейковые проверки локаторные; гонка
  «снимок до долива» исключена. E2E-якорь: тест 25.
- **US-2. Разработчик листает записи на страницу 2**: чтения страницы 1 и
  страницы 2 — точные сэттлы их подписей, серверный тотал поллится до
  точного значения. E2E-якорь: тест 12.
- **US-3. Фильтры (местоположение/услуга/составные), сброс и пустое
  состояние**: перечисления строк после мутаций — через хелпер или
  повторяющиеся реляционные формы, без снимков. E2E-якорь: тесты 6, 7, 11,
  16, 17, 18, 19, 24.
- **US-4. Клавиатурная перестановка колонок dayview переживает
  «пустышку»**: если move-нажатие не сдвинуло перетаскивание, тест
  повторяет его (≤3 move-попыток) вместо смерти по таймауту; settle-фаза и
  конечные проверки (порядок колонок после перезагрузки) без изменений.
  E2E-якорь: тест 2 dayview-column-reorder.spec.ts.
- **US-5. Автор нового e2e-теста не может незаметно вернуть сырой снимок**:
  скилл тест-писателей объявляет приём запрещённым с примером хелпера.
  E2E-якорь: секция скилла «Waiting & Time Discipline» + запись в Common
  Mistakes; в PR-диффе этого issue — ни одного нового сырого чтения.

## Behavioral Delta

- **Для пользователя продукта: ничего не меняется** — продуктовый код не
  трогается.
- **Для разработчика: до** — случайные красные первые прогоны e2e (3
  записи за 20–23.10, каждая блокировала мерж случайного PR), класс
  отрастал новыми сайтами поверх каждого точечного гварда, новый тест мог
  тихо родиться с той же миной; **после** — чтение строк таблиц
  структурно идёт либо через точный сэттл терминального состояния, либо
  через повторяющиеся реляционные/локаторные формы (замороженных снимков
  нет), канон скилла направляет авторов новых тестов, dayview-тест сам
  повторяет «застрявшее» нажатие, а сообщение его фейла несёт текст узла
  анонсов для диагностики.
