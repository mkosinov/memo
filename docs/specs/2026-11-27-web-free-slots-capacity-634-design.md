# Спека: свободные места и вместимость в карточке занятия + ограничение счётчика брони (web)

- Дата: 2026-11-27 · Задача: [#634](https://github.com/mkosinov/memo/issues/634) (milestone v1, `app:web`)
- depends-on: — (#551 «вместимость», #538 «локализация ошибок брони», #600/#601 «публичный API» уже смержены)
- Гейт A (26.11, решение юзера): при нуле свободных мест вход в форму брони закрыт — кнопка «Участвовать» в детальном окне неактивна, форму открыть нельзя.

## 1. Скоуп

Клиент публичного сайта открывает карточку занятия в расписании и видит, сколько мест свободно и какова общая вместимость: «Свободно 2 из 10». Если свободных мест нет — карточка показывает «Мест нет»; сюда же попадает закрытая запись (вместимость 0 — владелец «задал нулём», #551). Карточку из списка не прячем.

Форма бронирования ограничивает счётчики гостей свободными местами: сумма счётчиков по тарифам не может превысить остаток. Ограничивается именно сумма, а не каждый счётчик по отдельности — иначе два тарифа по 3 при 3 свободных местах дают 6.

Только web, без правок бэкенда и контракта API. Остаточная гонка (последнее место заняли, пока форма была открыта) остаётся и закрывается серверным отказом 409 «Недостаточно мест» — локализация готова в #538.

Границы из задачи: никаких подсказок «останется после вашей брони» и прогнозов по тарифам — только факт «свободно N из M» / «Мест нет».

## 2. Текущее состояние (рекон 26.11, вердикт actual)

Данные уже доходят до клиента, но обрезаются на экранной модели:

- `GET /api/v1/public/activities` отдаёт на каждое занятие `capacity` (вместимость, 0..99) и `occupied` (занято — сумма мест по активным записям, тот же расчёт, что в списке персонала).
- web хранит оба числа в DTO расписания (`buildSchedule`), но при переходе к экранной модели вместимость отбрасывается: до карточки и оверлеев доходит только «занято» (`guestsCount`). Протяжка `capacity` до экранной модели — часть работы.

Проводка экранов: карточка занятия → кнопка «Подробнее» (или тап по заголовку) → детальное окно (`ActivityDetail`, подвал — кнопка «Участвовать») → форма брони (`BookingActivityOverlay`: счётчик на каждый тариф, либо один счётчик «Места», если у услуги нет тарифов; отправка — «Записаться»). Других входов в форму брони от карточки занятия нет.

- Потолок каждого счётчика сегодня — проп по умолчанию `max = 99` (`Counter`; форма его не переопределяет), связи между счётчиками нет; отправка невозможна при нуле гостей (`totalCount > 0`). Значение вводится только кнопками −/+: поля ручного ввода числа в счётчике нет.
- При открытии формы сбрасываются только шаг флоу и состояние отправки; счётчики, посетители, контактные поля и валидность живут между открытиями и сменой занятия (нынешнее поведение — см. §3.4, правило меняется).
- Отказ 409 `ACTIVITY_AT_CAPACITY` («Недостаточно мест») приходит с сервера уже на русском и проходится насквозь в web (#538); словарь web-ошибок кода вместимости сознательно не содержит.
- Статичная карточка «Индивидуальный мастер-класс» (внизу расписания; запись на кастомное время, без занятия и вместимости) — вне скоупа, правила её не касаются.
- Приватные занятия (`is_private`) на публичном расписании не существуют: сервер исключает их из списка, а попытка записи на приватное занятие даёт 404 (#600) — правила этой спеки их не затрагивают. (e2e-фикстура «Индивидуальный МК» временно снимает флаг приватности у сида — приём тестовой инфраструктуры, не продукт.)

Существующее решение, которое пересматривается: спека #551 (рев. 4) специально не показывала на карточке закрытого занятия никакого значка — клиент проходил весь путь брони и получал отказ от сервера на отправке (это закреплено её e2e-тестом `booking-closed-activity.spec.ts`). #634 (текст новее, решение 24.11.2026) вводит «Мест нет» на карточке — это осознанная ревизия. Тест переписывается (§6); серверное покрытие 409 остаётся в e2e #538 (гонка) и бэкенд-тестах.

Инфраструктура проверок: web-e2e не входит в CI (#637, открыта) — прогоны локальные (`pnpm test:e2e` в `frontend/web`). Обычные карточки сида живут в фиксированных неделях (май–июнь 2026), поэтому на корневой странице «на сегодня» визуальный раннер их не видит; диплинка расписания по дате нет.

## 3. Решения дизайна

1. Термины: вместимость `M` — сколько мест отвёл владелец (0..99); занято — сумма мест активных записей; свободно `F = M − занято` (защитно не меньше 0).
2. Карточка занятия: строку «Уже N гостя/гостей» заменяет строка состояния:
   - `F > 0` → «Свободно F из M»;
   - `F = 0` (включая `M = 0`) → «Мест нет».
   Микро-решение спеки: замена, а не вторая строка — «занято» читается из пары «F из M», две строки перегружают маленькую карточку.
3. Детальное окно: при `F = 0` кнопка «Участвовать» неактивна, рядом подпись «Мест нет»; фото и описание остаются доступными. Форма брони не открывается — решение гейта A: клиент не попадает в тупиковую форму, где нельзя ничего выбрать. Второй слой защиты: обработчик «Участвовать» на странице при `F = 0` форму тоже не открывает (кнопка — первичный слой, обработчик — дублирующий). Семантика неактивности (нативный `disabled` или `aria-disabled` с видимой причиной) — решение плана; причина «Мест нет» видима рядом с кнопкой в любом варианте.
4. Форма брони: инвариант «сумма счётчиков ≤ F»:
   - потолок каждого счётчика = `F − сумма остальных счётчиков` (реактивно: заняли бюджет другим счётчиком — потолок этого падает); значение вводится кнопками −/+ («+» гаснет на потолке), поля ручного ввода в счётчике нет и не появляется;
   - форма полностью сбрасывается при открытии и при смене занятия: счётчики, посетители, контактные поля, валидность (сейчас сбрасывается только шаг флоу — правило расширяется);
   - при `F > 0` форма работает как сегодня, сервер не трогаем.
5. Данные: `capacity` протягивается из DTO расписания в экранную модель — в модель карточки (`ScheduleView`/`ScheduleCardView`) и в `ActivityView` (детальное окно и форма читают остаток из тех же `activities`); свободное `F` вычисляется в мапперах экранной модели как готовое к рендеру значение (канон web: производные значения живут в маппере, UI только рендерит). Если `capacity` не пришло — карточка показывает прежнюю строку «Уже N гостя/гостей» и ограничений нет (старое поведение как деградация данных; заодно защищает существующие тесты с `mockActivity` без вместимости и исключает «Свободно NaN»).
6. Свежесть: остаток фиксируется данными страницы на момент загрузки и при открытой форме не обновляется — исчерпание мест за время заполнения ловит серверный 409 (US-5, остаточная гонка по условию задачи). Автообновление и перезапрос после 409 — вне скоупа.

## 4. Behavioral Delta

| Было | Стало |
|---|---|
| Карточка: «Уже 3 гостя» | «Свободно 7 из 10»; при исчерпании — «Мест нет» |
| Карточка закрытого занятия (M=0): выглядит как обычная | «Мест нет»; в детальном окне «Участвовать» неактивна |
| Форма брони открыта с любой карточки | При исчерпании мест форма не открывается |
| Счётчики: каждый до 99, независимо | Сумма счётчиков ≤ свободных мест; потолок каждого реактивный |
| Счётчики и контакты живут между открытиями формы | Форма полностью сбрасывается при открытии и смене занятия |
| Перебор доезжает до сервера и падает 409 | Перебор отсечён в форме; 409 остаётся только для гонки |
| Сервер, контракт API, прочие экраны | Без изменений |

Не меняется: свежесть данных расписания (остаток считается на момент загрузки страницы, автообновления нет — гонка закрывается 409), анонимный флоу брони (шаг авторизации), карточки не прячутся из списка.

## 5. User Scenarios

- **US-1. Видит остаток на карточке.** Клиент открывает расписание — карточка занятия показывает «Свободно F из M» вместо «Уже N гостя/гостей»; вычитание проверяется на середине диапазона, не только на краях. E2E: активность на завтра, вместимость 10, 3 места занято заранее → на вкладке «Завтра» текст карточки «Свободно 7 из 10».
- **US-2. Закрытое занятие (вместимость 0).** Карточка показывает «Мест нет»; «Подробнее» открывает детальное окно; «Участвовать» неактивна и форма брони не открывается (главный ассерт); запроса на запись не возникает и записи в БД нет (дополнительные ассерты). E2E: переписанный `booking-closed-activity.spec.ts`.
- **US-3. Все места заняты.** Вместимость 1, единственное место занято заранее → карточка «Мест нет» (тот же стейт из другой причины). E2E: сценарий в новом spec-файле свободных мест.
- **US-4. Сумма счётчиков ограничена.** Вместимость 3, услуга с двумя тарифами: набрав 2 + 1, «+» гаснет на обоих счётчиках; отправка при сумме 3 успешна. E2E: сценарий в новом spec-файле + компонентные тесты vitest (реактивные потолки, один счётчик «Места» при услуге без тарифов, сброс формы).
- **US-5. Гонка — места кончились при открытой форме.** Отправка падает 409, экран показывает «Недостаточно мест» и «Отправить еще раз». Покрыт e2e #538 (`booking-error-l10n.spec.ts`, US-1) — но его нынешний второй акт повторно открывает форму свежей загрузкой страницы на исчерпанном занятии, что после этой спеки невозможно («Участвовать» неактивна при `F = 0`). Акт перестраивается: форма остаётся открытой, конкурентная бронь уносит последнее место через API, отправка → 409 (честная имитация гонки).

## 6. Тесты

- Новый e2e `frontend/web/e2e/free-slots-capacity.spec.ts`: US-1 (вместимость 10 задаётся явно — дефолт фикстуры 8), US-3, US-4.
- Переписанный `booking-closed-activity.spec.ts`: US-2 — главный ассерт «Участвовать» неактивна и форма не открылась; отсутствие POST и записи в БД — дополнительные.
- Vitest `BookingOverlay.test.tsx`: реактивные потолки счётчиков, один счётчик «Места» (услуга без тарифов) тоже ограничен, полный сброс формы при открытии и смене занятия — US-4.
- Перестроенный US-1 в `booking-error-l10n.spec.ts` (#538): гонка имитируется конкурентной бронью через API при открытой форме — без перезагрузки исчерпанного занятия (US-5); словарная проверка текста 409 сохраняется.
- Фикстуры e2e не зависят от сида: для US-4 тестовая услуга с двумя тарифами создаётся (или выбирается явным условием «≥2 тарифов»), а не берётся «первая из сида».
- Компонентные тесты со старой строкой «Уже N гостя/гостей» обновляются под новую строку состояния (и под деградацию «capacity не пришло» → старая строка): `MKCard.test.tsx`, `page.test.tsx`, `MKCarousel.test.tsx`.
- CI: web-e2e выполняется локально до закрытия #637 (риск-акцептанс записан); DoD сценариев проверяется локальными прогонами `pnpm test:e2e`.

## Visual Compliance Checks

Машинная проверка раннера — одна, на статически достижимом элементе страницы расписания (якорь загрузки страницы): обычные карточки занятий попадают в окно расписания лишь в фиксированные недели сида (май–июнь 2026) и раннеру недостижимы, диплинка по дате нет. Состояния «Свободно N из M» / «Мест нет» и блокировки живут на этих карточках и в интерактивных флоу (детальное окно, форма) — они покрыты web-e2e US-1–US-4 (те же элементы и тексты) и поверх — ручной проверкой:

- [ ] карточка "Индивидуальный мастер-класс" на странице расписания — рендерится при загрузке страницы и несёт `data-testid="activity-card"` (машинный якорь страницы) url="/"
- [ ] карточка занятия в окне расписания — показывает строку "Свободно 7 из 10" вместо строки "Уже N гостя/гостей" — web-e2e US-1 + ручная проверка
- [ ] карточка занятия при исчерпании мест — показывает "Мест нет", кнопка "Подробнее" остаётся активной — web-e2e US-2/US-3
- [ ] детальное окно занятия при исчерпании мест — кнопка "Участвовать" неактивна, подпись "Мест нет", форма брони не открывается — web-e2e US-2
- [ ] форма брони — сумма счётчиков по тарифам не превышает свободных мест — web-e2e US-4 + vitest

## 7. Не делаем

- Подсказки «останется после вашей брони», прогнозы остатка по тарифам.
- Правки бэкенда и контракта API (включая код в словаре web-ошибок — pass-through #538 сохраняется).
- Сокрытие карточек из списка; автообновление остатка при открытой форме.
- Правки статичной карточки «Индивидуальный мастер-класс» (запись вне расписания).
- Правки визуального раннера/сида ради достижимости карточек (грамматика клика/диплинков — отдельная задача #602).
