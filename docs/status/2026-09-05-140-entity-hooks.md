- **/clients migration:** page-scoped `filters` + `defaultSort` via factory; mutations via `useClientsMutations` (per-action hooks); modal per-tab progressive client resolution via point hook `useClient(id)` (+ new `ClientLabelById.tsx`); clients list fetches only on `/clients`.
- **api-client:** dead `getClients` (`per_page=100`) deleted.
- **Surfaces/contexts migrated:** records/schedule/photos surfaces + Locations/Masters/Materials/Services/Tags/Records/Schedule/Photos dict contexts → hooks + `qk` keys; photos components onto raw dict hooks.
- **Staleness fix (US-6):** `useRecordMutations` quick-add `createClient` branch invalidates `qk.clients` (existing-client branch does NOT) → new clients visible immediately in /clients.
- **Dict staleTime unified:** all dict hooks (raw AND lookup — shared keys) aligned on `DICT_STALE_TIME = 1h` (was 5 min vs `Infinity` split).

## Architectural Notes
- **Why thin hooks + central `qk` registry:** consistent dedupe/invalidation — one key shape, one source; call sites get a stable typed API. Framing: as of 2026 TanStack guidance leans toward `queryOptions` factories; this codebase deliberately standardizes on the hook + `qk` model instead (documented in ARCHITECTURE.md as team governance, not oversight).
- **Lookup/`Raw` shared-key invariant:** a lookup and its `Raw` sibling share the same key so they dedupe; shared-key observers take the most pessimistic `staleTime`, so one aligned value per key is the only sound end-state.
- **No-external-invalidation assumption:** no WebSocket/SSE/polling; cache freshness rests entirely on invalidations from the client's own mutations (prefix-invalidation breadth, e.g. client mutations invalidating the whole `['records']` prefix because records rows carry denormalized client name/phone).
