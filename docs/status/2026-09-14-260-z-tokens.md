## Summary of Changes
- **Token block (the only place with raw z-numbers):** `frontend/admin/app/globals.css` — old z-order documentation comment replaced by a `:root` block of 16 tokens (`--z-base` 10 … `--z-toast` 250). Contract: classes use `z-[var(--z-*)])`, inline styles use `zIndex: 'var(--z-*)'` (resolved at computed-value time, so `getComputedStyle` returns a number).
- **The bug fixed:** stack badge in `DayColumn` `z-[110]` → `--z-badge` (**26**) — above cards (25, top of the `25−z` depth model) but below sidebar (30) and panels (50); it no longer paints over the topbar/zoom popover or sidebar.
- **Migration (no renumbering beyond the badge):** ~30 components across schedule (`DayColumn`, `DayView`, `WeekView`, `NowLine`, `TimeColumn`, `ScheduleColumnHeader`, `OverlapPopover`, `ActivityCard`), layout (`Menubar`, `Topbar`, `Toolbar`, `StampFab`), shared (`Combobox`, `ColumnPicker`, `DataTable`, `CalendarPopover`, `FilterDropdown`, `MultiSelect`, `RemoteSearchSelect`, `MonthYearPicker`, `StatusFiltersPicker`, `StatusPicker`) and overlays (`DeleteDialog`, `ArchiveStaffDialog`, `ActivityDetailsModal`, `ToastContainer`, modals). DayColumn's `25−z` card-depth model is left untouched (spec §3.3 exception — arithmetic, no literal).
- **Blocking CI guard:** `scripts/check_z_tokens.py` scans `frontend/admin/app/**/*.{ts,tsx}` (skips `__tests__` / `*.test.*`) for bare `z-N`, `z-[N]` and numeric `zIndex: N`; wired into the `frontend-checks` job of `.github/workflows/test.yml`. Local run: 127 files / 0 violations; negative self-check (temporary `z-[999]`) confirmed file:line report and exit 1.
- **e2e guards:** new `frontend/admin/e2e/schedule-z-layering.spec.ts` (S1–S3, computed-z pairs within the root stacking context); existing `wave5-x-cards-blurred.spec.ts` stays green unedited. e2e selectors were moved off z-classes to testids (migration-proof): `records.spec.ts` `.fixed.z-50` → `[data-testid="client-quick-card"]`, topbar testid instead of a z-class selector.
