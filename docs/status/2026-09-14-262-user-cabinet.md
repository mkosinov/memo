## Summary of Changes

- **Backend — `user_profiles` + `GET/PUT /api/v1/my` (`c10ea19`, `532fd7b`):** private half of the
  employee profile in a new table `user_profiles` (1:1 with `users`, lazily created on first save);
  composite service writes staff-card fields (name) + private fields in **one transaction** and emits
  the existing `staff` SSE entity. Flat response `{role, has_staff, has_master, first/last_name,
  avatar_url, specialties, patronymic, birth_date, residence_address, birth_place, passport_*,
  registration_address}`; PUT semantics «omitted = keep, explicit `null` = clear»; `has_staff=false`
  when the card is missing **or archived** (names ignored), `has_master=false` when the master section
  is missing/archived (`specialties` null); `specialties` is read-only (admin owns the master section,
  #266 D5). `require_session` on both routes, `verify_fetch_metadata` on PUT. Public serializers
  (`/masters`, `/staff`) structurally carry no private fields (D3).
- **Backend — portrait (`d678a07`):** `POST /api/v1/my/portrait` — multipart upload with
  `Content-Length` precheck before reading the body, 5 MB cap while streaming, type sniffing via magic
  bytes (JPEG/PNG/WebP; filename not trusted), stored name = UUIDv4 + whitelisted extension; public
  serving via Starlette `StaticFiles` at `/api/v1/files/avatar` (+ `X-Content-Type-Options: nosniff`);
  successful upload rewrites `Staff.avatar_url` and deletes the previous **own** file (external URLs
  untouched); every error path removes the temp file; path-separator names cannot escape the dir.
- **Backend — `change-password` + avatar in `/auth/me` (`31d1776`, `5171573`):**
  `POST /api/v1/auth/change-password` (under session, `current_password` verified first; wrong →
  401 `AUTH_INVALID_CREDENTIALS` with timing parity via `DUMMY_HASH`, policy → 422 `PASSWORD_POLICY`);
  on success the **current session survives**, every other session row of the user is deleted (D6);
  the lockout ladder is untouched. `MasterSnapshot` gained nullable `avatar_url`; the `/auth/me`
  snapshot is assembled from the staff card with the archive-independent display rule.
- **api-client (`a9ce337`):** `getMyProfile` / `updateMyProfile` / `uploadPortrait` (multipart) /
  `changePassword`; `MyProfileSchema` / `MyProfileUpdateSchema` / `ChangePasswordSchema`;
  `MasterSnapshotSchema` += `avatar_url`; `PASSWORD_POLICY_HINT_RU`; backend fixtures regenerated.
- **Admin — theme persistence (`af3a7ae`):** bootstrap inline script in `app/layout.tsx` applies
  `data-theme` from `localStorage["memo-theme"]` **before hydration** (dark reload without a light
  flash); `UIContext.toggleTheme` writes the same key; legacy in-panel slider row removed.
- **Admin — `UserMenu` popup (`9b7624e`, `1131128`):** the bottom-left user block is the trigger for
  an upward popup of exactly 4 items (theme slider, «Мои данные», «Сменить пароль», «Выйти»); WAI-ARIA
  Menu Button pattern (roving tabindex, arrows/Home/End, Escape, Tab closes and returns focus,
  outside-click closes, label-in-name, checked state on the theme radio). Collapsed sidebar gets a
  round avatar trigger. «Выйти» calls the existing `AuthContext` logout helper (no duplicate API call)
  → `/login`. The plate shows avatar + first/last name (including archived card), **no** role label,
  no phone; «Аноним» + initial only when the card has no name (D9).
- **Admin — modals (`1330441`, `c53a7e0`):** `MyDataModal` (role read-only; name*/surname* — public
  half, hidden entirely when `has_staff=false`; specialty read-only row only when `has_master=true`;
  patronymic / birth date via `CalendarPopover` / residence address; «Паспорт» section with the
  disabled placeholder row «Фото первой страницы паспорта — появится позже»; portrait block with
  preview + «Загрузить фото» / «Удалить»; dirty-guard on close; submit → `updateMyProfile` →
  invalidation of `['me']` + `staff`/`masters` families, no new EntityName/SSE entities) and
  `PasswordModal` (3 fields + policy hint; wrong current → inline «Неверный пароль»; success → toast
  «Пароль изменён» without redirect).
- **E2E + infra + baselines (`d9eb32e`):** `cabinet.spec.ts` scenarios S1–S6 (popup + theme
  persistence; password change; name+portrait propagating to plate and «Сотрудники» table with
  read-only specialty; private fields persist + unauthenticated `/my` 401 + `/masters` key-set without
  private fields; logout; no-card user S6). Test-scoped `FILES_DIR` per shard with avatar-dir cleanup
  alongside the DB in `globalSetup`/`seed-reset`/`e2e-shard-start.sh`; `seedUser({noStaffId})` factory;
  `visual-regression.spec.ts` pins `localStorage["memo-theme"]="light"`; `menubar-*` baselines recaptured.
- **Visual-gate fix (`69615fb`):** modal shell natural height + working body scroll (fixed clipping
  found by the vision-verified visual gate).
