## Summary of Changes

- **`loading` toast kind (`ac7883ad`):** `UIContext` — `'loading'` added to `ToastKind`; `showToast`
  starts a hide-timer only for non-loading kinds (a loading toast lives until removed explicitly, no
  60s drift even with fake timers); `showToast` now **returns the id** (was `void`) — back-compatible:
  40+ existing call sites ignore the return value, the hook needs it for `hideToast`. Existing default
  timings (info 4500 / success 5000) untouched.
- **ToastContainer render + D5a (`a0ed3deb`):** explicit `loading` entry in `BORDER_BY_KIND` (same
  neutral border as `info`); no close button; SVG spinner (reused verbatim from the old Topbar chip)
  rendered before the message with `aria-hidden="true"`; D5a limit exemption — regular toasts still cap
  at the last 5, `loading` toasts are always visible and keep their chronological position (stacks like
  the rest, «новые снизу»). Vacuous loading-border test dropped (`e6af3067`).
- **e2e RED first (`3c8cc043`, `71e3a725`):** new `schedule-saving-toast.spec.ts` (shard-schedule
  project via the `schedule*` testMatch — no registration needed) with S1–S5, written **before** the
  hook so all five fail on missing `toast-loading`. Shared helper `delayActivityMutations(page, ms)` in
  `e2e/fixtures/helpers.ts` routes `**/api/v1/activities*`: GETs `route.continue()`, mutations delayed
  ~1.5 s — the «Сохраняем…» window is deterministic. Delay glob widened to activity detail URLs
  (`**/api/v1/activities/**`) so S2 edit-save and S4's 500-override for the create call work.
- **`useSavingToast` hook + chip removal (`253c4ee6`):** `useMutationState` filtered by
  `SCHEDULE_ACTIVITY_MUTATION_KEY`, selects mutation statuses, counts `pending` (covers paused — paused
  mutations stay status `pending`); one toast per batch (id kept in a ref, shown on first in-flight,
  hidden when the count returns to 0 — success or error alike); unmount-cleanup is the only
  ever-toast insurance (kill-timer rejected by the user decision in the spec). `Topbar` calls the hook,
  the chip block is deleted; `isSaving` + `useUnsavedChangesGuard(isSaving)` **stay** — the
  beforeunload guard is intact. Non-vacuous unmount-cleanup test (`7859b125`).
- **Deliberately unchanged:** result toasts (texts/timings), toast behavior outside the schedule, and
  the local create-modal button lock from #258/#259 (`onSavingChange` intentionally coexists with the
  global toast — different layers, spec §9).
