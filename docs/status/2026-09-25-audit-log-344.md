## Goal

Каждое законченное действие пользователя над данными оставляет атомарную append-only запись в журнале, а администратор видит историю в новом разделе «Журнал» (`/audit`) с фильтрами по автору/действию/сущности/периоду. Механика записи — сквозная, зеркалит аккумулятор событий #239; контракт #239 не меняется (инвариант доказан тестами без правок).

## Summary of Changes (per task)

- **T1 — модель и миграция `audit_logs`** (`6615d3cc`) — `AuditLog` на `Base`: собственный UUID `id` + `created_at`, без `updated_at`/soft-delete (append-only прикладного уровня); колонки и 4 индекса по §5 (`user_id` FK **ON DELETE SET NULL**, `user_role`, `action`, `entity`, `entity_id`, `entity_label` 255, `changes` JSON); миграция `c4e6a8f0b2d1_add_audit_logs_table`; тест схемы up/down + guard отсутствия API/сервисной поверхности изменения строк журнала.
- **T2 — аккумулятор аудита + автор + вставка в `@transactional`** (`2f1a063a`, `c941d289`, `84b8c00b`) — `backend/src/events/audit.py`: `mark_audit(...)` с токеном владения накопителя, actor-contextvar (`user_id`, `role`), которую ставит общее ядро `resolve_authed` (строгий guard и мягкий резолвер покрыты разом); канонический сериализатор значений (дата→ISO, decimal→строка, enum→значение), маскирование `phone`/`phone_digits`/`email`, потолок строковых скаляров `changes` — 500 символов с «…», `entity_label` обрезается до 255; вставка накопленных строк — в `@transactional` после метода до коммита, только обёрткой-владельцем (бес-`self` сценарные обёртки открывают пустой накопитель; каскадные дочерние строки молчат — «одно действие — одна строка»); ошибка метода откатывает действие и журнал вместе; `52a02226` — словарь подписей `ENTITY_SIGNATURES` (заголовок + ключевые поля подписи/снимка на канонический набор #239) + `derive_entity_label` с автоподстановкой в `mark_audit`.
- **T3 — автосбор в общем репозитории** (`78092b1e`, чистка `c941d289`) — `BaseRepository.create/update/patch/delete/reorder` формируют сырые записи `{entity, action, entity_id, before, after}`; правило целевой сущности (запись только при совпадении с target, открытым обёрткой) — каскадные дочерние строки не пишутся; правило старшинства: явная `mark_audit` вытесняет авто-строку (дублей нет); `reorder` — одна строка «N объектов» без снимка; no-op без строки.
- **T4 — явные пометки нестандартных мутаций** (`dc63f212`, пробелы §8 — `2e4c1928`, no-op услуг `bd144647`, minors `526f22fe`) — `ArchiveService`/`StaffService` archive/restore (действие без снимка, сверка `is_active` против no-op, вытеснение авто-update, подпись через `derive_row_label`); сценарии записей `usecases/records.py` (create/update/patch/delete; отложенное удаление — пометка рядом с `mark_changed("records")` до финального DELETE, §4.5); автономные визиты, фото (одиночные и композитные сотрудники), профиль (карточка = staff), настройки пользователя, `resolve_delete` и `ActivityService.delete`; закрытие двух пробелов охвата §8: явные пометки услуг (create/update/patch пишут мимо репозитория — вложенные тарифы/теги/материалы; снимок create через `snapshot_pairs_after`, no-op PUT/PATCH услуг без строки — сравнение до записи) и удаление посетителя (подпись и before-снимок сняты до удаления; каскад Client→visitors остаётся на голом `_delete_cascade` — §9-С6); единый строитель `diff_pairs` для всех 7 мест диффа.
