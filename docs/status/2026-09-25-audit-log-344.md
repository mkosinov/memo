## Goal

Each completed user action on data leaves an atomic append-only row in the journal (who / what /
on what / when / what exactly changed) written in the same transaction. Administrators get a new
«Журнал» section with filters (author / action / entity / period); masters see no interface change
and get 403 on both the page and the API.

## Summary of Changes (per task)

- **T1 — model + migration `audit_logs`:** `backend/src/models/audit_log.py`,
  `backend/migrations/versions/c4e6a8f0b2d1_add_audit_logs_table.py` — author FK

- **T2 — audit accumulator (`backend/src/events/audit.py`, 693 lines):** per-request accumulator on
  a contextvar (`mark_audit`, owner token); actor contextvar set in the shared session-resolve core

  (date/decimal/enum → JSON), phone/email masking, `ENTITY_SIGNATURES` (derive_row_label);

  outermost owner wrapper. #239 event contract untouched.
- **T3 — auto-collection in `BaseRepository` (`create/update/patch/delete/reorder`):**
  target-entity rule of the accumulator (target fixed in `open_audit`), explicit `mark_audit`
  supersedes the auto row, no-op → no row, reorder → single row «N объектов» without a snapshot.
- **T4 — explicit marks for non-standard mutations:** archive/restore (`ArchiveService` generic +
  `StaffService` own paths; `is_active` no-op check, supersede of auto-update); records scenarios

  profile (card = staff); standalone visits; payments; user settings; services
  (create/update/patch overrides bypass the repository — nested tariffs/tags/materials; PATCH no-op
  → no row); visitor deletion (signature + before-snapshot taken before the row is removed;
  Client→visitors cascade stays silent, §9-С6). One `diff_pairs` builder shared by all 7 explicit
  diff sites.
- **T5 — read API:** `GET /api/v1/audit-logs` (+ `/authors`) — pagination / filters / sorting,
  `users → staff` join in one query, `require_admin`, day boundaries via canonical `dates.py`,
  `#263` role allowlist; `403` master, `401` anonymous.
- **T6 — frontend «Журнал» `/audit`:** in `ADMIN_ONLY_SECTIONS` + Menubar entry; `DataTable` per
  canon; filters (author / action / entity / period); RU labels (`auditLabels.ts`), change render
  «поле: было → стало»; `AuditLogContext`, `useAuditLogAuthors`; api-client
  `getAuditLogs` / `getAuditLogAuthors` + zod schemas.
- **T7 — e2e:** `frontend/admin/e2e/audit-log.spec.ts` — spec §9 scenarios С1–С6 (table,
