## Проблема

Воркер Next.js dev-сервера переписывает `process.title` на «next-server (v14.2.35)» — вложенные
скобки/пробелы ломают разбор lsof'ом `/proc/<pid>/stat` (живой эксперимент в issue: листенер есть
в `/proc/net/tcp{,6}`, lsof не показывает НИЧЕГО). Все пять проверок портов контура прогонов
опирались на lsof: невидимый orphan-next держит порт → «свободен» → EADDRINUSE на старте →
красный прогон, не связанный с кодом; masked-уборка сироту не находит. Вторая дыра: смерть
дочернего сервера посреди прогона не замечалась (стек ждал только фронтенд) — десятки минут
красного шума вместо адресного вердикта.

## Что выполнено

1. **Примитив `listen_pairs` + нормализатор (T1 `a91b88aa`, standard)** — резолвер «порт → PID»
   без lsof: один сэмпл на вызов, `/proc/net/tcp` + `/proc/net/tcp6` (отсутствие tcp6 — не
   ошибка), строки состояния `0A` (LISTEN), hex→dec порт, inode → владелец одиночным проходом
   `/proc/[0-9]*/fd/*` по симлинку `socket:[inode]`; stat не парсится вовсе — title не существует
   для резолвера. Fail-closed: LISTEN без атрибутируемого PID = «порт занят» (строка с пустым
   pid — формат сэмпла сохранён, потребители не меняют парсинг). Не-Linux фолбэк: /proc
   нечитаем → предупреждение + прежняя lsof-ветка (macOS статус-кво). Переопределение путей
   /proc переменными — только в dryrun-режиме. Нормализатор `_watch_interval_s`
   (`SHARD_STACK_WATCH_S`/`SHARD_RUN_WATCH_S`, дефолт 5 при мусоре/0/отрицательном/>600).
   Dryrun-кейсы 23–26 на /proc-фикстуре.
2. **Замена пяти lsof-точек (T2 `04e34fc8` + ревью-фикс `062bcdf3`, standard)** —
   `_masked_pids`, `allocate_shard_ports` (один сэмпл, фильтр «порт ∈ кандидаты», подсказка
   ошибки переведена на /proc-таблицы), `_legacy_ports_free` + TOCTOU-recheck и `.next`-вайп-гард
   в `test-all.sh` — все на `listen_pairs`; конъюнкция с pgrep-номинацией и args-гейтами
   сохранена дословно (неатрибутируемый держатель не убивается, но занятость видна).
   Ревью-фикс: bounded retry (≤5) контролей 9a/9b против coupon-collector флэйка 4-портового
   окна (паттерн Case 8/28). Dryrun-кейсы 9/17/27/28 мигрированы со стабов lsof на /proc-фикстуру.
3. **Fail-fast слой стека (T3 `710acb35` + ревью-фикс `25971434`, standard)** — финальный блок
   `e2e-shard-start.sh`: вместо `wait "$FRONTEND_PID"` — цикл ожидания ЛЮБОГО из двух серверов
   (`kill -0`-поллинг, bash 3.2-совместимо); смерть любого — вердикт «stack shard N:
   backend|frontend died on :PORT» + путь лога ВСЕГДА + кап-хвост 20 строк с case-insensitive
   фильтром секретов (`_capped_log_tail`) + exit 1; exit-trap после TERM своих детей добирает
   внуков — держателей портов ЭТОГО стека (`_sweep_masked`, резолвер сделал внуков видимыми).
   Ревью-фикс: die-кейсы (14a–c/15) на `HOLD_S=600` вместо 8 — бессмертны-в-границах, окно
   различения 6 с больше не соскальзывает за естественную смерть держателя под нагрузкой;
   стабы ловят TERM на внутреннем sleep-ребёнке — teardown не сиротит sleep-600 (было 12 сирот
   на 3 прогона, стало 0). Кейсы 14–16.
4. **Fail-fast слой оркестратора (T4 `f4417af1`, standard)** — watchdog-примитив
   `run_watchdog`/`stop_run_watchdog` в `shard-helpers.sh`: тик `SHARD_RUN_WATCH_S`, `kill -0`
   по стек-обёрткам; провал подтверждается `wait "$pid"` (рептинг + статус — зомби отвечает
   `kill -0`, ложных смертей нет) → вердикт «умер»: диагноз шард/порты + кап-хвост стека-лога,
   маркер-файл в `LOG_DIR`, TERM ОБЕИМ Playwright-стадиям с лестницей TERM→грейс→SIGKILL
   (жёсткая форма rev4 — сосед не доезжает); самовыход по EXIT-списку стадий, TERM-флаг не
   сиротит sleep и не рубит идущую реакцию. `test-all.sh`: старт watchdog сразу после стеков
   (до readiness), списки стадий атомарным `mv`, жёсткий порядок «финальный wait → ОСТАНОВ
   watchdog → проверка маркера → вердикт» — живой watchdog при teardown зелёного прогона не
   успевает поставить ложный маркер; маркер → `FAIL=1` (US-6: смерть обёртки после зелёной её
   стадии краснит прогон). Обёртки в ALL_PIDS не вводятся — exit-семантика стадий не менялась.
   Dryrun-кейсы 29–32 на реальных фоновых детях.
5. **Сквозная верификация (T5, small)** — без кода: полный локальный `test-all.sh` зелёный
   (тег `978ca3`), оба dryrun-набора зелёные, grep-чистота (lsof — только не-Linux-фолбэк
   `listen_pairs`).
