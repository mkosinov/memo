   к существующему тесту `isInvalidated → refetched=true`
   (`ScheduleDataContext.test.tsx:1281`): кэш недели старше порога **по возрасту
   данных** (`dataUpdatedAt`) → ensure-fresh в `deleteActivityDeferred`
   срабатывает, `refetched=true`. Механика по плану: `vi.useFakeTimers()` ДО
   заполнения кэша (метка `dataUpdatedAt` на фейковых часах), порог
   приложения `staleTime: 30_000` через `queryClient.setQueryDefaults`,
   состаривание одним сдвигом `vi.setSystemTime(+31_000)` без срабатывания
   таймеров, разбор `vi.useRealTimers()` в `afterEach` — файл после точки
   вставки полон тестов на реальных таймерах. Контраст-ветка (свежий кэш →
   `refetched=false`) не дублируется — уже закрыта тестом `:1302`.
   **Дискриминируемость проверена с откатом**: временное удаление условия
   возраста из `ScheduleDataContext.tsx` краснит новый тест, возврат — зелнит;
   правка продукта не коммитилась. Сьют файла **45/45**.

   единый источник интервала окна отмены: `export const UNDO_WINDOW_MS = 5_000`
   в листовом `frontend/admin/lib/constants.ts`; 13 литералов `delayMs: 5000`

   импорт `../../lib/constants` — по прецедентам импорта app-модулей в e2e).
   **Границы**: литералы `5000` в `__tests__/` не тронуты (независимая
