## Отклонения и фикс-циклы

- **T7 (смоук `--notify` вскрыл 2 интеграционных бага):**
  `c723aeef` — диспетчер создаёт потребительские группы при старте
  (`ensure_consumer_groups` перед `reclaim_hanging`, спека §3.1): на свежем
  Redis XAUTOCLAIM падал NOGROUP и процесс умирал до циклов; `FakeQueue` —
  no-op. `9c78076f` — `|| true` на kill notify-детей в cleanup `dev.sh`:
  под `set -e` kill уже мёртвого диспетчера обрывал очистку до убийства
  воркера и redis, оставляя сирот. Оба одобрены ревью.
- **T8 (одна fix-итерация ревью-раунда 1, `14c57041`):** TS2339 в
  finally-блоке S1-спеки — типы строк БД `any` (домашний паттерн
  activity-details-modal), expect.poll-колбэки невидимы для CFA; локальные
  предпосылки транспорта (числовой порт, `redis-server` на PATH, свободный
  порт) перенесены в преамбулу включённого режима ДО `write_run_lease` —
  устранён класс lease-leak (ни один новый exit не течёт лизой и не трогает
  хранилище).

## Behavioral Delta

По умолчанию (без `NOTIFY_ENABLED`/`REDIS_URL`) поведение прежнее —
инвариант S2. При включённой доставке диспетчер вместо `FakeQueue` работает
с Redis Streams (`RedisQueue`), транспортный сбой постановки не теряет
событие (re-enqueue). `dev.sh --notify` поднимает локальный контур
(эфемерный Redis + диспетчер + воркер-скелет). Воркер ничего не потребляет —
доставка сообщений клиентам остаётся частью 3. UI не менялся (чекбокс флага —
из #482).
