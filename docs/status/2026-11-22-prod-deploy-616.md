## Behavioral Delta

Пользовательского поведения нет — фича инфраструктурная. Конвейер
доставки: фичи копятся в milestone и мержатся в main по зелёному CI как
обычно; владелец закрывает milestone командой `scripts/release.sh` →
публикуется релиз → `release: published` собирает 3 образа с тегом
релиза в GHCR и по SSH выполняет `deploy.sh` на VPS (pull → миграции →
up → health). Откат — повторный деплой предыдущего тега. Все 3 части
приложения (web/admin/api) едут одним тегом; прод-стек слушает только
loopback, секреты — только через `/opt/memo/env/production.env`.
Приложение стало честнее о режиме: неизвестный `ENV` не стартует,
sqladmin выключен по умолчанию, прод-валидаторы `SECRET_KEY`/`OTP_PEPPER`
не пускают слабые секреты в production.

## Rework 2026-11-22/23 (PR #629, спека рев.6)

**Почему:** раунд 1 (всё выше — история раунда, не переписывалась) ушёл
в PR #629, но CI-чек «Prod build smoke» покраснел — union-merge
`env_file` в compose (compose объединяет несколько env_file-источников;
статический оверрайд смоук-прогона смешивался с каноническим файлом).
Одновременно владелец принял три решения: env из секретов через рендер,
единый edge-nginx полного сайта вместо web-образа, единый медиа-том.
Спека переписана до рев.6, план переписан (оба на main, `c9fceb10`).
Rework-раунд — 14 коммитов `6c60c467..73a61ecf` поверх merge
origin/main (`6c60c467`) + docser-коммит мета-док; файлы rework:
`deploy/*`, `.github/workflows/{deploy,test}.yml`,
`scripts/prod-smoke.sh`, `.dockerignore` (16 файлов, +1701/−431).

**Что изменилось (три решения):**

1. **`deploy/render-env.sh`** — env рендерится из GitHub Secrets и
   job-переменных в канонический `/opt/memo/env/production.env`: вход
   по stdin, атомарная запись, права 0600, значения не печатаются;
   CRLF-толерантность, отказ на пустом рендере. Потребители —
   `deploy.yml`, CI-смоук (`test.yml`) и `prod-smoke.sh`.
   Красный-чек-фикс: `test.yml` рендерит литералы-пустышки в
   канонический путь (sudo + 0644 — runner не root);
   env_file-оверрайд compose больше не трогается вовсе.
2. **Edge-топология** — `Dockerfile.edge` + `nginx.conf` упраздняют
   web-образ: единственный nginx полного сайта; :80 — редирект на
   HTTPS + ACME-challenge + exact-match health-маршрут, :443 — TLS с
   хостовыми сертификатами; `/` → статика SPA, `/images/public/` →
   публичное поддерево медиа-тома, `/admin` → admin, `/api` → backend
   — без переписывания путей; HSTS; drift-гард конфигов в
   `verify-edge.sh`; для смоука — `deploy/nginx.smoke.conf`
   (TLS-off). compose публикует только edge (80/443); закреплённая
   подсеть со статическим IP edge `172.16.0.10` =
   `FORWARDED_ALLOW_IPS` (синхронно с ARG в `Dockerfile.backend`);
   loopback-порты сняты; health деплоя — через edge с хоста.
3. **Единый медиа-том** — `/opt/memo/media`: edge монтирует только
   `public/` read-only и отдаёт по `/images/`; backend монтирует
   корень read-write (`FILES_DIR`, загрузки в `avatars/`); граница
   публичности — уровнем монтирования. Прежняя схема раздельных
   томов упразднена.

**Качество по ревью:** charset-валидация тега/префикса реестра,
`REGISTRY_TOKEN` по stdin (не в argv), preflight
certs/acme/media-public, бэкап env рядом с целью + abort на
stale-бэкапе, TELEGRAM-секреты по контракту Settings.
