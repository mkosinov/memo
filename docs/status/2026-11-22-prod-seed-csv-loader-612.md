## Что выполнено

1. **CSV-парсер (T1, `9b57e86c` + `4854355e` + `8c2589c4`, large —
   3 staged подзадачи, комплаенс+качество ✅)** — чтение
   `utf-8-sig` (BOM±) + `csv.reader(..., strict=True, newline='')` с
   отслеживанием номера строки **начала записи** (многострочное поле
   в кавычках: ошибка указывает на старт записи, не на конец по
   `reader.line_num`); конечный автомат секций: маркер-строка (имя в
   1-й колонке, непустой хвост → ошибка) → шапка (1-я колонка пуста)
   → строки данных; повтор уже встречавшейся секции → ошибка,
   неизвестная секция → ошибка, порядок секций свободный. Шапка
   проверяется поимённо: отсутствие обязательной колонки → ошибка,
   лишняя колонка → предупреждение «секция + колонка» (перечень в
   конце прогона), дубль имени колонки → ошибка; строка данных
   короче/длиннее шапки → ошибка. Типизация у источника (§4.4):
   int-колонки, «пустая → null» — только для `int | None` полей
   (`max_age`, `sort_order`); для `capacity`/`min_age`/`duration`/
   `price` пустая → ошибка (не 0 и не null); bool `True`/`False`
   без учёта регистра, пустая → ошибка (исключение —
   `master_is_active` вне собранного блока); `audience` ∈
   {kid, adult, all}; парсер передаёт в модели настоящие int/bool —
   lax-режим pydantic не задействован. Групповые правила master_*
   (§4.3): блок собирается при любой непустой `master_*`, частичное
   заполнение → явная ошибка с номером строки. Мультизначения —
   списки через `;` с trim; `service_materials`/`tariffs`
   вкладываются в услуги по `service_title`; секция `specialty` —
   плоский список значений во 2-й колонке без шапки; секция `tags`
   опциональна (нет секции → теги всех сущностей `[]`). Все ошибки
   входа — `SeedDataError` с номером строки, операторский текст на
   русском. Контракт пост-599/606 (`4854355e`): specialty-секция и
   ссылки парсятся по §4.8, `is_public` — в контракте входа.
   Тесты спеки §6 № 1–3 (`8c2589c4`).
2. **Кросс-валидация + направления (T2, `f2f45dd7`, standard,
   ✅✅)** — `load_reference_data` принимает собранный
   `ReferenceData` от парсера (чтение каталога YAML удалено);
   вся существующая кросс-валидация сохранена: natural keys
   (title / first_name+last_name), дубликаты, `max_age < min_age`,
   `#RRGGBB`, ссылки service_materials→materials и tariffs→services,
   теги — + **одна новая кросс-проверка**: `staff.positions` →
   секция `positions` на этапе валидации (текст ошибки — зеркало
   существующей из слоя записи), `--check` теперь ловит
   необъявленную должность. Направления по контракту #599 §6:
   секция `specialty` → список названий для `_apply_specialties`;
   `services.specialty` и `master_specialty` — названия-ссылки с
   резолвом без учёта регистра, неизвестное название → ошибка с
   именем значения; D5: живой master-блок без направлений → ошибка.
   Тексты ошибок: ссылки на «файл YAML» заменены на «строка N CSV».
3. **CLI `--csv` и режимы (T3, `5bd768b8`, small, комплаенс ✅)** —
   `--csv <файл>` — обязательный аргумент (`--dir` удалён);
   `--check`/`--dry-run` — как были, взаимоисключающие (совместное
   использование → ошибка argparse, exit 2); коды выхода 0 успех /
   1 ошибка данных или файла / 2 ошибка вызова; несуществующий
   путь/каталог и файл без единой секции → внятная ошибка, exit 1;
   предупреждения (лишние колонки) печатаются во всех режимах;
   `--dry-run` — прежняя семантика слоя записи: прогон в
   откатываемой транзакции + печать сводки. Тесты спеки §6
   № 4/5/9.
4. **Перенос тестов слоя на CSV-фикстуры (T4, `cd749d8e`, standard,
   ✅✅ качество — approved with 3 minor → follow-ups)** — сюита
   независимых тестов существующего слоя переехала с YAML-фикстур
   на CSV: дубликаты natural keys, `max_age < min_age`, цвет,
   точная синхронизация наборов связей, одна транзакция + rollback,
   идемпотентность перезаливки, встроенные должности по фиксированным
   id — ассерты поведения без изменений, ассерты текстов сообщений
   обновлены под CSV. Тег-семантика §4.7: пустые тег-колонки →
   связи перечисленных сущностей очищены, сущности-теги не удалены;
   заполненные → связи созданы. `is_public` обеих полярностей через
   локальные CSV-фикстуры; контроль `load_reference_data(DEFAULT_DIR)`
   (3 локации) упразднён — роль перенесена в fixture-тест шаблона
   (T5). Тесты спеки §6 № 10/11/12.
5. **CSV-шаблон, README, зачистка YAML (T5, `473cec23`, standard,
   ✅✅)** — `backend/seed-data/prod-seed-template.csv`: полная
   геометрия §4.2 (обе полярности `is_public`, 2 example-тега,
   2 направления не по алфавиту; значения выдуманные — реальный
   прод в репо не попадает), `--check` на шаблоне зелёный без БД
   (fixture-тест §6 № 8 — единственный носитель контракта «шаблон
   всегда валиден»); README переписан: поток `--csv` → `--check` →
   `--dry-run` → заливка, коды выхода, механика файла (BOM±, `;`,
   кавычки RFC 4180, LF/CRLF, номера строк), таблицы полей по
   секциям с обязательностью и типами (инструкции из комментариев
   удалённых YAML-шаблонов перенесены), групповые правила master_*,
   тег-семантика §4.7, «данные предзагрузки в репо не коммитятся»,
   создание первого админа (`create-user`); удалены 6 YAML-шаблонов
   (`locations`/`materials`/`services`/`specialties`[#599]/`staff`/
   `tags`); `pyproject.toml`: сняты `pyyaml` и `types-PyYAML`
   (единственный потребитель — удалённый YAML-вход; остаточный
   pyyaml в `uv.lock` — transitive `uvicorn[standard]`, легитимно);
   `.gitignore`: `backend/seed-data/*.csv` с исключением
